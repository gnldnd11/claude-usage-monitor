# 탄광 띠 4차 규격: 암반에 박힌 광맥

> 2026-11-25. 사용자 반려 두 줄 중 **첫 줄 전부와 둘째 줄의 그리는 쪽**에 대한 설계다.
> `spec.md`(띠의 그림) · `spec-dig.md`(휘두름·파편·빛·자루) · `spec-idle.md`(카메라·쉬는 중)은
> 그대로 서고, 이 문서가 **띠 안에 서 있는 광맥 세 개의 그림**과 **타격이 암반에 남기는 자국**을 다시 정한다.
> 충돌하는 자리는 본문에 「N절을 뒤집는다」로 적었다.
>
> 목업: `ore-1x.png` · `ore-3x.png`(같은 디렉터리, 같은 페이지의 1배와 3배).
> **판정은 1x 로 했고 3x 는 확대용이다.** 재지 않은 것은 「안 쟀다」고 적었다.

---

## 0. 반려 두 줄과 이 규격의 범위

사용자 말 그대로.

> "돌이 파인다는 느낌이 너무안나와 그리고 젬들도 저 광석에 박혀있다는느낌을 주는게 너무 안나오고"

| 반려 | 이 문서가 맡는 것 |
|---|---|
| 1 보석이 암반에 박혀 보이지 않는다 | **전부** (1~6절) |
| 2 돌이 깨지는 느낌이 안 난다 | **그려지는 쪽만** (7절). 속도 쪽(미터당 토큰)은 엔진 담당이 따로 고친다 |

**값·속도·ms 체계를 새로 설계하지 않았다.** 이 문서에 새 ms 가 0 개이고, 7절은 이미 있는
`MN_DIG[step]` 한 변수와 이미 있는 `burst` 클래스를 그대로 탄다.

## 1. 지금 왜 스티커로 보이나 (재서 쓴 것)

### 1-1. 벽의 밝기 폭이 14배다. 그래서 암반 색으로 그린 것은 전부 불안정하다

마커가 서 있는 바탕은 **`.mn-rock`**(아직 안 판 암반)이다. 굴(`.mn-cut`)이 아니다.
`mine-rock.png` 두 단을 띠의 배치 그대로 깔고 `.30` slab 스크림을 얹어 38,640 화소를 쟀다.

| 바탕 | RGB | 휘도 |
|---|---|---|
| 벽 p10 (어두운 면) | `rgb(33,32,33)` | 0.0147 |
| 벽 p50 (중앙값) | `rgb(68,65,73)` | 0.0549 |
| 벽 p90 (밝은 면) | `rgb(113,109,119)` | 0.1578 |
| 벽 **p97 (가장 밝은 바위)** | `rgb(126,124,133)` | **0.2054** |

**p10 과 p97 이 14배다.** 그러니 팔레트의 어떤 색도 벽 위에서 한 값을 갖지 않는다.

| 토큰 | vs p10 | vs p50 | vs p90 | vs p97 |
|---|---|---|---|---|
| `slab` #2a2f36 | 1.20 | 1.35 | 2.67 | 3.28 |
| `stone` #7e828c | 4.22 | 2.60 | 1.31 | **1.07** |
| `steel` #bbbdc7 | 8.67 | 5.35 | 2.70 | **2.20** |
| `gold` #e8b23a | 8.40 | 5.18 | 2.61 | **2.13** |
| `cream` #fcecdc | 14.05 | 8.66 | 4.37 | 3.56 |
| `ink` #0b1310 | **1.16** | 1.88 | 3.73 | 4.58 |
| `red` #d4453a | 3.64 | 2.25 | 1.13 | **1.08** |

**지금 잠긴 광맥의 암반 턱(`LOCK`)이 `slab` 인 것이 여기 걸린다.** 1.20 에서 3.28 사이를 왕복하므로
어두운 바위 위에서는 사라지고 밝은 바위 위에서는 **검은 네모**가 된다. 렌더로 둘 다 확인했다.

### 1-2. 스티커로 읽히는 조건을 지금 마커가 전부 갖고 있다

| | 지금 |
|---|---|
| 실루엣 | **닫힌 볼록 도형** + 둘레 전체에 같은 굵기의 ink 키라인 |
| 앞을 가리는 것 | **없다**(잠긴 것만 있다) |
| 받는 그림자 | 없다 |
| 서 있는 자리 | 띠 높이의 정확히 한가운데(`top:50%`), 구조와 무관 |

**그리고 앞을 가리는 것이 잠긴 것에만 있어서, 열린 광맥일수록 더 떠 보인다.**
읽는 사람이 보고 싶어 하는 쪽이 제일 스티커인 상태다.

## 2. 채택안: 광맥은 「암반 주머니에 박힌 것」이다

```
암반에 주머니가 하나 파여 있고, 그 안에 캘 것이 들어 있고,
그것의 아랫부분은 돌 속으로 들어가 안 보인다.
```

그림 조각은 **넷**이고, 세 광맥이 같은 넷을 쓴다. 전부 24단위 한 장 안에 있고
**덧씌우는 층도, 마스크도, 새 요소도 없다.**

| 조각 | 무엇 | 왜 |
|---|---|---|
| **POCKET** | 각진 ink 주머니, 불투명도 .92 | 벽에 파인 구멍. **바탕색에 안 휘둘린다**(3-1) |
| **RIM** | 주머니 안쪽 아랫변을 따라가는 `stone` 한 줄 | 「그림자」가 아니라 「구멍」으로 읽게 하는 것 |
| **몸** | 지금 그림의 실루엣 그대로 | 보석은 보석, 유물은 금괴, 피버는 번개. 정체는 안 바꾼다 |
| **깨진 밑변** | 몸의 아래쪽을 **들쭉날쭉한 선으로 자른다** | 실루엣이 끊긴다. **이것이 스티커를 죽이는 한 가지다** |

**새 색 0개.** 전부 `games/tiles.js` 토큰(`ink` `stone` `steel` `cream` `gold` `emberLo` `red`)이거나
그 토큰의 알파다. **금색 테두리 0개.** 글자 0개.

### 2-1. 왜 앞을 가리는 것이 암반색이 아니라 ink 인가

1절의 표가 답이다. **벽 앞에 놓인 것은 벽과 같은 재질이므로 톤으로는 절대 안 갈린다.**
그런데 갱도에서 **앞에 있는 것은 그늘 속에 있다.** 그늘은 ink 이고, ink 는 광맥의 `steel`·`gold` 에
대해 **어느 바위 위에서나 9:1 이상**이다(8절). 그래서 대비가 **그림 안에서 닫힌다.**

이것은 이 저장소가 이미 세 번 쓴 처방이다(`ore.js` 의 유물 소켓, 피버 밑받침, `spec-dig.md` 파편의 ink 테).
**네 번째로 같은 처방을 쓴다.**

## 3. 그림 조각 넷의 정확한 값

24단위 viewBox. **보석·피버는 24px, 유물은 48px 에 그려지므로 유물에서는 한 단위가 2px 이다.**
상자 크기는 **안 바뀐다**(`docs/game-panels.md` 8-3 의 24 / 48 그대로).

### 3-1. POCKET (열린 것·잠긴 것·세 종류 전부 공통)

```
<path d='M11.4 1.6 18.6 4.0 21.6 8.8 20.4 12.2 23.2 16.0 19.6 21.0 12.0 23.0 5.0 20.4 2.0 14.6 2.6 7.6Z'
      fill='#0b1310' opacity='.92'/>
```

**열 꼭짓점, 좌우 비대칭, 어느 변도 상자 변과 평행하지 않다.** 셋 다 일부러다.

- **상자 변에 닿지 않는다.** 렌더 다섯 번으로 확인한 것: `x0..24` 또는 `y24` 까지 채우는 덩어리는
  **무슨 색이든 네모로 읽힌다.** 지금 `LOCK` 이 그래서 네모다.
- **등간격·대칭이 아니다.** 양끝이 뾰족한 대칭 렌즈는 **눈이나 입**으로 읽혔다(반려, 9절).
- **불투명도 .92 인 근거는 피버다.** `red` 대 ink 의 상한이 4.22:1 이고, .92 면 3.92~4.19 로 그 상한에
  붙는다. .86 이면 3.63 까지 내려간다.

### 3-2. RIM (주머니 안쪽 바닥의 되비침)

```
<path d='M2.4 15.6 5.4 19.8 12.0 21.6 18.8 20.0 22.6 16.6'
      fill='none' stroke='#7e828c' stroke-width='1.2' stroke-opacity='.55' stroke-linejoin='round'/>
```

주머니에 대해 **2.27~2.32:1**(8절). **일부러 약하다.** 되비침이지 테두리가 아니다.
**이 줄에 걸리는 정보는 없다.** 안 보여도 규격이 무너지지 않는다. 있는 쪽이 「그림자」가 아니라
「구멍」으로 읽혀서 둔다.

### 3-3. 깨진 밑변

몸의 아랫부분을 **꼭짓점 네댓 개짜리 들쭉날쭉한 선**으로 자른다. 자른 아래는 주머니의 ink 다.
**잘린 선이 실루엣을 끊는 유일한 수단이고, 이 규격에서 제일 중요한 한 줄이다.**

## 4. 세 광맥의 path (그대로 박는다)

**열린 것과 잠긴 것은 한 함수에 불린 하나다.** 같은 그림을 두 벌 적어 두지 않는다
(`ore.js` 머리말의 「600바이트짜리 문자열을 두 벌 유지하지 않는다」 그대로).

### 4-1. 보석 (`gem`, 24px)

```
공통 테두리   stroke='#0b1310' stroke-width='1.4' stroke-linejoin='round'

몸 열린 것    M12 2.4 21.2 10.0 18.6 14.6 15.2 16.4 12.0 14.8 8.6 16.6 5.4 14.0 2.8 10.0Z
몸 잠긴 것    M12 2.4 21.2 10.0 18.0 11.6 14.8 13.2 11.6 11.4 8.2 13.0 5.2 11.2 2.8 10.0Z
몸 맨 것      M12 2.4 21.2 10.0 12 21.6 2.8 10.0Z
   fill='#bbbdc7'

빛 받는 면    M12 3.8 4.8 10.0 12 <T>Z     fill = 열린 것 '#fcecdc' / 잠긴 것 '#7e828c'
그늘진 면     M12 3.8 19.2 10.0 12 <T>Z    fill='#0b1310' opacity='.3'
   T = 열린 것·맨 것 11.9 · 잠긴 것 10.8
```

**그늘진 면이 새로 생긴다.** 지금 보석은 면이 하나(cream)뿐이라 **납작한 마름모**다.
오른쪽에 ink `.3` 면을 하나 두면 같은 꼭짓점으로 **두 면을 가진 결정**이 된다. 새 색 0개.

### 4-2. 유물 (`relic`, 48px)

```
공통 테두리   stroke='#0b1310' stroke-width='1.2' stroke-linejoin='round'

몸 열린 것·맨 것  M4.9 13.9 7.9 9.3l10.3 1.5 1.1 4.2-3.3 4-9.9-1.3Z      (지금 것 그대로)
몸 잠긴 것        M4.9 13.9 7.9 9.3l10.3 1.5 1.1 4.2-3.5 1.6-3.9-1.6-3.3 1.4Z
   fill='#e8b23a'

윗면          M7.9 9.3 12.6 10 10.4 12.5 6.4 12Z   fill = 열린 것 '#fcecdc' / 잠긴 것 '#7e828c'
앞면          M5 14 14.9 15.3 16 19.5 6.1 18.1Z    fill='#c25a34' opacity='.6'   (열린 것·맨 것만)
깨진 모       M15.9 15.4 19.3 15 16 19Z            fill='#c25a34' + ink 1 stroke (열린 것·맨 것만)
```

**지금 유물이 들고 있던 ink 소켓 path 는 지운다.** POCKET 이 그 일을 하고, POCKET 쪽이 더 크고
더 불규칙해서 소켓이 하던 「그림자」 읽힘이 없어진다. 대비는 9.74 → **9.05~9.65** 로 사실상 같다(8절).

### 4-3. 피버 (`fever`, 24px)

```
공통 테두리   stroke='#0b1310' stroke-width='1.5' stroke-linejoin='round'

몸 열린 것·맨 것  M13.6 2 6 13.2h4.4L9 20.6l8.6-10h-4.8Z
몸 잠긴 것        M13.6 2 6 13.2h4.4l-.8 3.8 5.4-6.4h-3.4Z
   fill='#d4453a'

심 열린 것·맨 것  M12.6 5.4 8.6 11.6h2.6l-.7 3.8 3.5-4.2h-2.2Z   fill='#fcecdc'
심 잠긴 것        M12.6 5.4 8.6 11.6h2.6l-.4 1.8 3.0-3.4h-2.2Z   fill='#7e828c'
```

**지금 피버가 들고 있던 4단위 ink 밑받침(두 번 그린 같은 path)은 지운다.** POCKET 이 대신한다.
꼬리를 y22 에서 **y20.6** 으로 줄인 것은 주머니 안에 들어오게 하기 위함이다.

## 5. 잠긴 것과 열린 것 (신호를 바꾼다)

**지금 신호는 「암반이 덮였다」 하나다. 이제 열린 것에도 암반이 앞에 있으므로 그 신호는 못 쓴다.**
새 신호는 셋이고, 그 중 하나는 **이분법**이다.

| | 열린 것 | 잠긴 것 |
|---|---|---|
| **1 빛 받는 면** | `cream` | **`stone`** |
| 2 돌 밖에 나와 있는 양 | 몸의 약 75% | 약 45% |
| 3 몸의 형태 | 제 모양 | 아랫부분이 잘려 납작해짐 |

### 5-1. 1번이 주신호인 근거는 측정이다

```
cream 대 stone                     3.33 : 1     신호 자체의 대비
cream 대 몸(steel)                 1.62 : 1     면이 몸보다 밝다
stone 대 몸(steel)                 2.05 : 1     면이 몸보다 어둡다
```

**열린 것은 몸보다 밝은 면이 있고, 잠긴 것은 몸보다 어두운 면이 있다.** 밝기 부호가 뒤집힌다.
24px 에서 그 면은 7x8px 이고, 같은 자리의 밝은 모서리와 어두운 모서리는 갈린다(목업 `ore-1x.png` 3·4째 줄).

**그리고 이 신호는 바탕을 안 탄다.** 면은 주머니 안의 몸 위에 그려지므로 벽이 무엇이든 같다.

### 5-2. 뜻

**「아직 빛이 안 닿았다」**. 곡괭이 단계가 그 광맥을 여는 열쇠가 아니면 암반이 안 열렸고,
안 열렸으면 빛이 안 든다. 지금 그림이 하던 말(「암반이 아직 덮여 있다」)과 같은 말이고
**그림만 바뀐다.**

### 5-3. 무엇이 잠겼는지는 그대로 읽힌다

`ore.js` 머리말의 선(「무엇을 놓치고 있는지 보여야 다음 단계를 살 이유가 생긴다」)을 지킨다.
잠긴 것도 **몸의 색(steel / gold / red)과 윗부분의 모양**이 그대로 보인다.
목업 2째 줄(지금)과 4째 줄(새것)을 나란히 보면 **새것 쪽이 무엇인지 더 잘 읽힌다**:
지금은 회색 네모가 몸의 55%를 덮고 있고, 새것은 덮는 것이 없다.

### 5-4. 피버만 신호가 둘이다 (알고 두는 하자)

`stone` 대 `red` 가 **1.16:1** 이다. 즉 **잠긴 피버의 심은 사실상 안 보인다.**
신호가 「밝은 심이 없어진다」이므로 설계대로 동작하지만, 피버에는 1번이 「면이 어두워진다」가
아니라 「면이 사라진다」로 들어간다. 2·3번은 그대로다.

## 6. 맨 그림과 규칙 표

**띠에 서 있는 광맥**과 **캐낸 뒤의 광맥**은 다른 그림이다. 캐낸 것에는 암반이 안 붙는다.

| 쓰는 곳 | 그림 |
|---|---|
| 띠의 광맥 (`.mn-ore`) | 주머니 + 몸 |
| 띠의 잠긴 광맥 (`.mn-ore.locked`) | 주머니 + 잠긴 몸 |
| **수확 연출 (`.mn-ore.pop`)** | **맨 몸.** 벽에서 나오는 것은 돌이지 구멍이 아니다 |
| **자루 (`.mn-stack i`, 18px)** | **맨 몸.** 자루에 든 것은 씻긴 돌이다 |

```css
.mn-ore.gem{width:24px;height:24px;background-image:url("<GEM_SEAM>");}
.mn-ore.relic{width:48px;height:48px;background-image:url("<RELIC_SEAM>");}
.mn-ore.fever{width:24px;height:24px;background-image:url("<FEVER_SEAM>");}
.mn-ore.gem.locked{background-image:url("<GEM_SEAM_LOCKED>");}
.mn-ore.relic.locked{background-image:url("<RELIC_SEAM_LOCKED>");}
.mn-ore.fever.locked{background-image:url("<FEVER_SEAM_LOCKED>");}
.mn-ore.pop.gem{background-image:url("<GEM_BARE>");}
.mn-ore.pop.relic{background-image:url("<RELIC_BARE>");}
.mn-ore.pop.fever{background-image:url("<FEVER_BARE>");}
.mn-stack i.gem{background-image:url("<GEM_BARE>");}
.mn-stack i.relic{background-image:url("<RELIC_BARE>");}
```

- **`LOCK` 은 삭제한다.** 그 네 줄(`.mn-ore.<kind>.locked` 의 두 층 배경)도 같이 지운다.
- `.mn-ore.pop.<kind>`(0,3,0)이 `.mn-ore.<kind>`(0,2,0)를 이긴다. **`panel.js` 는 안 고친다**
  (`panel.js:697` 이 이미 `'mn-ore face pop ' + kind` 를 쓰고 `locked` 를 안 붙인다).
- 배경 쌓기가 한 장으로 줄어서 **`background-image` 에 쉼표가 없어진다.**
- 그림이 4장에서 9장으로 늘지만 URI 한 장이 **931바이트**라 스타일시트가 **약 2KB** 는다.
  새 파일 0개, 새 의존성 0개.

## 7. 돌이 깨지는 순간, 암반에 무엇이 보이나 (반려 2의 그리는 쪽)

### 7-1. 지금 깨질 때 **벽에서** 일어나는 일이 0 개다

| 깨질 때 움직이는 것 | 어디 |
|---|---|
| 게 한 걸음 | `.mn-dig.step` |
| 파편 다섯 | `.mn-chips` |
| 스프라이트의 흰 호·금 불똥 | `mine-dig.png` 안 |
| 막장 전진 | 돌 하나 = 0.95px(250) ~ 1.56px(351) |

**셋은 공중에서 일어나고 넷째는 한 번에 1px 이다.** 벽 자체는 한 화소도 안 바뀐다.
사용자가 본 것이 그것이다.

### 7-2. 채택: 자국 하나 (`BITE`)

**타격점에 암반 한 조각이 떨어져 나간 자국을 남긴다. 그것 하나다.**

```
12 x 10 viewBox

본체   M0.4 2.2 3.6 0.8 7.0 2.1 10.0 1.1 11.6 3.1 8.8 4.7 10.2 7.4 6.4 9.0 2.4 7.2 0.6 4.7Z
       fill='#0b1310' opacity='.92'
윗변   M0.4 2.2 3.6 0.8 7.0 2.1 10.0 1.1 11.6 3.1
       fill='none' stroke='#bbbdc7' stroke-width='.9' stroke-opacity='.8' stroke-linejoin='round'
```

```css
/* .mn-rock 의 ::before 는 스크림이 쓰고 있다. ::after 는 비어 있다 */
.mn-rock::after{content:'';position:absolute;left:calc(40% + var(--mn-adv,0%) - 3px);top:39px;
  width:12px;height:10px;background-image:url("<BITE>");background-size:contain;
  background-repeat:no-repeat;background-position:50% 50%;opacity:0;pointer-events:none;}
.mn-rock.burst::after{animation:mnBite var(--mn-digms,1760ms) step-end 1 both;}
@keyframes mnBite{0%{opacity:0}43.75%{opacity:1}75%{opacity:.55}93.75%{opacity:0}}
```

reduced motion 블록에 `.mn-rock.burst::after` 를 더한다(지금 네 선택자 옆에).

### 7-3. 이 자국이 지운 「타격 별」과 다른 점 셋

`spec-dig.md` 2-3 이 타격 별을 지운 이유가 그대로 여기 적용되므로 셋을 다르게 만들었다.

| | 지운 별 | 이 자국 |
|---|---|---|
| 밝기 | **밝다**(등급색 + cream 속심) | **어둡다**. 구멍이지 빛이 아니다 |
| 자리 | 타격점에서 **대각 15px** 떨어진 암반 한가운데 | **막장 변에 물려 있다**(왼쪽 3px 이 막장 clip 에 잘린다) |
| 쌓임 | 제자리에서 떴다 사라짐 | 막장이 전진한 자리에 남았다가 **단계적으로 흐려진다** |

### 7-4. 왜 `.mn-chips` 가 아니라 `.mn-rock::after` 인가

`.mn-chips` 는 `z-index:4` 로 **게와 곡괭이 위**에 그린다. 자국을 거기 두면 7프레임에
**곡괭이 머리를 덮는다**(머리 끝이 막장 +5.7px / y44.5, 자국이 막장 -3..+9 / y39..49).
`.mn-rock::after` 는 게보다 **아래**라 7~8프레임에는 곡괭이에 가려 있다가 **9프레임부터 연장이
빠지면서 드러난다.** 「치고, 빼면, 파인 자리가 보인다」가 그 순서다.

`.mn-rock` 의 `clip-path` 가 자국의 왼쪽 3px 을 막장선에서 자른다. 그래서 **막장 가장자리가
물어뜯긴 모양**이 되고, 떠 있는 조각이 아니다.

### 7-5. 세 바탕에서 재 봤다

자국이 설 수 있는 바탕은 **암반뿐**이다(게와 곡괭이보다 아래이고, 막장 왼쪽은 clip 에 잘린다).
그래도 셋을 다 쟀다.

| | ink 본체 | `steel` 윗변 |
|---|---|---|
| 가장 밝은 바위 (p97) | **4.58** | 2.20 |
| 벽 중앙값 (p50) | 1.88 | **5.35** |
| 가장 어두운 바위 (p10) | 1.16 | **8.67** |
| 게 몸 p50 (만약 위로 올라오면) | **7.65** | 1.32 |

**어느 바탕에서도 둘 중 하나가 4.5 를 넘는다.** 이것이 `spec-dig.md` 2-1 의 파편이 쓴
「`steel` 코어 + `ink` 테」를 **뒤집어 쓴 것**이다(여기서는 ink 가 몸이고 steel 이 테다).
자국은 구멍이고 파편은 돌이라 부호가 반대여야 한다.

### 7-6. 막장 폴리곤은 안 흔든다 (다시 확인)

`spec-dig.md` 2-4 가 반려한 그대로이고, 1.42.0 이후 **이유가 하나 늘었다**:
막장 `clip-path` 는 지금 **꼭짓점 16개가 `--mn-adv` 를 타고 보간되는 것**이 되돌이 300ms 를
지탱하는 수단이다(`meta.js`). 타격마다 꼭짓점을 더하거나 빼면 **그 보간이 깨진다.**

### 7-7. 패널 쪽이 해야 하는 것 (세 줄)

```js
// mnBurst 안, 파편에 burst 를 붙이는 그 자리
rock.classList.add('burst');
// mnCalm 안, 떼는 그 자리
rock.classList.remove('burst');
// 게·곡괭이·파편에 animationDuration 을 넣는 그 자리
band.style.setProperty('--mn-digms', ms + 'ms');
```

**새 요소 0개, 새 ms 0개.** `MN_DIG[step]` 하나가 이제 다섯 가지(게·곡괭이·걸음·파편·자국)를 탄다.

## 8. 대비 (계산. 1절의 벽 분포 위에서 합성했다)

### 8-1. 광맥이 자기 주머니에 대해

주머니는 ink `.92` 이므로 벽에 따라 `rgb(13,20,17)` ~ `rgb(20,27,25)` 사이를 움직인다.

| | 가장 좋을 때 | **가장 나쁠 때** |
|---|---|---|
| `steel` (보석 몸) | 9.97 | **9.34** |
| `cream` (열린 것의 면) | 16.15 | **15.14** |
| `gold` (유물 몸) | 9.65 | **9.05** |
| `stone` (잠긴 것의 면) | 4.85 | **4.55** |
| `red` (피버 몸) | 4.19 | **3.92** |

**`red` 의 3.92 가 이 그림의 바닥이다.** `red` 대 순수 ink 의 상한이 4.22:1 이고
`spec.md` 14절이 이미 그 값을 받아들였다. **더 올리려면 새 색이 필요하다.**

### 8-2. 주머니가 벽에 대해

| 벽 | 주머니 대 벽 |
|---|---|
| p10 (어두운 면) | 1.15 |
| p50 | 1.82 |
| p90 | 3.50 |
| **p97 (가장 밝은 바위)** | **4.26** |

**어두운 바위 위에서 주머니가 사라지는 것은 맞는 그림이다.** 어두운 돌에 파인 구멍은 안 보인다.
구멍이 보여야 하는 곳은 밝은 바위이고 거기서 4.26 이다.

### 8-3. RIM

주머니에 대해 **2.27 ~ 2.32**. 3-2 에 적은 대로 일부러 약하고, 여기 걸리는 정보는 없다.

### 8-4. 두 번째 바탕 (게 몸) 에 대하여

**마커는 게 몸 위에 그려지지 않는다.** `panel.js:304` 의 그리는 순서가 `.mn-cut` → `.mn-rock`
(그 안에 `.mn-slide` 와 마커) → `.mn-adv`(게·곡괭이·파편)이므로 **게가 마커 위에 칠한다.**
수확 직전 마커의 왼쪽 절반이 게 뒤로 들어가고, 그것이 맞다.

그래도 재 뒀다. 게 몸(프레임 0, 6,634화소) 기준.

| | vs 게 몸 p10 | vs p50 | vs p90 | vs p97 |
|---|---|---|---|---|
| `ink` | 3.06 | **7.65** | 7.98 | 9.61 |
| `steel` | 3.29 | **1.32** | 1.26 | 1.05 |
| `gold` | 3.18 | **1.27** | 1.22 | 1.01 |

## 10. 못 한 것 · 확신 없는 것

**못 한 것**

- **띠 전체에 올려놓고 못 봤다.** 벽과 마커만 렌더했다. 게·곡괭이·목재 틀·침목·막장이 같이 있는
  화면에서 주머니가 어떻게 보이는지는 **안 봤다.** 특히 **수확 직전(마커 왼쪽 절반이 게 뒤로 들어간
  상태)**은 안 봤다.
- **`BITE` 를 실제 스윙 안에서 안 봤다.** 네 바탕 위의 조각으로만 봤다. 7-4 의 가림 순서는
  좌표 계산이고 렌더가 아니다.
- **라이트 테마에서 안 봤다.** 띠는 전부 고정색이라 안 바뀌어야 하지만 확인 안 했다.
- **실제 VS Code 사이드바에서 안 봤다.** Chrome 으로 띠의 CSS 를 그대로 재현해 1x·2x·3x 로 봤다.
- `mine.js` · `games/mine/panel.js` 는 **읽기만 했다**(다른 에이전트 작업 중).

**확신 없는 것**

1. **잠긴 보석이 24px 에서 「보석」으로 읽히는지.** 열린 것과 **나란히 두면** 갈린다(목업 3·4째 줄).
   **잠긴 것만 처음 보는 눈**에게 「돌 안에 뭔가 회색 것」이 아니라 「보석」으로 읽히는지는 다른
   질문이고 안 봤다. 안 읽힌다는 말이 나오면 돌릴 손잡이는 **잠긴 몸의 자르는 높이** 하나다
   (지금 y11.2~13.2, 열린 것은 y14.0~16.6).
2. **주머니가 24px 에서 무겁다.** 48px 유물에서는 분명히 구멍으로 읽히는데, 24px 보석에서는
   「검은 테가 둘린 작은 돌」에 가깝다. 불투명도를 내리면 피버가 3.92 아래로 떨어지므로
   (8-1) 내릴 수 없고, 돌릴 수 있는 것은 **주머니 path 를 몸에 더 바싹 붙이는 것**이다.
   그러면 구멍 느낌이 줄어든다. **둘 중 하나를 골라야 하는 자리이고 지금은 구멍 쪽에 줬다.**
3. **자국이 1,760ms 에 한 번 뜨는 것이 「계속 깜박인다」로 읽힐 수 있다.** 지금은 돌이 실제로
   깨질 때만 뜨므로(`burst`) 평소 휘두름에는 안 뜬다. 그래도 바쁜 구간에서는 네 번 연속 뜬다
   (`spec-dig.md` 2-7 의 n=1~4). 그 구간을 안 봤다.
4. **피버의 잠긴 심이 1.16:1 이다**(5-4). 알고 두는 하자다.

## 11. 구현자가 지켜야 할 것

- **상자 크기를 안 바꾼다.** 보석·피버 24px, 유물 48px, 자루 18px. 띠 높이 72px, 줄 추가 0.
- **`image-rendering` 을 건드리지 않는다.** `mine-dig.png` · `hero-mine.png` · `mine-rock.png` 을
  고치지 않는다. 이 규격이 바꾸는 것은 **코드로 그린 SVG 뿐**이다.
- **새 색 0개 · 새 ms 0개 · 새 글자 0개 · 금색 테두리 0개 · 이모지 0개.**
- **SVG 문자열에 `;` `{` `}` 를 쓰지 않는다.** 전부 표현 속성으로 쓴다(`style="..."` 금지).
  거는 것은 `test/webview/minidom.js:31` 의 인라인 style 파서다.
- **열린 것과 잠긴 것은 한 함수에 불린 하나다.** 같은 path 를 두 벌 적지 않는다.
- **맨 그림은 띠 그림에서 주머니를 뺀 것이 아니라 따로 그린 몸이다**(보석의 밑변이 다르다. 4-1).
- `LOCK` 과 그 세 규칙을 지운다. `RELIC` 의 ink 소켓과 `FEVER` 의 4단위 밑받침도 지운다
  (POCKET 이 대신한다).
- 코드 주석은 영어.
