# 방 테마 추가하기

Agents 탭의 Room 배경을 추가하는 절차다. **순서를 지키지 않으면 라이트 테마에서 화면이 깨진다.**
아래 규칙은 2026-07-28에 정사각 디오라마에서 와이드 비네트로 전면 개편하면서 확정됐다.

---

## 왜 이렇게 하는가 (먼저 읽을 것)

예전에는 방 전체를 정사각(1:1) 프레임에 통째로 넣었다. 그림이 배경 위에 떠 있는 구조라 세 가지가
동시에 터졌다.

1. **라이트 테마에서 검은 슬랩**. 흰 패널 안에 어두운 사각형이 스티커처럼 박힘
2. **디테일이 안 읽힘**. 800px 그림이 사이드바 280px로 뭉개짐
3. **세로를 40% 잡아먹음**. "공간 너무 차지한다"는 이탈 요인

셋 다 원인이 하나다. **디오라마를 하나의 물체로 보여준 것.** 방 안쪽으로 파고들어 자르면 프레임이
바닥과 벽으로 꽉 차서 배경 자체가 사라지고, 셋이 한 번에 해결된다.

> 배경을 투명 처리해서 해결하려는 시도는 **하지 마라.** 이 그림들은 어두운 외곽선이 배경과 톤이
> 이어져 있어서, 색 기반 제거가 그림 내부까지 타고 들어가 캐릭터와 가구에 구멍을 낸다. 2026-07-28에
> floodfill·connected-components·모폴로지까지 다 시도했고 전부 실패했다. 크롭이 정답이다.

---

## 절차

### 1. 원본을 눈으로 본다

Read 도구로 직접 열어본다. 어림짐작 금지. 볼 것:

- 책상(모니터)이 어디 있는가
- 캐릭터가 설 **바닥**이 충분히 넓은 구간이 어디인가
- 방이 어느 높이에서 가장 넓은가 (아이소메트릭 다이아몬드는 중간 높이가 제일 넓다)

### 2. 1.8:1 와이드 크롭

가로 세로 비율 **1.8:1**, 최종 폭 **880px**로 맞춘다. 프레임 안에 원본 배경이 **한 픽셀도** 들어가면 안 된다.

```bash
magick "<원본>" -crop {w}x{h}+{x}+{y} +repage -resize 880x -strip room-{key}.png
```

크롭 크기는 `h = w / 1.8`로 잡는다. 1254x1254 원본 기준 `950x528` 정도가 출발점으로 무난하다.

**바닥을 아끼지 마라.** 하단이 가구 중간을 자르고 끝나면 마감이 어색해지고 캐릭터가 설 자리도 없어진다.
프레임 아래쪽은 바닥으로 끝나는 게 좋다.

### 3. 네 모서리에 배경이 들어왔는지 기계 검사

눈으로만 보면 놓친다. 원본 (2,2) 픽셀이 배경색이니 그것과 대조한다.

```bash
# 원본 배경색
magick "<원본>" -crop 1x1+2+2 +repage txt:-
# 크롭본 네 모서리 (880x488 기준)
magick room-{key}.png -crop 1x1+2+2     +repage txt:-   # TL
magick room-{key}.png -crop 1x1+877+2   +repage txt:-   # TR
magick room-{key}.png -crop 1x1+2+485   +repage txt:-   # BL
magick room-{key}.png -crop 1x1+877+485 +repage txt:-   # BR
```

배경색과 가까운 모서리가 있으면 크롭 위치를 옮긴다. 벽 색과 배경색이 비슷한 방(예: Pocket Den)은
색 대조만으로 판정이 안 되니 **반드시 크롭본을 Read로 열어 눈으로도 확인**한다.

> zsh에서 `p{x,y}` 문법은 중괄호가 깨진다. `-crop 1x1+x+y txt:-`를 쓰거나 `bash -c`로 감싼다.

### 4. 카탈로그에 등록

`extension.js`의 `rooms` 객체에 한 줄, `html.js`의 `#wsMap` 드롭다운에 `<option>` 한 줄.

```js
{key}: { name: '<표시 이름>', dark: spriteUri('room-{key}.png'), entry: [x, y], desk: [x, y] }
```

- `light:`는 **밝은 변형 이미지가 따로 있을 때만** 넣는다. 없으면 생략(다크 이미지가 양쪽에 쓰인다).
  비네트는 배경이 없어서 라이트 테마에서도 깨지지 않으므로 변형이 필수가 아니다.
- `entry` / `desk`는 **캐릭터 발 위치**, 프레임 기준 0~1 정규화 좌표다.
- 병렬 실행 시 좌우로 `±0.055`씩 부채꼴로 퍼지므로, `desk` 좌우로 그만큼의 바닥 여유를 남긴다.
- `entry`는 프레임 가장자리 쪽 바닥에 둔다. 문이 보이는 방이면 문 쪽에서 들어오게 하면 자연스럽다.

### 5. 이름 규칙

**상표를 피한다.** 원본이 특정 게임을 연상시켜도 그 이름을 쓰지 않는다. 실제 사례:

| 원본 | 쓴 이름 |
|---|---|
| 마인크래프트 풍 | Blocky Cave |
| 테라리아 풍 | Rootwood Cabin |
| 포켓몬 풍 | Pocket Den |

파일명도 마찬가지다(`room-minecraft.png`는 개편 전부터 있던 예외이고, 새로 만들면 안 된다).

### 6. 검증

```bash
node --check extension.js && node --check html.js
npx @vscode/vsce package --allow-star-activation
code --install-extension claude-usage-crab-<ver>.vsix --force
```

리로드 후 **실제로 에이전트를 하나 돌려서** 캐릭터가 바닥에 서는지 본다. 좌표는 눈대중이라 한 번은
반드시 실화면 검증이 필요하다. 허공이나 가구 위에 뜨면 `entry`/`desk`를 조정한다.

## 비용

방 하나당 vsix가 **약 0.7MB** 늘어난다. 패키지의 대부분이 방 이미지다.
테마를 급하게 늘리기보다 완성도 높은 소수를 유지하는 편이 낫다. 어느 하나가 퀄리티가 떨어지면
전체가 싸 보인다.

## 관련 상수

- 프레임 비율: `styles.js`의 `.ws-room { aspect-ratio: 1.8/1 }`
- 이미지 맞춤: `.ws-bg { object-fit: cover }`
- 룸 캐릭터 높이: `webview.js`의 `ROOM_T`(현재 39px)
