## 0. 열고 3초에 본 것

Ocean 을 입은 패널을 열고 Agents 를 누르면 **회색 확장으로 돌아간다.** 산 물건이 사라진다.

그리고 상점의 Panel 선반 여덟 칸은 **색종이 여덟 장**이다. 어느 것이 바다고 어느 것이 탄광인지
칸만 봐서는 모른다. 지금 칸이 보여 주는 것은 장면의 **왼쪽 위 48x34 를 1:1 로 자른 것**이고,
그 자리에는 대개 아무 그림도 없다(`chip-crop-vs-panel.png` 윗줄).

두 문제는 뿌리가 같다. **테마가 자기 CSS 를 두 벌 쓰게 되어 있고, 선반 칸에는 한 벌만 간다.**

## 1. 재서 알게 된 것 하나: 껍데기는 일곱 화면이 같다

사이드바 351px, Ocean 을 입힌 채 일곱 화면의 요소를 `--probe rect:` 로 쟀다.

| 화면 | `.card` | `.head` | `.tabs` | `.inner` | 판 아래 남는 띠 |
|---|---|---|---|---|---|
| Usage | 10,10 331x425 | 25,41 301x34 | 25,88 301x35 | 25,134 301x286 | **15** |
| Agents | 10,10 331x608.0 | 25,41 301x34 | 25,88 301x35 | 25,134 301x469.0 | **15** |
| 갈림길 | 10,10 331x381 | 25,41 301x34 | 25,88 301x35 | 25,134 301x242 | **15** |
| 상점 | 10,10 331x820 | 25,41 301x34 | 25,88 301x35 | 25,134 301x681 | **15** |
| 블랙잭 | 10,10 331x433 | 25,41 301x34 | 25,88 301x35 | 25,134 301x294 | **15** |
| 광산 | 10,10 331x371 | 25,41 301x34 | 25,88 301x35 | 25,134 301x232 | **15** |
| 코인시장 | 10,10 331x656.2 | 25,41 301x34 | 25,88 301x35 | 25,134 301x517.2 | **15** |

**카드의 x 와 머리·탭의 좌표가 일곱 화면에서 한 픽셀도 다르지 않다.** 다른 것은 카드 높이 하나뿐이다.
그래서 **틀의 마스크(좌우 14px 띠 + 좌상·우상 52x30)는 고칠 것이 없다.** 일곱 테마의 틀을 뜯어
보면 기둥은 전부 `/<n>px 100%` 세로 100%이고 **bottom 고정 레이어가 0개**다. 카드 높이 371~820
전 구간에서 그대로 선다.

그리고 **판(`.inner`)은 일곱 화면 전부 불투명**이다. 그래서 지금 구조 그대로 테마를 전 탭에 켜면
테마가 칠하는 면적은 이만큼이다.

```
Agents 29.9%   코인시장 28.3%   상점 24.5%   블랙잭 38.3%   갈림길 42.2%   광산 43.1%
```

이 상태를 실제로 렌더해서 봤다(`theme-across-tabs.png`). **읽을 만하다.** 카드·머리·탭·네 겹이
들어오는 것만으로 "같은 제품"이 된다. 거기서 남는 하자가 셋인데, 2~5절이 그 셋이다.

## 2. 가. 어디까지 입는가

### 2-1. 두 안

| | A 「그릇만」 | B 「전부」 |
|---|---|---|
| 토큰·장면·틀·티끌 | 전 화면 | 전 화면 |
| 안쪽 판 | 불투명 그대로 | **게임 판 빼고 투명** |
| 테마가 칠하는 면적(비Usage) | 24.5 ~ 43.1% | **100%** (게임 판은 24.5~43.1%) |
| 바닥 풍경 | 15px 에 끼어 잘림 | 판을 20px 들어올려 35px 확보 |
| 강조색 | 한 화면에 둘 (테마색 + ember 버튼) | **하나** |
| 손대는 파일 | `styles.js` · `themes/registry.js` | + `games/casino.js` 외 4 |
| 대비 재측정 | 7테마 x 4띠 | 7테마 x 7화면 x 띠 |

**B 를 고른다.** A 는 `theme-across-tabs.png` 가 그대로 보여 준다. 네 화면 중 둘에서 ember 버튼과
ember 테가 테마색 옆에 남고, 바닥의 보물상자가 카드 밑변에 끼여 잘린다. **결함을 셋 남기고
"넓혔다"고 하는 것이라 반려 목록을 다시 받는다.**

### 2-2. 겹별 판정표

| 겹 | Usage | Agents | 갈림길·게임목록·상점 | 게임 판 (블랙잭·휠·슬롯·하이로우·코인시장·광산) |
|---|---|---|---|---|
| 토큰 아홉 | 지금대로 | 입는다 | 입는다 | 입는다 |
| `.th-scene` | 지금대로 | 입는다 | 입는다 | 입는다 |
| `.th-frame` | 지금대로 | 입는다 | 입는다 | 입는다 |
| `.th-motes` | 지금대로 | 입는다 | 입는다 | **마스크가 좌우 기둥으로 좁아진다** |
| `.th-floor` | 지금대로 | 입는다 | 입는다 | 입는다 (판을 20px 들어올리고) |
| `.th-badge` | 지금대로 | 해당 없음 | 해당 없음 | 해당 없음 |
| 판 투명 | 이미 그렇다 | 새로 | 새로 | **안 한다** |

**게임 판만 불투명인 이유.** 거기가 판정이 일어나는 곳이다. 펠트·암반·차트·릴은 **그 게임의
바닥**이고, 테마 바닥과 겹치면 둘 다 죽는다. 그리고 `games/README.md` 1절이 테마가 게임 CSS 에
못 들어가게 막고 있는데, 판을 투명하게 만드는 것은 그 선을 다른 쪽에서 넘는 것이다.
**이건 "여기는 안 된다"가 아니다.** 게임 판에서도 카드·머리·탭·틀·장면·바닥은 전부 테마다.
`theme-across-tabs.png` 의 둘째 칸이 그 모습이고, 거기서 테마가 아닌 것은 녹색 펠트 하나다.

**티끌 마스크가 게임 판에서 좁아지는 이유.** 지금 마스크는 카드의 위 20px 과 아래 39px 이다.
게임 판에서는 그 두 띠가 머리줄과 베팅 줄이고, 광산에는 떨어지는 파편이, 코인시장에는 움직이는
차트가 이미 있다. **움직이는 것 둘이 한 화면에서 싸운다.** 좌우 14px 기둥으로 좁히면 테마는
계속 숨을 쉬고 판 위에는 아무것도 안 떨어진다. 껍데기 CSS 한 줄이고 테마는 모른다.

### 2-3. 판 투명화는 `--inner` 를 건드리지 않는다

`.sh-cell` 이 `background:var(--inner)` 다. **`--inner` 를 `transparent` 로 두면 상점의 칸 전부가
사라진다.** 투명하게 만들 것은 토큰이 아니라 **판 그 자체**다.

```css
/* 껍데기가 쓴다. 테마는 #panelShop 을 이름으로 못 부른다(registry 의 NEVER 목록) */
body[data-theme]:not([data-theme=""]) #panelAgents,
body[data-theme]:not([data-theme=""]) #panelCross,
body[data-theme]:not([data-theme=""]) #panelGames,
body[data-theme]:not([data-theme=""]) #panelShop{background:transparent;}
```

Ocean 이 `#panelUsage{background:transparent}` 를 자기 meta 에 쓰고 있는데, **그것도 껍데기로
옮긴다.** 일곱 테마가 같은 한 줄을 일곱 번 쓸 이유가 없고, 여덟째 테마가 빠뜨리면 그 테마만
장면이 안 보인다.

## 3. 나머지 하나: scope 를 하나로 줄인다

지금 테마는 CSS 를 **두 벌** 쓴다.

```
body.tab-usage[data-theme="ocean"] { ...장면... }     29행
.th-chip[data-th="ocean"]          { ...장면 또 한 번... }   89행
```

**이 중복이 2절과 4절을 동시에 막고 있는 것이다.** 선반 칸에 틀과 바닥까지 보여 주려면 복사본이
두 배가 되고, 그러면 드리프트한다(`spec.md` 12절이 이미 "스와치가 작다"로 이 실패를 적어 뒀다).

### 바꿀 것

**테마는 한 벌만 쓴다.**

```css
body[data-theme="ocean"]{ --card:#0a1b2e; ... }
body[data-theme="ocean"] .th-frame{ background: ... }
body[data-theme="ocean"] .th-floor{ background: ... }
```

등록부가 **같은 규칙을 한 번 더 찍는다.** 접두사를 문자열로 바꿔 치는 것이고, 파싱이 아니다.
검사(`whyNotCss`)가 이미 「모든 선택자가 이 접두사로 시작한다」를 증명한 뒤이므로 `split/join`
하나면 된다.

```
body[data-theme="ocean"]   ->   .th-skin[data-th="ocean"]
```

`.th-skin` 은 **테마를 맥락 밖에서 입는 상자**다. 선반 칸과 미리보기 상자가 그것을 쓴다.
`#panelUsage` 처럼 상자 안에 없는 것을 가리키는 규칙은 아무것도 안 맞고, 그게 정상이다.

### 특이도

| 선택자 | 특이도 | 비고 |
|---|---|---|
| `body.vscode-light` | 0,1,1 | 테마와 **동점**. `html.js` 202행이 테마를 뒤에 붙이므로 테마가 이긴다 |
| `body[data-theme="x"]` | 0,1,1 | |
| `.th-skin[data-th="x"]` | 0,2,0 | 라이트 팔레트를 이긴다. 선반은 무엇을 입고 있든 제 색이다 |
| `body.vscode-high-contrast` | 0,1,1 | **지금은 테마에 진다. 이건 결함이다** (아래) |

**고대비 모드가 테마에 지고 있다.** 오늘도 그렇다. `body.tab-usage[data-theme="x"]`(0,2,1)가
`body.vscode-high-contrast`(0,1,1)를 이겨서, 고대비를 켠 사람이 테마를 사면 Usage 탭이 테마 색이
된다. 전 탭으로 넓히면 패널 전체가 그렇게 된다.

```css
/* 고대비는 접근성 모드다. 테마가 이기면 안 된다 */
body.vscode-high-contrast[data-theme]{ /* 지금 값 그대로, 특이도만 0,2,1 */ }
body.vscode-high-contrast .th-l{display:none;}
```

### 등록부에 더할 선언 금지 목록

scope 가 body 로 넓어지면 토큰 하나가 게임까지 간다. 못 건드리게 막을 것:

```
--felt --felt-lo --felt-ink --felt-dim      펠트는 게임의 것 (spec.md 2절)
--bubble --bubblebd                          말풍선
```

판정색 넷(`#f0553a #f0a83a #e5484d #4fae74`)과 동전(`#c25a34 #e8b23a`)은 토큰이 아니라
리터럴이라 테마가 닿을 수 없다. 규격에만 적어 두고 검사는 안 만든다.

## 4. 강조색은 하나다: ember 13곳의 갈림

`games/` 안에 `#e8895a` 리터럴이 13곳 있다. `spec.md` 11절은 "그대로 둔다"고 적었는데,
그 근거가 **"패널 테마는 게임 화면에 들어가지 않는다"**였다. 그 전제가 뒤집혔으므로 다시 가른다.

**기준은 "그 주황이 무엇인가"다.**

| 무엇을 그리나 | 어떻게 | 확인한 곳 |
|---|---|---|
| **게 그림 자체** | ember 그대로. 게는 사용자 것이고 테마의 것이 아니다 | `games/symbols.js` 2곳(집게·등딱지), `games/tiles.js` 1곳(카드 그림) |
| **행동·상태·수치** | `var(--accent)` 로 | `games/casino.js` 3곳(`.bj-btn.primary` 바탕, 즐겨찾기 별, 목록 행 아이콘) |
| 나머지 7곳 | 같은 기준으로 구현자가 가른다 | `market/meta.js` 1 · `slots/meta.js` 3 · `wheel/meta.js` 2 · `wheel/panel.js` 1 |

**채워진 강조 판 위의 글자색은 새 토큰을 만들지 않는다.** 켜진 탭이 이미 그 문제를 풀어 뒀고
(`--tabon` 바탕 / `--tabonink` 글자), 일곱 테마가 전부 `--tabonink:#0d0d0f` 를 들고 있다.
`.bj-btn.primary` 의 하드코딩 `color:#1d1d1f` 가 그 자리다.

그리고 Agents 탭에서 같은 일이 두 군데 더 있다(`theme-across-tabs.png` 셋째 칸에서 보인다).

```
Room 머리 아이콘    ember 하드코딩   ->  --accent   (옆의 Crew 아이콘은 이미 --accent 다)
고른 크루 카드의 테  ember 하드코딩   ->  --accent
크루 이름 딸림줄     ember 하드코딩   ->  --accent
```

**판정색 넷은 안 움직인다.** 90%/70%/경고/완료는 테마가 못 건드리고, 그래서 테마색이 바뀌어도
"위험"은 늘 같은 빨강이다. 그게 강조색을 하나로 줄이는 진짜 이유다. 강조가 둘이면 어느 쪽이
판정인지 매번 다시 배워야 한다.

## 5. 바닥 풍경: 판을 20px 들어올린다

`spec.md` 5-2 가 정한 대로 **바닥 오브젝트는 카드 밑변에서 34px 안에 산다.** Usage 탭에서 그것이
글자를 안 가리는 이유는 통계 줄 밑에 항상 39px 이 쌓이기 때문이다(타일 10 + 판 13 + 카드 14 + 테).

**다른 여섯 화면에서 그 값은 15px 다.** 1절 표의 마지막 칸이 전부 15다.
그래서 지금 상태로 바닥을 켜면 보물상자가 카드 밑변에 **잘린 채** 박힌다. 실제로 그랬다
(`theme-across-tabs.png` 네 칸 전부 아래쪽).

```
필요한 것 34   있는 것 15   ->   20px 들어올린다   (15 + 20 = 35 >= 34)
```

```css
body[data-theme]:not([data-theme=""]) .card > .inner:not(#panelUsage){margin-bottom:20px;}
```

**대가는 비Usage 탭이 20px 길어지는 것이고, 테마를 안 산 사람에게는 아무 일도 안 일어난다.**
`spec.md` 5-1 이 틀 예산으로 카드 위 패딩을 14->30 으로 키운 것과 같은 거래다. 다만 그때는 모두가
16px 을 냈고 이번에는 산 사람만 낸다.

그리고 이 20px 이 대비 문제를 **없앤다.** 들어올린 띠에는 글자가 하나도 없으므로 바닥 풍경의
밝기 상한(0.0520)을 다시 풀 띠가 늘지 않는다. 늘어나는 것은 "글자 0"을 확인하는 측정뿐이다.

## 6. 나. 미리보기

### 6-1. 축소판인가 견본인가

| | 축소판 (패널을 그대로 줄인 것) | 견본 (테마 조각을 모은 판) |
|---|---|---|
| 테마가 더 쓸 CSS | **0줄.** 이미 쓴 것을 `.th-skin` 이 다시 쓴다(3절) | 테마마다 조각 배치 한 블록 |
| 틀 기둥 | 110px 상자에서 6.2px | 1:1 로 보여 주면 14px |
| 바닥 오브젝트 띠 | 110px 상자에서 15.0px | 1:1 로 보여 주면 34px |
| 악세(88x74) | 들어온다(제자리에) | 110x198 의 66%를 먹는다. 못 넣는다 |
| 실물과 어긋남 | **구조적으로 불가능.** 같은 좌표계·같은 CSS | 좌표계가 달라 패널을 고치면 따로 썩는다 |
| 조각이 더 커 보이는 값 | | 2.3배 |

**축소판을 고른다.** 견본이 조각을 2.3배 크게 보여 주는 것은 사실이고 그게 견본의 유일한 장점인데,
**조각이 커도 "그 테마가 어떻게 생겼나"에는 답하지 않는다.** 바다를 가르는 것은 산호의 크기가
아니라 파도 마루가 위에 있고 보물상자가 아래에 있다는 배치다. 그리고 테마당 블록을 하나 더
쓰게 하는 순간 3절에서 없앤 중복이 돌아온다.

### 6-2. 축소판에 뼈대를 넣는다 (낱말은 안 넣는다)

세 가지를 렌더해서 나란히 놓았다(`preview-content.png`).

```
A  겹만 (장면·틀·바닥·티끌)              ->  벽지로 읽힌다. 일곱을 섞어 놓으면 색만 남는다
B  겹 + 뼈대, 낱말 0                      ->  패널로 읽힌다
C  겹 + 뼈대 + 낱말 (지금 패널 그대로)   ->  B 와 다르지만, 그 차이가 테마를 가르지 않는다
```

**뼈대**는 넷이고 전부 강조색이다. 켜진 탭 칩 · 막대 셋 · 링 호 · 통계 아이콘 셋.
110px 상자에서 이 넷이 차지하는 면적은 21,780px² 중 **868px², 4.0%**다. 화면의 4%인데
A 와 B 의 차이가 저만큼이다. **대비가 제일 높은 4%라서 그렇다.**

C 를 안 고르는 이유는 두 가지다. 낱말(`1,240 credits`, `61%`, `2h 05m`)은 **일곱 테마가 전부
같으므로 테마를 가르는 데 한 글자도 보태지 않는다.** 그리고 낱말을 넣으려면 살아 있는 카드를
복제해야 하는데, id 중복·APNG 재시작·카드 안의 카드라는 문제를 셋 다 떠안는다.
**뼈대는 껍데기가 한 번 쓰는 정적 마크업이고, 테마는 그것을 모른다.**

낱말이 없으므로 `spec.md` 2절의 "테마가 낱말을 더하지 않는다"도 지킨다.

### 6-3. 크기: 폭이 아니라 **배율**을 고정한다

사다리를 렌더해서 쟀다(`preview-ladder.png`). 패널 250px 기준.

| 미리보기 폭 | 바닥 오브젝트 띠 | 틀 기둥 | 켜진 탭 칩 | 무엇이 오나 |
|---|---|---|---|---|
| 48px | 6.5 | 2.7 | 18.6x5.2 | 색과 켜진 탭까지. 바닥은 뭉갠다 |
| 64px | 8.7 | 3.6 | 24.8x6.9 | 바닥에 무엇이 **놓여 있다**는 것까지 |
| 80px | 10.9 | 4.5 | 31.0x8.6 | 그 무엇의 윤곽이 갈린다 |
| **110px** | **15.0** | **6.2** | 42.7x11.9 | 광차냐 보물상자냐 서버랙이냐가 온다 |

110 은 `spec.md` 0절이 이미 적어 둔 판정선이고(`thumbs-110.png`), 이 사다리가 그 값을 다시 낸다.

**그런데 바닥 오브젝트와 틀 기둥은 사이드바 폭을 안 따라간다.** 바닥 오브젝트는 `left 162px
bottom 2px` 처럼 고정 px 로 놓여 있고 기둥은 14px 띠다. 그래서 미리보기의 **폭을 110 으로
고정하면** 사이드바가 넓을수록 배율이 떨어지고 띠가 얇아진다(351px 사이드바에서 10.6px).

```
배율을 고정한다.   k = 0.44          (= 110 / 250, 이 제품이 설계 기준으로 쓰는 폭)
미리보기 폭      = 0.44 x 사이드바 폭,  220px 에서 끊는다
```

| 사이드바 | 미리보기 폭 | 바닥 띠 | 틀 기둥 | 조준 블록 안 폭 | 들어가나 |
|---|---|---|---|---|---|
| 190 | 84 | **15.0** | **6.2** | 84 | 들어간다 |
| 250 | 110 | **15.0** | **6.2** | 144 | 들어간다 |
| 351 | 154 | **15.0** | **6.2** | 245 | 들어간다 |
| 500+ | 220 (상한) | 15.0 | 6.2 | 넉넉 | 들어간다 |

**배율을 고정하면 재는 값 둘이 모든 폭에서 같다.** 상한 220 은 취향이 아니라 경계다. 그 위로는
미리보기가 아래 선반을 화면 밖으로 밀어낸다.

높이는 `0.44 x 지금 Usage 패널의 바깥 높이`다. 오늘 잰 값은 190~200px(wrap 445~451).
모서리 반경은 `16 x 0.44 = 7px`, `overflow:hidden`, `aria-hidden="true"`
(이름과 값은 옆의 `.sh-nm`/`.sh-price` 가 이미 글자로 말한다).

### 6-4. 어디에 띄우나: 조준 블록. 호버는 안 쓴다

지금 `.sh-try`(조준 블록)가 **살 것 옆에 그 그림을 88x74 로 보여 주는 자리**다. 테마는 그릴 것이
없어서 칩을 그 크기로 늘려 놓았다. **그 자리를 미리보기로 바꾼다.** 새 상호작용이 0개다.

```
안 사람이 칸을 누른다  ->  그 칸이 aim 이 된다  ->  조준 블록이 그 테마의 축소판이 된다
                                                  ->  바로 밑 버튼이 그것을 산다
```

**호버를 안 쓰는 이유 셋.**

1. **키보드와 터치에 같은 길이 없다.** 호버 팝오버를 만들면 포커스로도 열리게 또 만들어야 하고,
   그건 같은 것을 두 번 만드는 것이다. 누르기는 세 입력 전부에서 이미 된다.
2. **칸 여덟이 4열로 붙어 있다.** 110~154px 짜리 팝오버가 64px 칸 옆에 뜨면 이웃 칸 두세 개를
   덮는다. 사이드바가 190px 일 때는 덮을 자리도 없다.
3. **조준 블록은 이미 그 자리에 있고 이미 그 일을 한다.** 호버 팝오버는 블록을 안 없애므로
   **같은 답이 화면에 둘**이 된다.

누른 칸이 화면 밖이면 블록을 `scrollIntoView({block:'nearest'})` 한다. 테마 선반은 블록 바로
위라 보통 필요 없고, 마스코트 선반에서 누른 경우를 위한 한 줄이다.
`.sh-try.ping` 은 지금대로 둔다.

> 호버가 그래도 필요하다고 판단되면 **같은 0.44 상자를 그대로 띄우면 된다.** 설계는 더 들지 않는다.
> 다만 위 셋을 감수하는 결정이고, 그건 사용자가 정한다.

### 6-5. 산 테마는 「입는 것」이 미리보기다

가(2절)가 끝나면 **상점 화면도 테마를 입는다.** 그래서 이미 산 테마의 칸을 누르면 그 자리에서
**패널 전체가 그 테마로 바뀐다.** 축소판보다 나은 미리보기이고 공짜다.

```
안 산 테마  누르면 aim  ->  조준 블록에 축소판 + 살 버튼
산 테마     누르면 착용  ->  서 있는 화면이 통째로 바뀐다. 미리보기 위젯이 필요 없다
```

이게 가와 나가 같은 문서에 있는 이유다. **가를 하면 나의 절반이 저절로 풀린다.**

## 7. 다. 선반 칸은 안 키운다. 칩의 내용을 바꾼다

### 7-1. 지금 칩이 무엇을 보여 주나

```css
.th-chip::before{ background:var(--th-scene); background-size:250px 598px; }
```

48x34 상자에 장면을 **1:1 로** 깐다. 보이는 것은 **패널 왼쪽 위 48x34 의 crop** 이고,
그 자리는 대개 장면의 빈 구석이다. `chip-crop-vs-panel.png` 윗줄이 그 결과다.

### 7-2. 같은 상자에 패널의 윗띠를 넣는다

같은 48x34 에 **패널을 1:5.2 로 줄여 위에서 34px 만큼** 보여 준다(= 패널 위 177px).

```
들어오는 것   머리의 게 8.4x6.5 · 켜진 탭 칩 18.6x5.2 · 틀 좌상/우상 모서리 10x5.8 ·
             장면에서 가장 밝은 띠 · 첫 막대의 머리
안 들어오는 것  바닥 풍경 (48px 폭에서 6.5px 라 어차피 안 읽힌다)
```

`chip-crop-vs-panel.png` 아랫줄이 그 모습이고, **그게 합격 기준 그림이다.**
칩의 배율은 사이드바와 무관하게 `48/250 = 0.192` 로 고정한다. 선반은 카탈로그이고, 같은 물건은
누구 화면에서나 같은 그림이어야 한다.

### 7-3. 칸·열·높이는 그대로

| 사이드바 | 판 안쪽 폭 | 열 | 8칸이 차지하는 줄 | 선반 높이 |
|---|---|---|---|---|
| 190 | 140 | 2 (2x64+4=132) | 4 | 268 |
| 250 | 200 | 3 (3x64+2x4=200) | 3 | 200 |
| 351 | 301 | 4 (4x64+3x4=268) | 2 | 132 |

**오늘과 똑같다. 선반이 1px 도 안 길어진다.**

### 7-4. 세로 칸을 안 쓰는 이유 (잰 값)

칸을 세로로 키우는 안을 재 봤다.

```
칩 56x101 (패널 전체, k=0.224)
   바닥 오브젝트 띠 7.6px   ->  48px 짜리(6.5)보다 1.1px 나을 뿐, 여전히 안 읽힌다
   선반 높이  351 에서 +128px,  250 에서 +192px

바닥이 읽히려면 폭 74px 이상이 필요한데(띠 10.1px), 74px 칸은 250px 사이드바에서 2열이다
   ->  칸 높이 150 x 4줄 + 간격 = 612px.  이미 820px 인 상점에 +412px
```

**값을 못 한다.** 세로 칸이 사는 값은 "바닥까지 보여 주는 것"인데 그 값을 못 산다.
바닥은 미리보기(0.44, 띠 15.0px)가 보여 주면 되고, 선반 칸의 일은 **고를 수 있게 갈라 주는
것**이다. 7-2 가 0px 으로 그 일을 한다.
