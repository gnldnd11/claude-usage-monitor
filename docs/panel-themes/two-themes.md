# 정예 둘: 풀숲과 탄광 (3차 · 판 발주 규격서)

> **이 문서는 그림을 그리지 않는다. 무엇을 몇 픽셀로 몇 장 받아야 이 패널에 붙는지를 정한다.**
> 그림은 사용자가 만든다. 여기 있는 것은 판(plate) 열넷의 규격과, 그 판을 받아 붙일 배관과,
> 판이 오기 전까지 자리를 지킬 CSS 다.
>
> 라이브 **배치 시안**: `docs/panel-themes/live/two-themes.html`
> 계약 정본은 `themes/README.md`. 이 문서가 그 계약을 다섯 넓히자고 제안한다(4·5절).
> 값이 어긋나면 넓히기 전까지는 `themes/README.md` > `reach-and-preview.md` > `spec.md` > 이 문서 순.
>
> 2026-11-27. 전부 Chrome 렌더에서 쟀고 **실제 확장에서는 안 봤다.** 확장 코드는 한 줄도 안 고쳤다.

## 0. 왜 3차인가

반려가 둘이다.

```
1차 (둥근 평면 실루엣)   "복셀로 해보라는건 다 무시하고 그냥 이렇게했구나"
2차 (4px 하드 엣지 블록) "복셀은 더 구리네. 누가봐도 조잡해보이지않음?
                          진짜 풀같은 부쉬같은그런질감을원하는데 탄광도 진짜 돌같고 횃불같은"
```

그리고 사용자가 **목표 수준을 그림으로 보여 줬다.** 그림 모델이 만든 회화 수준의 일러스트 여섯 장이다.
숲은 네 변을 덩굴과 잎이 둘러싸고 잎마다 명암이 따로 있다. 광산은 좌우에 목재 지지대와 위에 들보가
있고 나뭇결과 못자국과 접촉그늘이 있으며 등유 램프가 광륜을 뿌린다.

**그 수준은 CSS 그라데이션으로 도달할 수 없다.** 그라데이션은 색 면을 만드는 도구이고,
1차는 둥근 얼룩이 됐고 2차는 각진 얼룩이 됐다. 같은 재료로 세 번째를 그리면 세 번째 얼룩이 나온다.
그래서 **재료를 PNG 로 바꾼다.** 이 문서는 그 전환의 설계다.

> 그 컨셉 그림에 「이미지 없이도 구현 가능 (필요 시 SVG 인라인)」이라는 체크리스트가 붙어 있다.
> **그림 모델이 지어낸 것이고 근거가 아니다.** 이 문서는 그 줄을 따르지 않는다.

### 버린 것과 살린 것

| | |
|---|---|
| **버린다** | 2차의 4px 큐브 어법 전부. `--fx-seam`·`--fx-bevel`·격자에 맞춘 `clip-path`·블록 실루엣. 바닥의 「버섯 셋 · 풀 둘 · 돌 하나」 줄 세우기. 1차의 둥근 평면 실루엣 |
| **살린다** | 1절의 하자 셋 · 좌표 규칙(왼쪽은 `left`, 오른쪽은 `right`, 폭은 `100%`) · 겹 자식 26개 계약 · `.inner` 투명화 · reduced-motion 가드 · 띠 23px 결정과 근거 · 측정 방법 |
| **고쳐 살린다** | 입자. 2차는 4px 하드 엣지 큐브였다. **원형 광점으로 바꿨다**(`border-radius:50%` + radial + glow). 복셀을 버렸으니 큐브 입자도 버린다 |
| **고쳐 살린다** | 빛기둥. 2차는 하드 스톱 쐐기였다. **경계를 전부 부드럽게 했다.** 빛은 물건이 아니라 공기 중에 퍼지는 것이다 |

## 1. 재서 알게 된 하자 셋 (출시판의 것. 1차·2차 그대로이고 여전히 유효하다)

### 1-1. 오른쪽 기둥이 없다

틀의 그림이 250px 랩 좌표로 쓰여 있는데(`236px 0/14px 100%`) 마스크는 `right 10px/14px` 라 폭을 따라간다.
351px 랩에서 마스크가 통과시키는 자리는 x337..351 인데 그림은 x228..250 에 있다. 왼쪽만 `0 0/...` 이라
우연히 살았다.

### 1-2. 지면이 카드의 3분의 2에서 끊긴다

지면이 `0 0/230px 156px no-repeat` 다. 230 은 250px 사이드바의 카드 폭이다.

### 1-3. 바닥 풍경이 카드 밑 15px 에만 보인다

`.inner` 가 `background:var(--inner)` 로 불투명하다.

### 결론: 규칙 하나

> **왼쪽 물건은 `left`, 오른쪽 물건은 `right`, 가운데 물건은 `left:50%` + 음수 margin.
> 폭은 `100%` 또는 타일. 그림에 랩 폭을 숫자로 박지 않는다.**

**3차는 이 규칙을 그대로 쓴다.** 판 열넷 중 랩 폭이나 패널 높이를 숫자로 박은 것은 하나도 없다
(9절 측정표가 그것을 증명한다).

## 2. 겹을 PNG 와 CSS 로 가르는 원칙

**전부 PNG 로 하면 늘어나지 않고 용량도 터진다. 전부 CSS 로 하면 1차·2차가 된다.**
가르는 선은 「늘어나야 하는가」다.

| 겹 | 재료 | 왜 |
|---|---|---|
| `.th-scene` | **CSS** | 바탕·빛기둥·안개·비네트. **폭과 높이를 전부 따라가야 하는 것들**이다. 그라데이션은 늘어나도 안 깨지고, 애초에 그라데이션으로 그리는 것이 맞는 대상이다. 190~600px, 425~820px 전 범위에서 한 벌로 산다 |
| `.th-frame` | **PNG** | 덩굴·잎·목재 지지대·램프 본체. **고정 크기 조각으로 쪼갤 수 있다.** 9-slice |
| `.th-floor` | **PNG + CSS** | 바닥 물건은 PNG 고정 판, 좌우로 이어지는 땅은 PNG 가로 타일. 그 위에 덮는 어둠만 CSS |
| `.th-motes` | **CSS** | 반딧불·불티·먼지. 2~4px 광점 여덟이고 **각자 다른 시계로 움직인다.** PNG 로 할 이유가 없고, PNG 로 하면 여덟 장이 더 생긴다 |
| `.th-badge` | **PNG** | 게가 쓰는 것. 40x24 한 장 |
| `.th-orbit` | **안 쓴다** | 5-3 에 근거 |

**움직임은 전부 CSS `transform`·`opacity` 다.** PNG 를 얹은 `<i>` 를 흔들면 잎이 흔들린다.
실측 애니 13개/테마, 속성 두 개 외 0건(9절).

## 3. 9-slice 를 무엇으로 구현하나: **`<i>` 다섯 개**. `border-image` 는 탈락

### 3-1. `border-image` 가 안 되는 이유는 기하다

`border-image` 는 한 장의 아틀라스를 슬라이스해 모서리를 고정하고 변을 타일링한다.
파일이 하나라 `art.frame` 을 문자열 그대로 쓸 수 있어서 가장 싸다. **그런데 기하가 안 맞는다.**

```
모서리의 크기 = 맞닿은 두 변의 두께의 곱.      이것이 border-image 의 고정 규칙이다
```

이 패널이 쓸 수 있는 자리는 측정으로 이렇게 나온다(351px, 실측).

```
상변   y0..40     전폭.  글자가 하나도 없다
좌우   23px       전높이. spec.md 가 이미 잰 안전영역 B 의 폭
```

**모서리를 62~72px 폭으로 쓰고 싶은데 변은 23px 이어야 한다.** `border-image` 로 모서리를 72px 로
만들려면 좌우 border 가 72px 이 되고, 그러면 변이 72px 폭으로 글자를 덮는다(카드 패딩은 14px 다).
반대로 변을 23px 로 맞추면 모서리가 23x40 이 되어 **덩굴 뭉치도 램프도 그 안에 안 들어간다.**

컨셉 그림이 모서리에 무게를 싣고 변은 가늘게 가는 구도이므로, **이 제품에서 모서리와 변의 두께는
독립이어야 한다.** `border-image` 는 그것을 구조적으로 못 한다.

### 3-2. 그래서 조각 = 요소다

```
1 tl    72x40    고정        좌상 모서리
2 tr    72x40    고정        우상 모서리
3 t     64x40    가로 타일   상변.  left:64px right:64px  (모서리와 8px 씩 겹친다)
4 l     23x240   세로 타일   좌 변.  top:32px bottom:10px
5 r     23x240   세로 타일   우 변
6 sa    56x40    고정·움직임  흔들리는 앞겹 / 램프 불꽃
7 sb    52x36    고정·움직임  흔들리는 앞겹 / 쇠사슬
8·9·10  미사용               계약이 열을 주지만 일곱으로 액자가 선다
```

**한 요소의 `background` 레이어로는 안 된다.** 레이어마다 `repeat` 를 따로 줄 수는 있지만,
**크기가 다른 타일들의 position 을 좌·우 양끝 기준으로 동시에 잡을 수가 없다.**
(`right 0` 과 `left 64px` 을 한 레이어가 같이 못 가진다.) 조각이 요소여야 하는 이유다.

### 3-3. 하변을 두지 않는 이유

`.th-floor` 가 전폭 156px 높이로 하단을 이미 가진다. frame 에 하변을 더 두면 **같은 자리를
두 겹이 그린다.** 좌우 변의 아래 끝 단면은 **CSS 마스크 페이드**가 흙 쪽으로 지운다.

```css
mask:linear-gradient(180deg,transparent 0,#000 14px,#000 calc(100% - 26px),transparent 100%)
```

위 14px 은 모서리 판 밑으로 들어가는 구간이고, 아래 26px 은 지면에 묻히는 구간이다.
**마지막 타일이 몇 번째에서 잘리든 그 단면이 안 보인다.** 측정: 좌 변 타일이 425px 패널에서
1.70회, 820px 패널에서 3.31회 반복된다(9절).

### 3-4. 타일의 이음매는 「매듭」으로 푼다

픽셀 단위 seamless 를 그림 모델에 요구하면 잘 안 나온다. 그래서 **타일의 상하(또는 좌우) 경계에
의도된 반복 요소를 놓는다.**

```
세로 타일   경계에 대나무 마디 / 갱목의 쇠 보강띠.  240px 마다 한 번 오는 것이 자연스럽다
가로 타일   경계에 덩굴 매듭 / 널빤지 이음과 못.    64px 마다
```

**이음매가 완벽하지 않아도 그 자리에 마디가 있으면 마디로 읽힌다.** 발주 규격서의
「이음매 요구」 항목이 전부 이 형태인 이유다.

## 4. 마스크를 세 띠로 다시 쓴다 (껍데기 변경)

출시판은 네 조각(좌우 14px + 모서리 창 52x30 둘), 2차 설계는 다섯이었다. **셋으로 줄인다.**

```css
.th-frame{
  mask:linear-gradient(#000,#000) left 0 top 0/100% 40px no-repeat,
       linear-gradient(#000,#000) left 0 top 0/23px calc(100% - 10px) no-repeat,
       linear-gradient(#000,#000) right 0 top 0/23px calc(100% - 10px) no-repeat}
```

**상변을 모서리 창 둘로 쪼갤 이유가 없다는 것이 측정 결과다.**

```
card(10,10) + border 1 + padding-top 30  ->  머리줄이 y41 에서 시작한다 (실측 40.7)
접기 버튼                                 ->  y46..70.  더 아래다
```

y0..40 전폭에 글자가 **하나도 없다.** 그래서 전폭 40px 띠 한 장이면 「패널 네 변을 액자가 둘러싼다」가
된다. 좌우 23px 는 `spec.md` 가 이미 잰 값이고, 아래는 랩 하단 10px 만 비운다.

**좌우 띠가 글자를 먹지 않는다는 것도 쟀다.** 190px 사이드바(가장 좁은 경우)에서
우 띠의 안쪽 끝이 카드 좌표 157px, 내용의 바깥 끝이 155px. **2px 여유로 안 겹친다.**
구조적으로도 보장된다: 띠 23 < 셸 10 + 카드 패딩 14 + border 1 = 25.

## 5. 판 목록 열넷 — **발주 규격서**

**이 절이 본체다.** 판마다 아래를 적는다. 그릴 내용 문단은 그림 모델에 그대로 넣을 수 있게 썼다.

### 5-0. 모든 판에 공통인 것

```
형식        PNG, 알파 포함(투명 배경). 배경을 색으로 채우지 않는다
해상도      표의 @2x 픽셀 그대로. 표시 크기의 2배이고 그 이상은 받지 않는다
파일명      <테마>-<판>.png    예: forest-frame-tl.png · mine-floor-center.png

색          테마의 어두운 바닥 위에 놓인다. 풀숲 카드 #0f1a10 · 탄광 카드 #17120e
금지        금색 테두리. 빨강 #e5484d 계열(경고색이다). 글자. 숫자. 로고. 이모지
```

**안전 여백의 공통 규칙 셋.** 어기면 글자를 덮는다.

```
가. 상변 판(1·2·3)은 아래 12px 의 알파가 0 으로 빠져야 한다
    y40 바로 아래 0.7px 에 머리 게와 크레딧 숫자가 있다. 경계가 딱 끊기면 글자를 누른다
나. 바닥 판(10·11·12·13)의 내용은 판 상자 안을 다 써도 되지만, 상자 자체가 카드 밑변에서
    34px 안에 있다. 그 밖으로 나가는 설계는 하지 않는다(이 표의 높이가 이미 그 값이다)
다. 먼 층(9)은 통계 줄 뒤에 있다. **가장 밝은 화소의 상대휘도가 0.052 이하**여야 한다.
    대략 #3a3a3a 보다 밝은 화소가 없어야 한다는 뜻이다. 실루엣만 그린다
```

## 6. `art` 계약을 어떻게 넓혀야 하나 (**코드는 안 고쳤다. 문서에만 쓴다**)

### 6-1. 지금 있는 문

`themes/registry.js` 의 `artCss`(436행~)가 그 문이다. 테마가 `art:{floor:'x.png'}` 를 적으면
호스트가 URI 로 풀고 겹이 `background-image:var(--th-floor)` 로 읽는다.

```js
const vars = Object.keys(t.art).map((k) => '--th-' + k + ':url(' + uri(t.art[k]) + ');').join('');
```

**지금은 「칠해지는 겹 하나 = 파일 하나」다**(`whyNotMeta` 303~305행).
9-slice 는 `frame` 한 겹에 일곱 장이 필요하다.

### 6-2. 넓히는 안: **값이 문자열이거나 파트 객체**

```js
// whyNotMeta 안, 지금의 for (const k in art) 루프를 이렇게 바꾼다
const PART_RE = /^[a-z][a-z0-9-]{0,15}$/;
for (const k in art) {
  if (PAINTED.indexOf(k) < 0) return 'art names "' + k + '", which is not a painted layer';
  if (t.layers.indexOf(k) < 0) return 'art names "' + k + '", a layer this theme does not claim';
  const v = art[k];
  if (typeof v === 'string') { if (!v) return 'art.' + k + ' must be a filename'; continue; }
  if (!v || typeof v !== 'object' || Array.isArray(v)) {
    return 'art.' + k + ' must be a filename, or an object of named parts';
  }
  const parts = Object.keys(v);
  if (!parts.length) return 'art.' + k + ' names no part';
  for (const p of parts) {
    // a part name goes into a CSS custom property, so it may hold nothing that needs escaping,
    // which is the same rule ID_RE enforces on a theme's own id
    if (!PART_RE.test(p)) return 'art.' + k + '.' + p + ' is not a part name';
    if (typeof v[p] !== 'string' || !v[p]) return 'art.' + k + '.' + p + ' must be a filename';
  }
}
```

```js
// artCss
function artCss(uri) {
  let out = '';
  for (const t of THEMES) {
    const vars = [];
    for (const k of Object.keys(t.art)) {
      const v = t.art[k];
      if (typeof v === 'string') vars.push('--th-' + k + ':url(' + uri(v) + ');');
      else for (const p of Object.keys(v)) vars.push('--th-' + k + '-' + p + ':url(' + uri(v[p]) + ');');
    }
    if (vars.length) out += 'body[data-theme="' + t.id + '"]{' + vars.join('') + '}';
  }
  return out;
}
```

테마는 이렇게 쓴다.

```js
art: {
  frame: { tl:'forest-frame-tl.png', tr:'forest-frame-tr.png', t:'forest-frame-t.png',
           l:'forest-frame-l.png',   r:'forest-frame-r.png',
           sa:'forest-frame-sa.png', sb:'forest-frame-sb.png' },
  floor: { ground:'forest-floor-ground.png', far:'forest-floor-far.png',
           center:'forest-floor-center.png', left:'forest-floor-left.png',
           right:'forest-floor-right.png',  sway:'forest-floor-sway.png' },
  badge: 'forest-badge.png'
}
```

### 6-3. 키 이름을 `frame-tl` 로 늘리는 안을 버린 이유

`PAINTED` 와 `layers` 가 **같은 이름 목록을 공유한다.** `art['frame-tl']` 을 허용하려면
`PAINTED` 에 일곱 개를 더 넣어야 하고, 그 순간 `layers:['frame-tl', ...]` 도 선언 가능해진다.
그러면 `picturesOf` 가 세는 겹 수가 3 에서 15 로 뛰고 **가격 등급이 10K 에서 1000K 로 올라간다.**
등록부가 「겹 수로 센다」고 못 박은 바로 그 성질이 깨진다.

**중첩 객체는 그 선을 안 건드린다.** `picturesOf` 는 `t.layers` 만 보므로 한 글자도 안 고친다.
**가격은 지금과 같다**(frame · floor · badge = 3 겹 = 10K).

### 6-4. 다른 두 곳

| 무엇 | 왜 |
|---|---|
| `surfaceOf`·`whyNotCss`·`rungOf`·`picturesOf`·`normalize` | **안 고친다.** 전부 `art` 를 안 본다 |
| `test/themes.test.js` | `art` 가 객체인 경우를 넣는다. 파트 이름이 `PART_RE` 를 어기면 드롭되는지도 |

## 7. 전환기: 판이 하나도 없을 때, 그리고 한 장씩 들어올 때

**판 자리는 전부 `var(--th-…, <폴백>)` 이다.** 변수가 정의되지 않았을 때만 폴백이 그려지고,
`artCss` 가 그 변수를 내는 순간 그 자리만 PNG 로 덮인다. **한 장씩 들어와도 깨지지 않는다.**

```css
background-image:var(--th-frame-l,linear-gradient(90deg,var(--fb-lit) 0 5px,
  var(--fb-mid) 5px 11px,var(--fb-ink) 11px 16px,transparent 16px));
```

### 폴백은 **둘뿐**이다

| 자리 | 폴백 |
|---|---|
| 좌 변 · 우 변 (4·5) | 세로 기둥 그라데이션. 출시판이 하던 것과 같은 수준 |
| 땅 (8) | 흙 띠 그라데이션 |
| **나머지 열한 자리** | **`none`.** 아무것도 안 그린다 |

**처음에는 모서리와 상변에도 폴백을 그렸다. 보고 걷어냈다.** 모서리가 대각 그라데이션,
상변이 가로 띠가 되니 **들보가 가운데만 있고 양끝이 흐려진 모양**이 됐다. 1·2차가 반려된
것과 같은 종류다. 액자 모서리를 CSS 로 흉내 내면 또 얼룩이 된다.

> **폴백은 「자리를 지킨다」가 전부이고 「그림인 척」을 하지 않는다.**
> 시안에서 자리표를 끄면 그 상태가 보인다. 기둥 둘과 땅 하나, 그리고 CSS 가 끝까지 책임지는
> 장면과 입자. 조용하고 비어 있지 않다.

## 9. CSS 가 끝까지 책임지는 겹 (**최종본이다**)

시안에서 자리표를 꺼도 남는 것들이고, 판이 전부 들어와도 이대로 간다.

### 9-1. 장면

| | 풀숲 | 탄광 |
|---|---|---|
| 빛 | 왼쪽 위에서 비스듬히 내려오는 빛기둥 셋(101·97·104deg). **폭을 px 로 고정하고 높이만 100%** 라 사이드바가 넓어져도 기둥이 굵어지지 않는다 | 오른쪽 위 램프 광추 하나. 경계가 전부 부드럽다 |
| 공기 | 산광 한 겹 · 안개 한 겹 | 층리 없음. 어둠과 램프뿐 |
| 비네트 | `radial-gradient(ellipse 128% 72% at 50% 46%, transparent 34%, rgba(0,0,0,.30))` | 같은 꼴 |
| 움직임 | 빛기둥 흐름 **31s** · 수관 그늘 **43s** | 램프 광륜 맥동 **4.3s** · 석영 반짝임 **17.3s** |

**탄광의 「불이 흔들리고 주변 돌이 따뜻해진다」는 판 없이도 돈다.** 램프 본체는 2번 판에
그려져 있지만, 그 빛이 번지는 범위와 맥동은 장면(CSS)이 낸다. 불꽃 판(6번)의 3.7초와
광륜의 4.3초가 어긋나서 **합성 주기가 약 26초**다.

### 9-2. 입자 여덟

**2차의 4px 하드 엣지 큐브를 버리고 원형 광점으로 바꿨다.**

```css
width:var(--s,3px);height:var(--s,3px);border-radius:50%;
background:radial-gradient(circle at 50% 50%,#fbffe8 0 26%,#dcff92 54%,rgba(170,214,78,0) 100%);
box-shadow:0 0 8px 2px rgba(206,255,126,.34)
```

풀숲은 반딧불 여섯(2~4px, 11.1~19.7s)과 홀씨 둘(31.7s · 41.3s).
탄광은 불티 다섯(9.3~15.9s)과 먼지 셋(21.7~34.9s, 내려온다).

### 9-3. `.th-orbit` 은 안 쓴다

껍데기가 링 안에 그 자리를 주고 있고(`html.js` 293행) 켜는 것도 한 줄이다. **안 쓴다.**
링은 세션 사용률을 읽는 **판정 요소**이고, 그 위를 도는 점은 판정을 읽는 눈을 끈다.
테마가 바꿀 수 있는 것은 판정 주변이지 판정 자체가 아니다. 램프 광륜의 맥동은
`.th-scene > i` 가 이미 내고 있고, 그쪽은 글자가 없는 면이다.
