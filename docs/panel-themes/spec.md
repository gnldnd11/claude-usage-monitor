# 패널 테마 규격

> 상점에서 파는 **패널 모습**. 여덟이 있고 하나는 공짜(= 지금 모습)다.
> 시안: `scratchpad/themes.html`(세션 산출물). 정답지: `ref-user-themes.png`(사용자 제공).
> 증거: `thumbs-110.png`(썸네일 줄) · `burn-94.png`(한계가 가까울 때).
> 이 문서의 수치는 전부 **사이드바 250px 에서 렌더해 잰 값**이다. 다시 재지 마라.
>
> **2026-11-26 설계. 이 문서는 코드를 고치지 않았다.**

## 0. 판정선 하나

**110px 썸네일에서 「아 탄광」·「아 우주」가 1초에 와야 한다.**

색만 바꾼 판은 거기서 전부 똑같이 보인다. 1차 시안이 색 토큰 아홉만 바꾼 판이었고 반려됐다.
원인은 측정됐다. **장면을 `.card` 에만 깔았는데 `.inner` 가 카드 폭의 88퍼센트를 불투명하게 덮는다.**
테마가 칠할 수 있던 것이 14px 띠와 머리글뿐이었다. **장면은 `.inner` 뒤로 내려야 한다.**

그래서 테마는 색이 아니라 **장면**이고, 불변은 글자와 숫자의 자리·크기·굵기뿐이다.

## 이 문서와 `themes/README.md` 의 관계

같은 날 다른 작업자가 `themes/` 구현을 시작했고 **계약은 그쪽이 정본**이다.
축이 같고(`frame` · `floor` · `badge` · `motes` + `accent`) 표기만 다르다.

| 이 문서 | `themes/` 계약 |
|---|---|
| `.frame` 틀 | `layers:['frame']` + `art.frame` |
| `.floorart` 바닥 풍경 | `layers:['floor']` + `art.floor` |
| `.accbox` 마스코트 악세 | `layers:['badge']` + `art.badge` |
| `.fx` 입자 | `layers:['motes']`, CSS |
| `body.th-<id>` | `body[data-theme="<id>"]` |

**이 문서가 그쪽에 없는 것만 보탠다.** 안전영역 좌표(5절) · 바닥 풍경 밝기 상한(5-2) ·
실측 대비표(6절) · 겹침 z-index(4절) · 여덟 팔레트 값(8절) · 테마가 켜지면 깨지는 것 둘(10절).
**값이 어긋나면 `themes/README.md` 가 이긴다.**

## 1. 편집기 테마 상속: 안 A (테마가 자기 바탕을 가진다)

테마는 `--vscode-*` 를 따르지 않고 자기 바탕색을 가진다. **사용자 결정(2026-11-26).**

| 근거 | |
|---|---|
| 대비를 증명할 수 있는 쪽이 A 다 | B(편집기 색 위에 장식)는 바탕이 사용자 편집기 테마라 **수천 가지**이고, 대비를 계산할 대상 자체가 없다. A 는 바탕이 하나로 고정되므로 **테마마다 표 하나를 증명하고 끝낸다**(6절) |
| B 는 요청받은 것을 못 만든다 | 「우주 느낌」은 깊은 남색에 별이고 「매트릭스 느낌」은 검정에 녹색이다. **컨셉이 바탕색 그 자체**인데 바탕을 못 건드리면 컨셉이 안 선다 |
| 장면을 그리려면 바탕이 내 것이어야 한다 | 성운·지층·주사선은 바탕 위에 겹치는 것이 아니라 바탕 자체다 |
| C(테마마다 밝은 판·어두운 판 둘)를 안 쓰는 이유 | 상품 하나에 두 판을 달면 만드는 양이 두 배다. **따로 파는 상품으로 두면 같은 작업량이 재고 두 개**가 된다 |

### 1-1. 안 산 사람의 기본값은 바뀌지 않는다

**테마는 전부 「덮어쓰기」이고, 덮지 않는 상태가 기본값으로 반드시 남아 있어야 한다.**

```
아무것도 안 산 사람   body 에 테마 클래스가 없다 -> styles.js 의 지금 팔레트 그대로,
                     body.vscode-light / body.vscode-high-contrast 분기도 그대로
산 사람              body[data-theme="<id>"] 가 붙고 그 블록이 토큰을 덮는다
```

### 1-2. 이음매

A 로 가면 편집기와 패널 사이에 이음매가 생긴다. **그 이음매는 이미 출시돼 있다.**
`styles.js` 의 `body{background:transparent}` 때문에 `.wrap` 의 10px 여백으로 편집기 사이드바
색이 비치고, 카드(`#232326`)와 Dark Modern 사이드바(`#181818`)는 지금도 다른 색이다.

테마는 `--shell` 을 채워 **webview 바닥까지 칠한다**. 그러면 이음매가 떠 있는 판 둘레의 테가
아니라 **뷰 헤더 밑의 가로선 하나**로 줄어든다. 줄이는 방법은 이것뿐이고, 감수할 만하다.

### 1-3. 여덟이 전부 어두운 이유

밝은 테마는 **판정색이 안 선다**.

```
stuck 호박 #f5a623 (상대휘도 .468) 이 4.5:1 을 넘으려면 바탕 휘도가 .1227 이하여야 한다.
출시된 라이트 팔레트도 이미 미달이고(--track #e4e4e7 에서 1.60:1) 그건 기존 결함이다.
```

밝은 테마를 팔려면 **판정색 넷에 밝은 면용 짝**이 먼저 있어야 한다. 저장소에 이미 쓰는 값이
있으므로(`#b32a2e` `#8a5a00` `#1f7a49`) 새 색은 0이지만, **그건 기본 팔레트를 고치는 별개 과업**이다.

## 3. 테마가 채우는 것

### 3-1. 토큰 아홉

| 토큰 | 무엇 | 비고 |
|---|---|---|
| `--shell` | webview 바닥 | 이음매를 한 줄로 만든다(1-2) |
| `--card` | 카드 바닥 | 장면이 깔리는 면 |
| `--inner` | 판 바닥 | 테마에서는 `transparent`. 장면이 비친다 |
| `--track` | 막대 홈 · 링 홈 | 테마에서는 보통 `rgba(0,0,0,.52)` |
| `--line` | 테두리 | `--border` 와 `--iborder` 둘에 같은 값 |
| `--text` | 글자 | |
| `--muted` | 딸림 글자 | `#cucInkFlood` 의 flood-color 이기도 하다 |
| `--accent` | 유일한 강조 | 막대 채움 · 링 호 · 글리프 · **켜진 탭 칩** · 포커스 링 |
| `--accent2` | 막대 채움의 끝 | 지금 하드코딩된 `#f0a882` 자리 |

### 3-2. 장면 레이어 (칸 수 제한 없음)

| 이름 | 어디 | 무엇 |
|---|---|---|
| `--scene` | `.card > .scene` 의 `background` | 바탕 · 결 · 빛 웅덩이 · 비네트 |
| `.fx` | `.card > .fx` | 입자와 움직임 |
| `.frame` | `.wrap > .frame` | 틀 (5-1) |
| `.floorart` | `.card > .floorart` | 바닥 풍경 (5-2) |
| `.accbox` | `.mascot-wrap > .accbox` | 마스코트 악세 (5-3) |
| `--bartrack` / `--barfill` | `.mbar` / `.mfill` | 테마가 막대를 다시 칠한다 |
| `--tabsbg` / `--tabon` / `--tabonink` | `.tabs` / `.tab.active` | 켜진 탭이 강조색 칩이 된다 |
| `--statsbg` / `--tilebg` | `.stats` / `.stat` | 테마에서는 둘 다 `transparent`. 바닥 풍경이 비친다 |
| `.rtrack` 의 `stroke-dasharray` | 링 홈 | 궤도(우주) · 눈금(주식) · 블록(개발자) |

**`--scene` 은 `background` 단축으로 쓴다. `background-image` 가 아니다.**
`background-image` 는 `left 296px/100% 152px` 같은 position/size 를 못 받고, 커스텀 프로퍼티는
레이어 하나가 깨지면 **값 전체가 무효**가 되어 장면이 통째로 사라진다. 실제로 그렇게 됐다.

**`background` 레이어는 먼저 쓴 것이 위다.** 보드를 먼저 쓰고 LED 를 뒤에 써서 LED 가 가려진
적이 있다. 그리고 `no-repeat` 을 빼면 x 축으로 반복돼 2px 줄이 패널 전면을 덮는다.

## 4. 겹침 순서

`.card` 에 `isolation:isolate` 를 걸어 이 스택을 가둔다.

| z-index | 무엇 | 종류 |
|---|---|---|
| 0 | `.card` 의 `background-color` | 토큰 |
| **1** | `.scene` (`inset:0`, `border-radius:15px`, `overflow:hidden`) | CSS |
| **2** | `.floorart` 바닥 풍경 | CSS (PNG 로 교체 가능) |
| **3** | `.fx` 입자 (`pointer-events:none`) | CSS |
| **4** | `.head` · `.tabs` · `.inner` = 읽는 것 전부 | 불변 |
| **5** | `.frame` 틀 (`pointer-events:none`) | CSS (PNG 로 교체 가능) |
| **6** | `.accbox` 마스코트 악세 | CSS (PNG 로 교체 가능) |

**틀(5)과 악세(6)가 글자보다 위인 이유.** 레퍼런스에서 덩굴과 갱목이 카드 모서리를 덮는다.
글자를 가리지 않는 것은 z 가 아니라 **안전영역**이 보장한다(5-1).

**바닥 풍경(2)이 글자보다 아래인 이유.** 레퍼런스에서도 광차와 보물상자가 통계 줄 뒤에 있고
숫자는 다 읽힌다. 그 관계를 숫자로 적은 것이 5-2 의 밝기 상한이다.

## 5. 세 상자

**지금은 CSS 가 정본이고, PNG 가 들어오면 그 상자를 덮는다.**
PNG 가 하나도 없어도 화면은 완성이다. PNG 는 품질을 올리는 선택지이지 전제가 아니다.

### 5-1. 틀 `.frame`

```
상자   .wrap 기준 inset:0        250 x 597.5      (PNG 로 낼 때 2x 는 500 x 1195)
```

**그림이 올 수 있는 곳은 네 조각뿐이고 나머지는 전부 투명이다.**

```
A 좌 기둥   x   0..24   y 0..597.5     머리 게가 wrap x25 부터다
B 우 기둥   x 227..250  y 0..597.5     접기 버튼이 x201..225 다
C 좌상      x   0..62   y 0..40        덩굴·아치가 쏟아져 들어온다
D 우상      x 188..250  y 0..40        매달린 램프. 접기 버튼(y46..70) 위로 끝난다
```

구현은 마스크로 강제한다. 네 레이어의 합집합이다(시안에서 검증한 그대로).

```css
.frame{ -webkit-mask:linear-gradient(#000,#000) left  top/24px 100% no-repeat,
                     linear-gradient(#000,#000) right top/23px 100% no-repeat,
                     linear-gradient(#000,#000) left  top/62px 40px  no-repeat,
                     linear-gradient(#000,#000) right top/62px 40px  no-repeat;
        mask:/* 같은 넷 */; pointer-events:none; }
```

**C 와 D 를 y 0..40 으로 끊은 이유는 측정이다.** 처음에 y 0..120 으로 뒀더니 머리 게
(wrap x25..69, y41..75)를 덮었다. 접기 버튼도 D 안에 있어서(x201..225, y46..70) y40 에서
끊어야 버튼이 산다. 버튼을 가리면 접기가 안 눌린다.

**틀 예산을 벌려고 `.card` 의 `padding-top` 을 14 -> 30 으로 키웠다(패널 +16px).**
레퍼런스는 "CLAUDE USAGE" 한 줄을 패널 **안**에 넣어 상단 여유를 55px 벌었는데, 실제 제품에서
그 줄은 VS Code 뷰 헤더라 **패널 밖**이다. 14px 로는 덩굴도 암반 아치도 못 그린다.

### 5-2. 바닥 풍경 `.floorart`

```
상자   .card 기준 left:0 right:0 bottom:0    230 x 156     (2x 는 460 x 312)
       border-radius:0 0 15px 15px; overflow:hidden
```

**밝기 상한.** 글자가 그 위에 오므로 수로 정한다.

```
통계 줄 띠 = floorart 내부 좌표로 y 76..127   (card 기준 y 497.5..548.5)
   그 사각형 안 픽셀의 98분위 상대휘도  <=  0.0520
```

0.0520 은 계산해서 나온 값이다. 가장 어두운 딸림 글자(`#92b0c9`, 휘도 .4089)가 4.5:1 을 넘으려면
바탕 휘도가 `(.4089+.05)/4.5 - .05 = .0520` 이하여야 한다. 테마마다 딸림 글자가 다르므로
테마별로 다시 푼다. 실측 방법은 6-2 에 있다.

**밝은 오브젝트는 그 띠를 피해 위나 아래로 보낸다.** 레퍼런스도 그렇게 돼 있다: 접시 안테나는
통계 줄보다 **위**(마스코트 옆), 보물상자는 **아래**다. 이 규칙을 어겨서 네 번 미달이 났다.

### 5-3. 마스코트 악세 `.accbox`

```
상자   .mascot-wrap 기준 left:0 top:0       88 x 74     (2x 는 176 x 148)
기준점 idle 의 잉크는 상자 안에서 y 35.5 부터 시작한다
       (styles.js 의 .mascot-wrap[data-state="idle"] .mwarn{top:20.5px} + 15)
```

**`crab.png` 와 `mascot-*.png` 를 건드리지 않는다.** 악세는 그 위에 겹치는 별개 층이다.

> **악세는 `idle` 한 장에만 건다.** 그림마다 머리 위치가 달라서 장수가 폭발한다.
> `styles.js` 의 `.mwarn` 오프셋 여덟(20.5 / -0.4 / -3 / 12.8 / 25.6 / 7.2 / -15 / -8.4)이
> 그 증거다. 테마 7 x 그림 8 = 56장은 안 된다. `shop.js` 가 `idle` 을 "the most looked-at
> thing in this product" 라고 적어 두었고, 패널이 가장 오래 머무는 장면이다.
> 나머지 일곱 상태에서는 악세를 끈다.

### 6-2. 장면 위 (실측)

토큰 대비만으로는 모자라다. 장면이 깔리면 바탕이 값 하나가 아니라 **범위**다.
**렌더를 재야 한다.** 상수 파일을 세는 것으로는 못 잡는다.

```
1. 글자를 숨기고 장면만 남긴 페이지를 띄운다
   (.plain: .head/.tabs/.body/.stats 를 visibility:hidden. 바닥 풍경은 남긴다)
2. 스크린샷 -> magick 으로 띠 넷을 크롭 -> 픽셀 RGB 덤프
3. 각 띠의 2% / 중앙 / 98% 분위 상대휘도를 구한다
4. 글자색과 2%·98% 양쪽에 대해 대비를 재고 나쁜 쪽을 쓴다
```

## 9. 상점에 서는 법

### 9-1. 모양은 「랜덤 줄」과 같다

`webview.js` 의 `renderShop` 이 그리는 마지막 줄(`.sh-rand`)과 **같은 CSS**를 쓴다. 새 규칙 0개.

```
칸          .sh-cell 64px, .sh-opts 는 repeat(auto-fit,minmax(60px,64px))
            250px 사이드바에서 두 칸씩, 여덟이면 네 줄
그림 자리   48x34 판. 그 테마의 장면 + 상단 띠(틀) + 하단 띠(바닥) + accent 막대. CSS 만
꼬리표      Free / 1K / 10K / Own  (.sh-tag 그대로)
고른 칸     .sh-cell.on 의 테 하나. 금색 테두리 없음
```

**`.sh-cell.on` 의 배경 틴트(`rgba(232,137,90,.13)`)는 쓰지 않는다.** 강조가 토큰이 되면 그
리터럴을 못 만들고, `color-mix()` 는 `engines.vscode ^1.75.0`(Chromium 102)에서 안 돈다.
테 하나로 충분하다. `styles.js` 주석이 이미 "The word in the cell says it too" 라고 적어 두었다.

### 9-2. 저장과 값

접두는 `theme` 이고, `shop.js` 머리말이 이미 답을 적어 두었다.
"A shop that one day sells something that is not [a drawing of the crab] is a second prefix,
not a migration."

**값은 `themes/registry.js` 가 세는 방식을 따른다.** 그쪽이 더 낫다.

```
그림 수(frame + floor + badge)로 칸이 정해진다.  motes 와 accent 는 세지 않는다
   0장   free     기본 테마, 그리고 그것만
   1장   1K
   2~3장 10K
```

**처음 제안한 「전부 1K 고정」은 철회한다.** 근거가 "테마에 프레임이 없으니 맨 아래 칸"이었는데,
테마에도 세어야 할 그림이 있다. **그림 수는 측정이고 고정값은 의견이다.**

이 규격의 일곱은 전부 CSS 로 완성돼 있으므로 **그림 수 0 = free** 로 둘 수도 있고, PNG 로
품질을 올리면 그때 칸이 올라간다. **CSS 판과 PNG 판의 값을 다르게 매길지는 결정 사항이다.**

## 10. 테마가 켜졌을 때 깨지는 것 둘 (구현자가 반드시 고칠 것)

**둘 다 「편집기가 어두운가」를 묻는 선택자이고, 안 A 에서는 그 질문이 틀린 질문이 된다.**

### 10-1. 마스코트 잉크 테두리

```css
/* 지금 (styles.js) */
body:not(.vscode-light) .ink-lift{ filter:url(#cucInkEdge); }
```

밝은 편집기에서 어두운 테마를 켜면 `body.vscode-light` 가 그대로 붙어 있으므로
**잉크 테두리가 안 걸린다.** `mascot-coding` 의 near-black 키 입력이 어두운 바탕에서
1.1:1 이 된다. 이건 테마 기능이 새로 만드는 결함이다.

고치는 법: 묻는 것을 **편집기가 아니라 면**으로 바꾼다.

```css
body.ink-dark .ink-lift{ filter:url(#cucInkEdge); }
```

`ink-dark` 는 기본 다크·하이컨트라스트와 **모든 어두운 테마**가 함께 붙인다.
`#cucInkFlood` 의 flood-color 가 `var(--muted)` 이므로 색은 테마를 따라 저절로 간다.

### 10-2. 방 바탕

```css
.ws-room{ background:#0c0c0d; }
body.vscode-light .ws-room{ background:#ececef; }
```

같은 문제다. 같은 방식(`body.ink-dark`)으로 고친다.
