## 0. 열고 3초

**갈림길.** 그림 둘이 **같은 높이로 같은 바닥에** 나란히 서 있다. 왼쪽은 초록 펠트에 카드와 칩,
오른쪽은 빨간 차양과 궤짝. 글자를 읽기 전에 어디가 어디인지 안다.
아래에 `Games` `Shop` 두 낱말뿐이다.
**이 화면에는 숫자가 하나도 없다.** 잔액은 바로 위 머리글이 이미 들고 있다.
**그림 양옆이 비어 있다.** 1.32.1 에서는 그림 둘이 칸을 좌우 여백 0 으로 채웠고
사용자가 「너무 크고 꽉 찬다」고 했다. 2-2 가 그 자리다.

**Shop.** 네 장면이 두 줄로 서 있고 장면마다 칸 둘이다. **엠버 표식이 다섯 개 보인다.**
네 개는 칸을 두른 테두리(「지금 이게 들어 있다」), 하나는 값 밑에 누운 막대(「`Buy` 가 이걸 산다」).
맨 아래에 그 하나가 그림·이름·값으로 다시 서 있고, 그 밑이 `Buy` 다.
**막대 친 칸과 아래 판이 같은 그림이다.** 그게 이 화면이 말하는 한 가지다.

## 1. 이름은 Shop 이다. 「마켓」을 쓰지 않는다

`games/market/meta.js:55` 의 `name` 이 **`Coin Market`** 이고 그 화면의 제목도 같다.
시세를 사고파는 게임이 이미 「마켓」이라는 이름으로 목록에 서 있다.

사용자가 말한 「마켓」은 **사는 곳**이라는 뜻이고, 그 자리의 이름은 **Shop** 이다.
마켓이 둘이 되면 목록에서 `Coin Market` 과 문 이름이 같은 낱말을 쓰게 되고,
**그 둘은 돈의 방향이 반대다**(시장은 되팔 수 있고 상점은 못 되판다, 7절).
이름이 같으면 그 차이를 사람이 기억해야 한다.

한국어로 말할 때도 **상점**이라고 쓴다. 화면 글자는 영어(`Shop`)다. 제품이 영어다.

#### 왜 상자를 2:1 로 고정하나 (1.32.2 에서 고친 것)

**1.32.1 까지는 `.cr-art img{width:100%;max-height:120px;height:auto}` 였다.**
그 한 줄이 사용자가 말한 「너무 크고 꽉 찬다」의 원인 전부다. 셋이 한꺼번에 일어났다.

| 증상 | 1.32.1 실측(351) | 왜 |
|---|---|---|
| 그림이 좌우 여백 0 으로 칸을 채운다 | 그림 132.5 = 칸 132.5. 줄 273 중 **흰자리가 가운데 8px 뿐**(2.9%) | `width:100%` |
| 두 그림 높이가 21.5 다르다 | Games 86.39 · Shop **107.88** | `height:auto` 라 **높이를 그림의 비가 정했다**(1.534 대 1.228). 바닥만 맞으니 Shop 혼자 21.5 솟았다 |
| 넓은 사이드바에서 천장이 안 듣는다 | 420 에서 그림 **167 x 108.88**, `.card` **300** | `max-height:120` 은 높이의 천장인데 **폭을 안 막는다.** Games 는 비가 1.534 라 높이 120 에 닿으려면 폭 184 가 필요해서, 그 전까지 폭을 따라 계속 커졌다. **옛 표의 420 줄(287.88 / 132.5)은 틀린 수치였다** |

**고친 규칙은 한 줄이다. 상자가 칸을 대신 받고, 그림은 그 상자 안에 들어간다.**

```
상자 = 칸의 폭 x 그 절반의 높이 (천장 72)
그림 = 상자 안에 contain, 바닥 정렬
```

**2:1 이 규칙의 전부다.** 두 그림이 **둘 다 2:1 보다 좁으므로**(1.534 · 1.228)
상자 안에서 **언제나 높이가 먼저 걸린다.** 그래서

1. **두 그림이 항상 같은 높이로 같은 바닥에 선다.** 어느 사이드바 폭에서도 그렇다. 쌍으로 읽힌다
2. **각자 자기 그림에 필요한 폭만 쓴다.** 남는 폭이 곧 여백이다. 만드는 사람이 여백을 따로 안 정한다
3. **천장이 진짜로 듣는다.** 폭이 아무리 넓어져도 상자가 72 에서 멈춘다

**실측 (위 CSS 를 실제로 렌더한 값. `ink:` 프로브는 상자가 아니라 그려진 그림을 잰다):**

| 사이드바 | `.card` | `.cr-pair` | 상자(`.cr-art`) | Games 그림 | Shop 그림 | 한 줄의 여백 |
|---|---|---|---|---|---|---|
| 250 | **223** | 172 x 72 | 82 x 41 | 62.88 x **41** | 50.35 x **41** | 58.8 / 172 (34%) |
| **351 (집 기본)** | **248.25** | 273 x 97.25 | 132.5 x 66.25 | **101.61 x 66.25** | **81.36 x 66.25** | 90 / 273 (33%) |
| 420 | **254** | 342 x 103 | 167 x 72 | 110.42 x **72** | 88.43 x **72** | 143.2 / 342 (42%) |

재는 명령은 9-2 에 있다. **여백 칸은 줄 폭에서 두 그림의 폭을 뺀 값**이고,
1.32.1 에서 같은 자리가 351 기준 **8 / 273 (2.9%)** 이었다.

**스크롤은 안 생긴다.** 248 은 이 패널에서 **가장 짧은 화면**이고(Usage 409 · 게임 목록 374 ·
블랙잭 421.59 · Agents 596.63) 고치기 전보다 **39.63 더 짧아졌다.**

**420 에서 그림이 더 안 커지는 것은 의도다.** 상자가 72 에서 멈춘다. 멈추기 시작하는 지점은
칸 폭 144, 즉 **사이드바 374** 다. 집 기본 351 에서는 천장이 아직 안 걸리므로
사이드바를 조금 넓히면 그림도 조금 커진다.

**더 크게/작게 하려면 고치는 값이 하나다.** `aspect-ratio` 를 2/1 에서 1.8/1 로 내리면
351 에서 상자가 73.6 이 되고(Games 112.9 · Shop 90.4, 여백 69.7 = 26%), 2.2/1 로 올리면 60.2 가 된다.
**단, 어느 쪽으로 가든 두 그림의 비(최대 1.534)보다 커야 위 세 성질이 유지된다.**
그 조건은 `test/panel-css.test.js` 2c 가 PNG 머리에서 비를 다시 읽어 지킨다.

#### 재지 않은 것 하나 (하자 아님. 사용자가 판정할 것)

**두 그림의 폭이 다르므로 줄 전체의 잉크가 왼쪽으로 5.1px 쏠린다.** 351 기준
Games 잉크 왼끝이 패널 안쪽 벽에서 29.4, Shop 잉크 오른끝이 39.6 이다(273 의 1.9%).
문 둘은 폭이 같고 각자 안에서 그림이 가운데 있으므로 **구조는 맞다.**
없애려면 높이가 아니라 폭을 맞춰야 하고, 그러면 1.32.1 의 높이 21.5 차이가 돌아온다.

### 2-3. 자르지 않는다. 통째로 줄인다

**두 그림 다 `object-fit:contain` 이고 한 화소도 안 버린다.** 근거 둘이다.

1. **어디를 잘라도 그 그림이 말하던 것 하나가 없어진다.** 상점 그림은 위가 차양, 가운데가
   수레 간판과 등불, 아래가 궤짝과 물약이다. 위를 자르면 차양이 없어져 가게로 안 읽히고,
   아래를 자르면 파는 물건이 없어진다. 게임 그림은 반대로 위쪽(게의 머리와 나비넥타이)이
   주인공이고 아래가 펠트다.
2. **상자 규칙이다.** 사용자가 그림을 다시 그린다. `header-fold-spec.md` 5절이
   「새 그림이 들어와도 안 깨지는 상자」를 하자 D 로 적어 두었고, 같은 규칙을 여기 건다.
   **상자는 열이 정하고**(`flex:1 1 0` + `aspect-ratio:2/1`), **그림은 상자 안에 들어간다.**
   1.32.1 처럼 그림의 비가 높이를 정하면 상자가 그림마다 다른 높이가 되어 그 규칙이 반만 선다.
   지금은 어떤 비의 그림이 와도 줄 높이가 안 움직인다.

### 2-4. `image-rendering:pixelated` 를 **걸지 않는다**

타일(`games/tiles.js`)과 마스코트에는 걸려 있지만 이 두 그림에는 걸면 안 된다. **재서 하는 말이다.**

| | 색 차이 12 이내를 같은 열로 본 **열 경계 실측** |
|---|---|
| `hero-shop.png` 646x526 | 경계 사이 간격이 1px 인 것이 **417 / 645** |
| `hero-games.png` 592x386 | **486 / 591** |
| `mascot-coding.png` 353x223 | 34 / 61 (나머지는 9~26px 덩어리) |

**앞의 두 장은 화소 격자가 없다.** 명암과 디더가 들어간 그림이라 열마다 색이 조금씩 다르다.
여기에 nearest-neighbour 를 걸고 646 -> 81.36(**0.126배**)로 줄이면 1px 윤곽선은
여덟 번에 한 번만 살아남는다. **검은 윤곽이 군데군데 없어진다.**
반대로 마스코트 두 장은 덩어리가 있어 지금 규칙(`pixelated`)대로 둔다.

**이 결론은 1.32.2 에서 그림이 작아지면서 더 세졌다.** 0.205배일 때도 안 걸었던 것을
0.126배가 된 지금 걸 이유는 없다. 배율만 갱신하고 판정은 그대로다.

### 2-5. 문에 숫자를 달지 않는다

**그려 보고 버렸다.** 시장의 열린 손익 합(`+1,240`)을 Games 문 오른쪽에 다는 안을 렌더까지
했고(스크래치 `cross-a-120.png`), 뺀 이유는 둘이다.

1. **공유 파일이 게임 이름을 알게 된다.** `CUC.rowFig(id, …)` 는 `#fig-<id>` 한 곳에 쓴다.
   문까지 끌어올리려면 `html.js` 가 `data-fig="market"` 을 들고 있어야 하고,
   그 순간 **「공유 파일에 게임 이름이 한 번도 안 나온다」**(CLAUDE.md, `games/README.md` 1절)가 깨진다.
   숫자 하나 때문에 깰 값이 아니다.
2. 그 숫자는 한 걸음 안(목록의 시장 행)에 이미 있고, `game-panels.md` 7-4 가
   「숫자가 한 행에만 있어야 그게 보인다」고 적은 자리가 거기다.

### 2-6. 안 2 (반려하지 않음, 2순위). 세로로 쌓기

문 둘을 세로로 쌓고 그림 상자를 120px 로 고정한 안. **실측 `.card` 459**(250 에서도 459).
그림이 커지는 것이 유일한 이득이고(Games 184x120 · Shop 147x120), 값은 **171px** 이다.
갈림길은 지나가는 화면이라 그 값을 치를 이유를 못 찾았다.
스크래치에 렌더가 있다(`cross-a-120.png`).

**1.32.2 뒤로는 이 안의 값이 더 비싸졌다.** 가로 한 줄이 248.25 가 됐으므로 차이가 171 이 아니라
**210.75** 다. 그리고 사용자가 지금 말한 것은 그림이 크다는 쪽이라 방향이 반대다.
「그림을 더 크게」가 나오면 **이 안으로 가기 전에 2-2 의 `aspect-ratio` 한 값**을 먼저 내린다.

## 3. Shop 안

> **2026-11-19 에 다시 썼다.** 좌석 일곱을 파는 옛 3절은 반려됐고, 지금 서 있는 화면은 아래다.
> 바뀐 계기는 사용자 지적 한 줄이다. 「클릭하면 테두리 표기되고 buy가 활성화되는게 맞지않냐.」

### 3-1. 무엇을 파나

> **상점은 네 장면에 들어갈 게 그림을 판다.** 장면마다 공짜 기본이 하나 있고, 가진 것 중에서 고른다.

목록과 값은 머리말 표와 `shop.js`(`ITEMS`·`SLOTS`·`PRICES`)에 있다. 지금 값이 붙은 것은
`mascot-float` **하나**(1,000)이고, 나머지 다섯 장은 설치하면 바로 쓴다.

**선반은 네 장면 x 같은 칸 수의 직사각형이다.** 칸이 모자라는 장면은 `Soon` 으로 채운다.
그래야 그림이 하나뿐인 장면이 「깨진 줄」로 안 읽히고, 다음 그림이 들어갈 자리가 그대로 보인다.

### 3-2. 칸 세 종류와 **표식 두 개**

| 칸 | 무엇을 보여주나 | 누를 수 있나 |
|---|---|---|
| 가진 그림 | 그림 + `free` 또는 `own`, 지금 끼워져 있으면 **테두리** | 그 장면에 가진 그림이 **둘 이상일 때만** |
| 안 산 그림 | 그림 + 값(`1K`), 지금 조준돼 있으면 **아래 막대** | **언제나.** 누르면 아래 판과 `Buy` 가 이것을 가리킨다 |
| 빈 칸 | **그림 없음** + `Soon` | 아니다. 탭 순서에도 없다 |

#### 테두리 두 뜻을 이렇게 가른다

**같은 엠버 하나, 모양 둘.** 이 화면의 액센트는 엠버 하나뿐이고 여기서 색을 늘리지 않는다.

```
테두리(ring)   칸을 둘러싼다.  「지금 이 장면에 들어 있다」      = 사실
막대(bar)      바닥에 눕는다.  「Buy 를 누르면 이 값을 낸다」    = 조준
```

**근거 넷.**

1. **둘은 한 칸에 절대 같이 안 온다.** 가진 것은 안 팔고 파는 것은 아직 안 끼운다.
   구별이 필요한 자리는 **둘이 나란히 서는 한 줄**(Burning: `despair` 테두리 · `float` 막대)뿐이고,
   거기서 「상자」와 「밑줄」은 안 헷갈린다. 채움 대 윤곽으로 갈랐다면 그 줄에서 틀렸을 것이다.
2. **막대는 값 바로 밑에 눕는다.** 밑줄 친 대상이 값이고, 그 값을 내는 버튼이 바로 아래 있다.
   테두리는 칸 전체를 두르므로 「칸의 상태」로 읽히고, 막대는 「이 값」을 가리킨다.
3. **고대비 테마에서도 산다.** `--card` 와 `--inner` 가 둘 다 `#000` 이라
   판돈 칩처럼 **판을 들어 올리는 방식**(`background:var(--card)` + 그림자)은 거기서 아무 말도 못 한다.
   막대는 칠이라 산다.
4. **색만으로 말하지 않는다.** 조준된 칸의 짝인 아래 판이 **같은 그림·같은 이름·같은 값**을 글자로 쓴다.
   막대가 안 보여도 무엇이 골라졌는지는 글자가 답한다.

```css
.sh-cell.on{background:rgba(232,137,90,.13);box-shadow:inset 0 0 0 1.5px #e8895a;}   /* 끼움 */
.sh-cell.aim::after{content:'';position:absolute;left:8px;right:8px;bottom:0;height:2px;
  border-radius:2px 2px 0 0;background:#e8895a;}                                      /* 조준 */
```

**반려한 안 둘.**

| 안 | 왜 반려 |
|---|---|
| 조준을 다른 색으로 | 액센트가 둘이 된다. 상태색(ok·fail)은 판정에만 쓴다 |
| 판돈 칩처럼 판을 들어 올린다(`.bj-stakes button.on`) | 관계는 똑같지만(칩이 Deal 의 대상, 칸이 Buy 의 대상) 칩은 `--inner` 쟁반 위에서 `--card` 로 뜬다. 칸은 `--card` 위에 있어서 들어 올리면 배경에 묻고, 고대비에서는 아예 안 보인다 |

### 3-3. 처음 열었을 때 · 누를 때 · 하나뿐일 때 · 다 샀을 때

| 언제 | 무엇이 보이나 |
|---|---|
| **열었을 때** | **선반의 첫 번째 팔 것이 이미 조준돼 있다.** 그 칸에 막대, 아래 판에 같은 그림, `Buy` 활성 |
| **다른 값을 누르면** | 막대가 그 칸으로 옮겨 가고, 아래 판이 그 그림으로 바뀌고, 읽어 준다(`Buy: <이름>, <값> credits.`) |
| **이미 조준된 것을 누르면** | 선반은 안 움직인다. **아래 판이 0.18초 반응한다**(`.sh-try.ping`) |
| **다 샀을 때** | 조준이 없어지고 **판과 `Buy` 가 같이 사라진다**(`shTry.hidden`/`shCtl.hidden`). 규칙 그대로 |

**왜 (가) 미리 골라 놓나.** (나) 아무것도 안 골라진 채로 열면 `Buy` 가 꺼져 있고,
**「칸을 누르면 된다」를 아무도 안 알려 준다.** 지금 화면의 문제는 선택이 없다는 것이 아니라
**아래 판과 칸이 서로를 안 가리킨다**는 것이고, 미리 고르면 그 관계가 열자마자 보인다.
걸음 수도 안 는다(열자마자 `Buy` 한 번, 지금과 같다).

**왜 이미 조준된 것을 눌러도 반응하나.** 지금 파는 것이 하나뿐이라
**그 하나를 누르는 것이 이 화면에서 가능한 유일한 누름**이다. 거기서 아무 일도 안 일어나면
사용자가 지적한 바로 그 상태로 돌아간다. 반응은 **아래 판**이 한다. 누른 값이 간 자리가 거기다.
`prefers-reduced-motion` 에서는 안 움직인다. 이 화면의 유일한 모션이고 장식이 아니라 시선 유도다.

**조준은 저장하지 않는다.** 돈도 취향도 아니고 **커서**다. 창 안의 `sh.aim` 하나이고,
매 repaint 마다 선반에서 다시 푼다(`shopOnSale`): 조준한 것이 다른 창에서 팔리면
**치우는 코드 없이** 다음 것으로 넘어간다. 저장하면 「이미 산 것을 가리키는 저장값」이 생긴다.
끼운 것(`mascotSlotsV1`)은 취향이라 저장하는 것이고, 이것은 다르다.

### 3-4. 접근성. 한 줄에 두 종류가 섞인다

**누를 수 있는 칸은 전부 `<button>` + `aria-pressed` 다. 라디오를 쓰지 않는다.**

| 칸 | `aria-pressed` 의 뜻 | 이름표(`aria-label`) |
|---|---|---|
| 가진 그림(고를 수 있는 장면) | 이 장면에 끼워져 있다 | `Busy crab, yours` / `Laptop crab, in use` |
| 안 산 그림 | `Buy` 가 이것을 가리킨다 | `Floating crab, 1,000 credits` |

**뜻은 이름표가 가른다.** 끼운 칸은 `in use`/`yours` 라고 말하고, 안 산 칸은 값을 말한다.
`aria-pressed` 는 「이 줄에서 지금 눌려 있는 것」이라는 한 가지 문법만 지고, 어느 뜻인지는 글자가 답한다.

**`role="radio"` + `aria-checked` 를 반려한 근거 셋.**

1. **묶음의 범위가 다르다.** 끼우기는 **장면 하나 안**에서 고르고(이미 `.sh-opts` 가
   `role="group"` 이다), 조준은 **선반 전체**에서 하나다. 라디오그룹 하나로 못 적는다.
2. **라디오는 화살표 키를 약속한다.** WAI-ARIA 라디오그룹은 Tab 으로 들어와 화살표로 옮긴다.
   지금 칸들은 각자 탭 정지점이고, 그 키 모델을 바꾸는 것은 이 블록의 범위가 아니다.
   **답 안 하는 라디오는 버튼보다 나쁘다**(「라디오, 2 중 1」이라고 읽어 주고 화살표가 안 듣는다).
3. **섞이는 자리가 실제로 한 줄이다.** Burning 줄에 `<span>`(despair, 끼움·고를 것 없음)과
   `<button>`(float, 값)이 같이 선다. 한 문법이면 그 줄이 일관되고, 둘이면 안 그렇다.

빈 칸과 「고를 것이 없는 장면의 그림」은 **지금처럼 `<span role="img">`** 이고 탭 순서에 없다.

### 3-5. 조작 줄은 버튼 하나다

| 상태 | `Buy` | 아래 줄(`.bj-note`) |
|---|---|---|
| 조준돼 있고 살 수 있다 | 활성 | 없음 |
| 조준돼 있고 돈이 모자라다 | 비활성 | `You need 1,000 credits.` |
| 조준돼 있고 다른 판이 묶어 뒀다 | 비활성 | `Another table is holding these credits.` |
| 살 것이 없다 | **판과 같이 사라진다** | 없음 |

**조준은 돈을 안 본다.** 못 사는 값도 누를 수 있고 막대가 붙는다.
**무엇을 가리키나는 사용자가 정하고, 눌러도 되나는 호스트가 정한다.**
판정 기준은 `CUC.free('shop')` 이지 머리글 잔액이 아니다.

**산 뒤.** 산 그림이 그 장면에 바로 들어가고(`wornSlots`), 머리글 잔액이 값만큼 준다(되팔기 없음).
산 그림은 그때부터 **고르는 칸**이 되어, 공짜 그림으로 되돌아갈 수 있다.
**환불·되팔기·구매 취소는 화면에도 기록에도 없다**(7절).

`icons.js` 에 열쇠 하나를 더한다. **이름은 `tag`**, 값표(price tag) 모양.

| | |

무엇이 무엇인지 안 갈린다.

## 4. 나가는 길

### 4-1. 깊이와 그 문

```
Usage / Agents
   │  코인(#hdCredits)
   ▼
갈림길  (머리글 없음. 화살표 없음)
   │                         │
   │ Games 문                │ Shop 문
   ▼                         ▼
게임 목록  [←] Games        Shop  [←] Shop
   │  행
   ▼
게임 화면  [←] <게임 이름>
```

| 지금 어디 | `[←]` | 코인 | Escape |
|---|---|---|---|
| 갈림길 | **없다** | `lastTab` 으로 나간다 | 코인과 같다 |
| 게임 목록 | 갈림길 | `lastTab` | `[←]` 와 같다 |
| Shop | 갈림길 | `lastTab` | `[←]` 와 같다 |
| 게임 화면 | 게임 목록 (지금 그대로) | `lastTab` | 지금 그대로 |
| 게임 안의 깊이(시장 종목) | 한 칸 위 (`up`, 지금 그대로) | `lastTab` | 지금 그대로 |

### 4-2. 조정자의 권고를 **반려한다**. 코인은 언제나 문이다

> 권고: 「게임 안에서 코인을 누르면 갈림길로 한 칸 올라간다」

**반려. 근거 셋이다.**

1. **한 화면에 뒤로가기가 둘이 된다.** `game-panels.md` 2절이 못 박은 바로 그 금지다.
   「화살표가 둘이면 누르기 전에 둘을 구별해야 하고, 그 구별은 화면이 아니라 사람이 한다.」
   시장이 한동안 그랬고 그 줄을 걷어낸 것이 1.31.0 이다.
   화살표가 이미 「한 걸음 뒤로」를 지고 있으므로 코인이 같은 일을 하면 안 된다.
2. **코인은 토글이고 토글에는 상태가 있다.** `webview.js:595` 가
   `hdc.setAttribute('aria-pressed', t === 'games' ? 'true' : 'false')` 로 「이 영역이 열려 있다」를
   말한다. 어떤 깊이에서는 한 칸 올리고 어떤 깊이에서는 닫는 버튼은 그 상태를 못 지킨다.
3. **걸음 수가 안 늘어난다.** 게임에서 Shop 까지는 어느 쪽이든 세 번이다.
   화살표로 가면 `[←] [←] Shop`, 코인으로 나갔다 들어오면 `코인 코인 Shop`.
   권고의 이득이 실제로는 0이다.

**대신 화살표가 한 칸씩 제대로 올라가는 것이 이 블록에서 새로 생기는 것이다.**
지금 게임 목록에는 화살표가 없다(나가는 길이 코인뿐이다). 갈림길이 생기면서 목록이 한 칸 안이 되므로
**목록 머리에 `.bj-back` 이 선다.**

### 4-3. 코인으로 다시 들어오면 **갈림길에서 시작한다**

`webview.js:652` 가 지금 영역을 떠날 때 `s.game = null` 로 비운다. 같은 규칙을 `door` 에도 건다.

```js
// 떠날 때: 다음에 들어오면 갈림길이다
if (t !== 'games') { s.lastTab = t; s.game = null; s.door = null; }
```

**마지막으로 연 문을 기억했다가 바로 열어 주는 안을 버렸다.** 매일 블랙잭만 하는 사람에게는
한 번 더 눌러야 하는 비용이지만, **사용자가 요구한 것이 「코인을 누르면 진입점이 두 개 나오는 것」**이다.
기억해서 건너뛰면 그 요구가 없어진다. 영리하게 굴지 않는다.

### 4-4. 보는 것을 정하는 상태

웹뷰 상태(`vscode.getState()`)에 열쇠 하나를 더한다.

```
s.tab    'usage' | 'agents' | 'games'      (지금 그대로)
s.door   null | 'games' | 'shop'           (새로. tab 이 games 일 때만 뜻이 있다)
s.game   열린 게임 id 또는 null            (지금 그대로. door === 'games' 일 때만 뜻이 있다)
```

`applyView()` 의 분기 셋:

```js
setVis('panelCross', t === 'games' && !door);
setVis('panelGames', t === 'games' && door === 'games' && !g);
setVis('panelShop',  t === 'games' && door === 'shop');
```

`body.tab-games` 는 세 화면 모두에 그대로 걸린다. **새 body 클래스를 만들지 않는다.**

`switchTab('games')` 가 `enterGames()` 를 부르는 자리에서, 갈림길이면 **첫 문에 포커스**를
`refocusIn` 으로 준다(`webview.js:644` 가 목록 첫 행에 주는 것과 같은 방식, 같은 이유).

### 4-5. Shop 은 게임이 아니다. 등록기에 넣지 않는다

`games/registry.js` 는 **게임**의 등록기다. 상점은 판도 판돈도 환수율도 없다.
등록기에 넣으려면 「목록에 안 나오는 게임」이라는 새 낱말이 필요하고,
**그 순간 `webview.js` 가 'shop' 이라는 게임 이름을 알아야 한다.** 그 불변식이 이 저장소의 설계다.

그래서 상점은 **Agents 탭과 같은 급의 영역**으로 짓는다.

| 무엇 | 어디 |
|---|---|
| 빈 껍데기 `<div class="inner shop" id="panelShop" style="display:none">` | `html.js` |
| 내용(입어 보는 자리 · 칸 · 버튼) | `webview.js` 가 그린다. 목록이 데이터(소유·값)라서다 |
| CSS | `styles.js` (Agents 탭 CSS 가 거기 있는 것과 같다. **`games/casino.js` 가 아니다**) |

## 5. 마스코트. 축이 둘이 된다

### 5-1. 배치표 (안 1, 권고)

| 단계(기존 축) | **coding** (최근 응답 있음) | **float** (조용) |
|---|---|---|
| idle | **`mascot-coding`** | **`mascot-float`** |
| working | `mascot-working` | `mascot-idle` |
| despair | `mascot-despair` | `mascot-despair` |
| stunned | `mascot-stunned` | `mascot-stunned` |

**근거 넷.**

1. **활동 축은 아래 두 단에서만 그림을 가른다.** despair 와 stunned 에서는 **한도가 뉴스**이고,
   지금 치고 있는지 아닌지가 그 뉴스를 바꾸지 않는다.
2. **stunned 에서는 활동 축이 애초에 한쪽으로 쏠린다.** 한도가 막히면 응답이 안 오고,
   응답이 안 오면 `d.last.t` 가 안 움직여 자동으로 조용해진다. 거기서 그림을 둘로 갈라도
   한쪽은 거의 안 나온다.
3. **여섯 장이 전부 쓰인다. 버리는 그림이 없다.** 사용자 작업물이고 `mascot-stunned` 는
   24프레임짜리다.
4. **사용자가 못 박은 것이 지켜진다.** 치는 동안 단계가 idle 이면 `coding` 이 보이고,
   단계가 올라가도 `working` -> `despair` 로 **쉬는 그림이 아니라 일하는 그림**이 이어진다.
   사용자 계정의 지금 단계는 **idle**(5절 실측: strain 24)이라 **치는 동안 거의 항상 `coding`** 이다.

**안 2 (2순위).** float 열을 `float` 하나로 누른다(stunned 만 예외).
더 단순하지만 `mascot-idle` 이 화면에서 완전히 사라진다. **기존 그림을 버리라고 권하지 않는다**는
지시에 걸려서 2순위에 둔다. 사용자가 「조용하면 무조건 떠 있는 게」를 원하면 이 안이다.

### 5-2. 조용함의 문턱은 **180초**다

**감으로 박은 값이 아니다. 사용자 트랜스크립트 3일치를 실제로 세었다.**
`~/.claude/projects` 의 최근 3일 안에 쓰인 파일에서 `usage` 를 가진 줄(어시스턴트 응답)의
타임스탬프를 전부 뽑아 **4,309건**, 그 사이 간격을 잰 값이다.

| 간격 | p50 | p75 | p90 | p95 | p99 | 최대 |
|---|---|---|---|---|---|---|
| 초 | **2.3** | 4.9 | 12.9 | 22.6 | **67.5** | 65,620 |

| 문턱 후보 | 문턱을 넘는 간격 | 문턱 +-25% 구간에 걸터앉은 간격 |
|---|---|---|
| 45s | 101건 (2.34%) | |
| 60s | 55건 (1.28%) | **62건** |
| 120s | 23건 (0.53%) | 14건 |
| **180s** | **15건 (0.35%)** | **4건** |
| 300s | 11건 (0.26%) | 3건 |

**60초면 사흘에 55번 끊긴다.** 그리고 60초 언저리(45~75초)에 **62건**이 몰려 있어서
문턱이 분포의 어깨 위에 앉는다. 거기서는 같은 작업 중에 그림이 들락날락한다.
**180초는 p99(67.5초)의 2.7배**이고 걸터앉는 간격이 사흘에 4건, 하루 1.3번이다.

**호스트 주기와도 맞는다.** `extension.js:1841` 이 **10초마다** 푸시하고,
`extension.js:1680` 의 `fs.watch` + `scheduleRefresh`(200ms 디바운스)가 **트랜스크립트에
한 줄이 붙을 때마다** 푸시한다. 따라서,

```
coding 으로 돌아오는 것   사건이다. 메시지가 붙으면 200ms 안에 그려진다
float 로 넘어가는 것      시간이다. 문턱을 넘고 최대 10초 뒤에 그려진다
```

**비대칭이 제품이 원하는 방향과 같다.** 치기 시작하면 바로 coding 이고, 멈춘 것은 천천히 알아챈다.

### 5-3. 데드밴드를 넣지 않는다

단계 축(`MASCOT_STEPS`)에는 데드밴드가 있고(50/47 · 70/67 · 90/87) 그건 **잡음 있는 스칼라를
자르는 선**이라서다. 활동 축은 그런 축이 아니다. **한쪽은 사건이고 한쪽은 시간**이라
위아래 문턱이라는 것이 성립하지 않는다.

문턱을 살짝 넘겼다가 돌아오는 깜빡임은 **사흘에 4번, 한 번에 몇 초**다(위 표).
그 값에 기계를 더하지 않는다. **최소 체류 시간을 두면 「치는 동안 coding」이 늦어지고,
그건 사용자가 명시적으로 요구한 것을 깎는 것이다.**

### 5-4. 코드의 모양

`webview.js:1326` 의 주석이 이미 이 블록을 가리키고 있다.
「다음 블록이 활동 축을 더한다. 인자를 더하고 쌍을 돌려줄 것.」

```js
// 문턱의 근거는 docs/shop-spec.md 5-2. 호스트의 푸시 주기에서 끌어낸 값이다
var QUIET_MS = 180000;
// 어느 그림이냐. 단계는 mascotState 가 그대로 정하고, 이 표가 그림을 고른다
var MASCOT_ART = {
  idle:    { busy: 'coding',  quiet: 'float'   },
  working: { busy: 'working', quiet: 'idle'    },
  despair: { busy: 'despair', quiet: 'despair' },
  stunned: { busy: 'stunned', quiet: 'stunned' }
};
function mascotQuiet(d) {
  var t = d && d.last && d.last.t;          // 오늘 마지막 어시스턴트 메시지. 없으면 조용하다
  return !t || (Date.now() - t) >= QUIET_MS;
}
```

호출부(`webview.js:1411`)는 **이름과 입력 쌍 그대로** 둔다.

```js
var _step = mascotState(mascotStrain(d, noSession), (d.sd && d.sd.used_percentage) || 0);
var _state = MASCOT_ART[_step][mascotQuiet(d) ? 'quiet' : 'busy'];
```

| 같이 고치는 곳 | 무엇 |
|---|---|
| `html.js:156` | `#mascot` 에 `data-coding` · `data-float` 두 속성 추가 |
| `html.js` 머리 + `extension.js` 의 `renderHtml` 호출부 | `mascotCodingUri` · `mascotFloatUri` 두 변수 |
| `styles.js:68` | `.mascot-wrap[data-state="coding"] .mwarn{top:3.4px;}` **한 줄 추가** |
| `test/panel-css.test.js:187` | `STATES` 를 여섯 장으로 |

**`.mwarn` 의 3.4 는 잰 값이다.** 상자가 88x74 이고 `object-fit:contain` 이므로,

| 그림 | 원본 | 상자 안 실측 | 위 여백 | `.mwarn top` |
|---|---|---|---|---|
| `mascot-coding.png` | 353x223 | **88.00 x 55.59** | **18.41** | **3.4** (= -15 + 18.41) |
| `mascot-float.png` | 345x320 | **79.78 x 74.00** | **0.00** | 규칙 불필요(기본 -15) |

기존 규칙(`idle` · `stunned`, 위 여백 24.5 -> `top:9.5`)과 같은 식이다.
**두 그림을 넣어도 `.card` 는 409 그대로다**(둘 다 실측). 상자가 일한다.

### 5-5. 기본 캐릭터는 공짜다

**`coding` 과 `float` 은 상점에 올라가지 않는다.** 설치하면 바로 쓴다.
상점이 파는 것은 3절의 자리뿐이고, 마스코트 그림은 어느 쪽도 값이 붙지 않는다.
사용자의 불만(「idle 말고 볼 일이 없다」)을 유료화로 바꾸는 것이 이 블록이 가장 하면 안 되는 일이다.

### 5-6. 본 대로 적는 것 둘 (하자는 아니다. 사용자가 판정할 것)

1. **`mascot-coding` 은 88px 에서 게의 얼굴이 상자를 꽉 채운다.** 원본 자체가 오른쪽에서
   잘려 있어(노트북이 353px 경계에 걸려 있다) 88x55.59 로 줄면 노트북이 검은 덩어리 하나가 되고
   타이핑 자국은 1px 아래로 내려간다. 상자 세로의 **75%**만 쓴다(`working` · `despair` 는 100%,
   `idle` · `stunned` 는 67%). **구조는 멀쩡하고 그림 이야기다.**
2. **새 두 장은 갈색이고 기존 넷은 분홍/주황이다.** 배치표에서 활동 축만 움직일 때는
   둘 다 갈색이라 같은 게로 읽히고(`coding` <-> `float`), **단계가 오를 때 갈색에서 주황으로 바뀐다**
   (`coding` -> `working`). 「한도를 태우면 게가 달아오른다」로 읽히기도 하고
   「다른 게로 바뀐다」로 읽히기도 한다. 그림을 다시 그릴 사람은 사용자다.

## 7. 구현자가 지켜야 할 것

### 7-1. 돈. 여기를 틀리면 돈이나 물건이 복제된다

**`credits.js` 를 끝까지 읽어라.** 41~113행 머리말에 규칙이 전부 있고
**이미 한 번 터진 버그의 기록**이 있다(창마다 은행에 적은 판매가 칼 하나에 372,000 크레딧을 찍었다).

```
balance = earned(날짜별 토큰) + bankNet + forgeEarned + market.netOf + shop.netOf
                                                                       ^^^^^^^^^^ 새로 더하는 항
```

| 규칙 | 내용 |
|---|---|
| 1 | **상점의 기록 규칙은 `shop.js` 가 가진다.** `clean` · `newer` · `merge` · `same` · `netOf` 를 내보내고 `credits.js` 가 부른다. 한 기록의 병합이 두 군데 적히면 답이 둘인 기록이 된다 |
| 2 | **`credits.js` 는 세 줄만 는다.** `normalizeLedger` 에 한 줄, `mergeLedger` 에 세 줄짜리 블록 하나, `creditSummary` 에 `+ shop.netOf(ledger.shop)`. **시장이 배선된 그 세 자리를 베껴라** |
| 3 | **값을 `bank` 에 적지 마라.** `bank` 는 창마다 grow-only 카운터를 max 로 병합한다. 구매는 지갑을 통째로 비울 수 있고, 창이 둘이면 같은 캐릭터를 두 번 산다 |
| 4 | **거래의 양쪽이 한 기록 안에 있다.** `owned`(물건)와 `spent`(돈)가 같은 레코드다. `netOf(shop) = -spent`. 떨어진 구매는 **받지도 뺏지도 않는다** |
| 5 | **병합은 레지스터다.** `moves` 가 큰 쪽이 **통째로** 이기고, 같으면 `by` 가 큰 쪽. **max 하는 항목이 하나도 없다**(시장과 같다) |
| 6 | **`owned` 를 두 사본에서 합집합하지 마라.** 이것이 상점판 372,000 버그다. 합치면 떨어진 구매의 물건이 값 없이 남는다. **이긴 기록을 통째로 받는다** |
| 7 | **메시지마다 저장된 기록을 먼저 읽는다.** 다른 창이 움직였을 수 있다. `extension.js` 에 `deps.storedShop()` 문을 시장 옆에 하나 더 낸다 |
| 8 | **쓰고, 병합된 것을 되읽고, 그 다음에 수가 선다.** `deps.record(net, { shop: mine })` 한 번이 상태와 돈을 같이 나르고 병합된 원장을 돌려준다. `kept(mine, landed)` 는 `(moves, by)` 만 본다 |
| 9 | **`held()` 는 0 이다.** 산 순간 값이 나간다. 다른 게임에서 묶어 둘 것이 없다 |
| 10 | **한 수에 원장 한 번 쓴다.** 사기(돈 + `owned` + `seat`)가 한 번, 앉기(`seat`)가 한 번. 앉기도 `moves` 를 올린다. 안 올리면 두 창의 `seat` 가 서로를 덮어쓴다 |
| 11 | **답을 먼저 보내고 `push()` 는 그 뒤에.** 머리글 잔액이 화면보다 먼저 말하면 안 된다 |
| 12 | **환불이 없다.** 되팔기도 취소도 없다. 화면에도 없고 기록에도 없다 |
| 13 | **산 것은 남는다.** 폐지된 대장간의 `forgeEarned` 가 `credits.js` 에 그대로 남아 있는 것과 같은 이유다. 품목이 목록에서 빠져도 `owned` 와 `seat` 는 안 지운다. 앉아 있던 스프라이트가 패키지에서 없어지면 **기록은 그대로 두고 그릴 때만 `player` 로 떨어진다** |
| 14 | **기록의 열쇠에 자리 이름을 붙인다.** `owned: { 'seat:witch': 1 }`. 자리가 둘이 되는 날 이사가 없다 |

기록 모양(제안):

```js
// ledger.shop
{ by: '<replicaId 16hex>', moves: 0, owned: { 'seat:witch': 1 }, seat: 'player', spent: 0, at: 0 }
```

`REPLICA_RE` · `DAY_RE` 와 같은 급의 **경계에서의 청소**를 `shop.clean` 이 한다:
모르는 열쇠는 버리고, `owned` 는 **값표에 있는 열쇠만** 받고(없는 열쇠로 무한히 불릴 수 없게),
`spent` 는 안전 정수 양수만, `seat` 는 `owned` 에 있거나 기본값일 때만 산다.

## 9. 검증

### 9-1. 하네스에 필요한 것 넷. 구현자가 한다

측정 산출물은 `tools/.measure` 로 나가고 `--probe` 가 붙으면 **파일을 아예 안 쓴다.**

1. **`SHOTS` 에 측정 샷 둘.** `usage` · `agents` 와 같은 `measure: true` 꼴이다.
   ```js
   cross: { file: 'measure-cross', tab: 'games', measure: true, usage: { pct: 42, weekly: 61 } },
   shop:  { file: 'measure-shop',  tab: 'games', door: 'shop', measure: true, usage: { pct: 42, weekly: 61 } },
   ```
2. **`renderPage` 의 `STATE` 에 `door` 추가.** 지금 `{tab, game, lastTab}` 뿐이라
   갈림길 아래 두 화면에 **들어갈 방법이 없다.**
3. **`usageData()` 에 `shop` 추가.** `{ owned: ['seat:player','seat:witch'], seat: 'player' }`.
   값표는 `assetsJson.ui.shop` 으로 가므로 harness 도 거기서 받는다.
4. **`--quiet` 플래그.** `usageData` 의 `last.t` 를 문턱 밖(예: 지금 -10분)으로 민다.
   **없으면 float 쪽 그림을 아무도 못 잰다.** `--no-session` · `--stale` 과 같은 이유로 더하는 것이고
   `BOOLS` 에 넣어야 다음 인자를 안 삼킨다.
5. **`ink:<img 셀렉터>` 프로브** (1.32.2 에서 더했다). 그림에 자기 상자가 생긴 뒤로는
   `getBoundingClientRect` 가 어느 그림에나 **상자 크기**를 답한다. 그려진 크기는 거기 안 나온다.
   `ink:` 는 `naturalWidth/Height` 로 contain 을 풀어 **실제로 칠해진 폭과 높이**를 낸다.
   2-2 의 표가 묻는 것이 그 값이다.

## 10. 순서

```
1. 마스코트 두 축   webview.js + html.js + styles.js 한 줄 + 시험.  다른 것과 안 겹친다
2. 갈림길           html.js(#panelCross) + styles.js + webview.js(applyView, s.door)
                    + 목록 머리에 .bj-back
3. 돈               shop.js + credits.js 세 줄 + test/credits.test.js.  화면보다 먼저
4. Shop 화면        html.js(빈 껍데기) + styles.js + webview.js(renderShop) + extension.js(메시지 둘)
5. 좌석             games/blackjack/panel.js 가 CUC.seat() 를 그릴 때 읽는다 + CUC 에 seat() 하나
```

**3을 4보다 먼저 한다.** 화면이 먼저 서면 돈 모델을 화면에 맞추게 되고,
그 방향으로 틀리면 돈이 복제된다. **각 단계가 끝날 때 9-2 의 해당 줄을 돌린다.
다섯 단계를 다 하고 한 번에 재지 않는다.**

### 이 규격이 판정하지 않은 것

- **하이로우에도 내 자리를 둘지.** 지금 좌석이 있는 화면은 블랙잭 하나다. 하이로우 펠트에
  44px 스프라이트가 들어갈 자리가 있는지 **안 쟀다.** 재고 나서 다음 블록에서 정한다.
- **품목 이름 일곱.** 열쇠는 정했고 이름은 제안이다. 사용자가 바꾸면 그대로 간다.
- **방 배경과 에이전트 외형을 상점이 언젠가 팔지.** 지금은 둘 다 무료고 그대로 둔다.
