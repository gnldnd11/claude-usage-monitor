# 게 카지노 화면 규격

> 게임 4개가 14개가 된다. 이 문서는 **14개가 한 가족으로 보이게 하는 규칙**이다.
> 계약(파일 배치·엔진·메시지·검증)은 `games/README.md`에 있고 여기에 다시 쓰지 않는다.
> 이 문서는 **화면만** 다룬다. 충돌하면 계약이 이긴다.

구현 담당자가 읽는 순서는 이렇다.

```
1. games/README.md          무엇을 어디에 만드나 (2·7·8절은 낡았다고 보고됨)
2. 이 문서 1~4절            폭·골격·바닥·테마. 열 화면이 공유하는 것
3. 이 문서 5절의 내 게임     무엇을 크게 보여주고 무엇을 버리나
4. 이 문서 6절              내 게임의 연출 밀리초
5. games/highlow/panel.js   가장 짧은 실제 예제. 베끼지 말고 구조만 볼 것
```

## 1. 폭: 재서 쓴 값

VS Code 탐색기 사이드바다. 가로 스크롤은 없고 사용자가 더 좁힐 수 있다.
아래는 추정이 아니라 `styles.js` + `games/casino.js`를 실제로 렌더해 잰 값이다.

| 사이드바 폭 | 펠트 바깥 폭 | **펠트 안 그릴 수 있는 폭** |
|---|---|---|
| 250 | 172 | **152** |
| 280 | 202 | **182** |
| 320 | 242 | **222** |
| 400 | 322 | **302** |

공식은 `펠트 안 = 사이드바 폭 - 98`이다.
(wrap 10x2 + card 15x2 + inner 14x2 + felt padding 10x2)

**설계 기준 폭은 182px(사이드바 280)이고, 152px(사이드바 250)에서 깨지지 않아야 한다.**

### 조작 줄에 버튼 몇 개가 들어가나 (측정값)

`.bj-btn`은 `flex:1 1 64px`, `.bj-ctl`은 `gap:6px`. 잰 결과는 이렇다.

| 버튼 수 | 한 줄로 유지되는 최소 사이드바 폭 |
|---|---|
| 2개 | 250 이하까지 |
| 3개 | **300** (280에서 두 줄로 접힌다) |
| 4개 | **360** |
| 칩 3개 + Deal | 260 |

> **High-Low는 지금 280px에서 이미 두 줄로 접힌다.** 버그는 아니지만 새 게임이 따라 할 이유도 아니다.

**규칙: 조작 줄의 버튼은 두 개까지.** 세 번째 동작이 필요하면 그것은 버튼이 아니라
펠트 위의 물건이어야 한다. 지뢰는 칸을 눌러 파고 타워는 문을 눌러 올라가므로,
두 게임의 조작 줄에는 `Cash out` 하나만 남는다. **이게 셋을 넘기지 않는 방법이다.**

## 2. 패널 골격

네 화면이 이미 쓰고 있는 뼈대다. **열 개 전부 이 순서를 지킨다.** 순서를 바꾸지 않는다.

```
┌ .ihead.bj-head ──────────────────────────────┐  높이 ~18, margin-bottom 12
│ [←] 글리프 제목              우측 슬롯        │  CUC.frame(id) 가 만들어 준다
├ .bj-felt (또는 .fg-anvil, 또는 없음) ────────┤  padding 12/10, radius 12
│                                              │
│   이 게임이 답하는 것. 최대 블록이 여기 든다  │
│                                              │
│   .hl-line                                   │  min-height 22, margin-top 8
├──────────────────────────────────────────────┤
│ .bj-sr      (화면 밖, aria-live)              │
│ .bj-note    muted 11px                        │  margin-top 10, 보통 hidden
│ .warnbar    거절 사유                          │  보통 hidden
│ .bj-ctl     판돈 칩 + 버튼 (최대 2개)         │  margin-top 14, gap 6, 버튼 34px
└──────────────────────────────────────────────┘
```

### 각 자리에 무엇이 드나

| 자리 | 무엇 | 안 되는 것 |
|---|---|---|
| 좌측 화살표 | 목록으로. `CUC.frame`이 배선해 준다 | 손대지 않는다 |
| 제목 | `meta.title`. `meta.hint`가 `title=` 툴팁 | 규칙을 화면에 펼치지 않는다 |
| **우측 슬롯** (`.bj-side`) | **내가 안 보는 동안에도 남아 있는 것 하나.** 대장간 `3 broken`, 시장 열린 손익, 즉석복권 `4 left` | 배당률·확률·승률 |
| 펠트 | **이 화면이 답하는 질문의 답, 그리고 그 답을 얻으려고 누를 물건.** 판·릴·카드·바퀴 | 배당표, 설명문 |
| `.hl-line` | 판돈 또는 판정 칩. 한 줄, 최대 두 조각 | 세 번째 칩 |
| `.bj-note` | 돈이 모자란 까닭 등. `CUC.note` | 상시 노출 안내문 |
| `.warnbar` | 호스트가 거절한 문장 그대로 | 화면이 지어낸 문장 |
| 조작 줄 | 베팅 화면은 칩+Deal, 진행 화면은 버튼 **2개까지** | 세 번째 버튼 |

### 첫 수는 펠트 위의 물건이 말한다

2026-11-06에 사용자가 직접 해 보고 **지뢰·타워·크래시·키노 넷을 "어떻게 하는지 모르겠다"**고 했다.
나머지 열은 안 걸렸다. 열넷을 나란히 띄워 재 보니 갈리는 선이 하나였다.

| | 펠트 안에 그려진 것의 면적 | 사용자 판정 |
|---|---|---|
| 슬롯 · 휠 · 즉석복권 · 플린코 | 183% · 146% · 94% · 74% | 알겠다 |
| 블랙잭 · 하이로우 · 레드독 | 딜러 게가 앉아 있다 | 알겠다 |
| 포커 | 배당표가 펠트 위에 상시로 펼쳐져 있다 | 알겠다 |
| 키노 | 54%, 그런데 숫자판만 있고 뭘 하라는 말이 71px 아래에 | **모르겠다** |
| 타워 | 49%, 그런데 문의 대비가 펠트 대비 **1.07:1** | **모르겠다** |
| 크래시 | 35%, 그런데 34px 숫자가 무엇인지 아무 데도 없다 | **모르겠다** |
| 지뢰 | **5%. 25칸 중 0칸이 아무것도 안 그린다** | **모르겠다** |

(사이드바 280, Chrome에서 실제로 렌더해 잰 값이다. 면적은 펠트 안에서 **무언가를 칠하는
요소**의 박스 넓이 합을 펠트 넓이로 나눈 것이라, 겹쳐 놓인 요소가 많으면 100%를 넘는다.
절대값이 아니라 **열넷을 같은 자로 잰 순서**로 읽는다.)

**못 알아본 넷은 "안내문이 없는 넷"이 아니라 "펠트가 빈 넷"이다.**
지뢰는 딜 전에도 딜 후에도 25칸이 전부 투명이라, **Deal을 눌러도 화면이 바뀌지 않는다.**
안내문을 어디에 붙여도 그건 안 고쳐진다.

> **그래서 첫 수는 문장이 아니라 물건으로 말한다.**
> 누를 것은 **누를 수 있게 생겨야 하고**, 그러려면 눌리기 전에도 거기 있어야 한다.
> 덮인 칸은 덮개를 그리고, 닫힌 문은 문틀을 그린다. 바퀴가 돌기 전에도 바퀴인 것과 같다.

**문장은 물건으로 말할 수 없는 것에만 쓴다.** 열넷에서 그런 것은 둘뿐이다.
키노의 「몇 개를 골라야 하는가」(개수는 모양이 아니다)와 크래시의 「이 숫자가 무엇인가」
(같은 자리의 같은 숫자가 목표였다가 결과가 된다). 둘 다 **한 줄 11px**이고, 그 줄은
**자기가 가리키는 물건에 붙어 있어야 한다**(5-8 · 5-3).
**지뢰와 타워에는 문장을 한 줄도 쓰지 않는다.** 둘은 물건으로 전부 말할 수 있다.

### 누를 수 있는 것은 펠트 대비 3:1 이상이다

하자 기준이고 취향이 아니다. 아래는 고치기 전 실측값이다.

```
타워  지금 눌러야 할 문(now)   펠트 대비 1.32:1    미달
      지나온 문(past)          펠트 대비 1.23:1    미달
      아직 못 간 문(ahead)     펠트 대비 1.07:1    사실상 안 보인다
      now 와 ahead 의 차이     1.24:1             같은 색으로 읽힌다
지뢰  덮인 칸                   그리지 않는다       0 of 25
      칸 hover                 펠트 대비 1.22:1    마우스를 올려도 안 바뀐다
```

**새 색을 만들지 않고 `--felt-dim`의 불투명도로 세 단을 만든다.** 재서 쓴 값이다.

| 쓰임 | 값 | 펠트 대비 |
|---|---|---|
| 지금 누를 것 | `--felt-dim` 1.0 | **5.11:1** |
| 눌렀던 것 · 아직 안 연 것 | `--felt-dim` .7 | **3.33:1** |
| 이번 판에 내 것이 아닌 것 | `--felt-dim` .7 x 행 opacity .3 | 1.5:1 (일부러 흐리다) |
| hover · focus | `#e8895a` | 4.18:1 |

> **`.bj-why`의 글자 크기는 지금 안 먹고 있다.** `games/casino.js`의 `font:700 10.5px inherit`은
> **단축 속성에 `inherit`를 쓸 수 없어 선언 전체가 버려진다.** 브라우저에서 재면 열넷 전부
> **13.33px · weight 400 · Arial**이다(10.5px · 700 · 패널 글꼴이 아니다).
> 같은 오타가 `games/keno/meta.js`의 `.kn-act`와 `games/market/meta.js`에도 있다.
> 셋 다 `font-weight` · `font-size` · `font-family`를 따로 쓰면 고쳐진다.
> **이건 2절의 「글자 여섯 종」을 지금 깨고 있는 것이고, 9절이 "브라우저에서 세어라"라고
> 적어 둔 항목이 정확히 이것이다.**

### 머리 글리프

`meta.icon`이 `icons.js`에서 고르는 열쇠다. **14개가 서로 달라야 한다.**
목록에서는 48px 타일이 아이콘 자리를 덮으므로 겹침이 안 보이고, 겹치는 자리는 패널 머리 하나뿐이다.

| | |
|---|---|
| 크기 | `.ihead .it svg`가 **15x15**다. 24단위 박스가 0.625px/단위로 줄어드니 2단위 선이 1.25px이고, **2.5단위보다 가는 것은 사라진다** |
| 색 | `.ihead .it svg{color:#e8895a}`로 ember가 들어온다. 따라서 **`currentColor`만 쓴다** |
| 박힌 색 금지 | `warn` · `heart` · `coin`은 `fill`이 박혀 있어 저 규칙을 안 탄다. 머리에 쓰면 강조색이 둘이 되어 3절을 깬다 |
| 같은 물체 | `games/tiles.js`의 그 게임 타일과 **같은 물체**를 가리킨다. 타일이 탑이면 글리프도 탑이다 |

지금 쓰는 열쇠는 `icons.js` 아래쪽 블록에 게임별로 모여 있다.
새 게임이 생기면 **거기에 하나를 더하고, 기존 열쇠를 두 번째 게임에 돌려쓰지 않는다.**

### 치수는 이 값만 쓴다

```
간격      4 · 6 · 8 · 10 · 12 · 14          (.bj-ctl gap 6, felt padding 12/10)
반경      6 (작은 칸) · 8 (버튼·타일) · 12 (펠트)
버튼      높이 34, 최소 폭 64
칩 버튼   높이 28
글자      22 (영웅 수) · 16 (판돈) · 12.5 (제목) · 12 (버튼) · 11 (설명) · 10.5 (칩·우측 슬롯)
```

**글자는 이 여섯 종이 전부다.** 새 크기를 만들면 그 화면만 다른 화면이 된다.
22px 위를 쓰는 곳은 크래시의 배수 하나뿐이고(5-3절), 그건 예외로 적어 둔 것이다.

## 3. 바닥은 셋, 결은 넷

제안받은 결은 다섯이었다. **다섯이면 패널이 다섯 색으로 깜빡인다**는 지적이 맞다.
그래서 **배경이 바뀌는 횟수를 14화면 중 두 번으로 줄이고**, 결은 펠트 위에
**무엇이 놓이는가**로 가른다.

### 바닥 (배경), 셋

| 바닥 | 토큰 | 쓰는 화면 | 왜 |
|---|---|---|---|
| 녹색 펠트 `.bj-felt` | `--felt` `--felt-lo` `--felt-ink` `--felt-dim` | 11개 (카드 4 · 기계 4 · 판 4 중 크래시 제외… 아래 표 참조) | 한 판이 올라가는 테이블 |
| 모루 갈색 `.fg-anvil` | `--forge` 계열 | 대장간 1개 | 작업장이지 테이블이 아니다 |
| **바닥 없음** | `.inner` 그대로 | 시장 1개 | 5-10절에 이유 |

### 결 (펠트 위에 놓이는 것), 넷

| 결 | 게임 | 펠트 위에 | 딜러(`.bj-crab`) |
|---|---|---|---|
| **카드 테이블** | 블랙잭 · 하이로우 · 포커 · 레드독 | 카드만. 장치 없음 | 있다 |
| **기계** | 슬롯 · 플린코 · 휠 · 즉석복권 | **슬레이트 기계판** `.gm-plate` | 없다 |
| **판** | 지뢰 · 타워 · 키노 · 크래시 | 펠트에 그린 **hairline 격자**. 판은 그려진 것이지 놓인 것이 아니다 | 없다 |
| **작업장** | 대장간 | 모루 갈색 | 있다 |

```css
/* games/casino.js 에 추가. 기계 넷이 공유한다 */
.gm-plate{padding:8px;border-radius:8px;background:#15181c;
  box-shadow:inset 0 0 0 1px rgba(0,0,0,.6), 0 1px 0 rgba(255,255,255,.06);}
/* 판 넷이 공유하는 격자선 */
.gm-rule{background:rgba(255,255,255,.1);}
```

> **좌우 패딩 8px은 휠에서만 예외다.** 원 지름이 150px 고정이라 `150 + 8x2 = 166 > 152`가 되어
> 사이드바 250에서 가로 스크롤이 샌다. 휠만 좌우를 1px로 줄인다(5-7절). 위아래 8px은 그대로다.

**기계판이 슬레이트인 이유는 계측값이다.** 바다 심볼 중 가장 흔한 `kelp`는
펠트 위에서 3.25:1, 슬레이트(#15181c) 위에서 5.39:1이다.
심볼을 펠트에 바로 놓으면 흔한 심볼이 바닥에 녹아 **게 심볼이 잭팟이라는 정보 설계가 깨진다.**

### 강조색은 하나다

```
강조      #e8895a (ember)   누를 것·선택된 것·지금 일어나는 것. 결마다 바꾸지 않는다
판정 win  #7ee6a4           이겼다·안전하다. 판정에만
판정 lose #f6836e           졌다·터졌다. 판정에만
```

**결마다 강조색을 다르게 주지 않는다.** 강조색이 넷이면 ember가 더 이상 "누르는 곳"을 뜻하지 않는다.
새 색을 만들지 않는다. 금색 테두리를 쓰지 않는다.

## 4. 테마 경계

지금 섞여 있는 그 경계를 여기서 못 박는다. 판정 기준은 하나다.

> **방의 것은 테마를 따른다. 테이블 위의 것은 따르지 않는다.**

| | 무엇 | 어떻게 |
|---|---|---|
| **방** | 패널 바탕, 카드 테두리, 제목·설명 글자, 버튼 바탕, 판돈 칩, 경고 줄 | `--card` `--inner` `--track` `--text` `--muted` `--border` `--iborder`. VS Code 테마를 따른다 |
| **테이블** | 펠트, 모루, 기계판, 심볼 칸, 목록 타일, 픽셀 카드, 픽셀 동전 | 고정색. **라이트에서도 어둡다** |

이건 이미 그렇게 되어 있다. `styles.js`의 `--felt` · `--forge` 계열에는
`body.vscode-light` 재정의가 **없다.** 그게 의도다. 바꾸지 않는다.

**따라서 `games/tiles.js`와 `games/symbols.js`도 테마 변수를 쓰지 않는다.**
타일 열 개는 자기 녹색 명판을 통째로 들고 있고, 심볼 열 개는 슬레이트 칸 위에서만 산다.
양 테마에서 같은 그림이고, 그게 맞다 (대비는 9절).

| 쓰이는 대비 (측정값) | |
|---|---|
| `--felt-ink` on 펠트 | 9.85:1 |
| `--felt-dim` on 펠트 | 5.11:1 |
| ember on 펠트 | 4.18:1 |
| win on 펠트 / lose on 펠트 | 7.03:1 / 4.29:1 |
| cream on 슬레이트 | 15.41:1 |
| kelp(가장 흐린 심볼) on 슬레이트 | 5.39:1 |

## 5. 게임별 정보 설계

각 항목의 형식은 같다. **질문 → 최대 블록 → 펠트 안 → 버리는 것 → 조작 줄.**

> **화면은 계산하지 않는다.** 엔진이 보낸 것 중에서 고를 뿐이다.
> 배수, 확률, 배당, 잔액을 화면에서 만들지 않는다 (`games/README.md` 6절 1번).

공통으로 **버리는 것**이 하나 있다. **배당표는 어느 화면에도 상시로 깔지 않는다.**
`pays` · `ladder` · `ways` · `tables` · `fair`는 전부 `.hl-line` 아래의
`?` 토글 하나로 접어 두고, 한 줄 요약은 제목의 `title=`(`meta.hint`)에 넣는다.
상시로 펼치면 열 화면 모두가 표가 되고, 그러면 **무엇을 보라는 건지가 사라진다.**

### 이 금지가 첫 수까지 덮은 적이 있다. 가르는 질문은 하나다

> **빼고 나서도 플레이어가 다음에 뭘 누를지 아는가.**
> 알면 `?` 뒤로 접는다. 모르면 화면에 있어야 한다.

```
배당표      "이기면 얼마"          접는다
첫 수       "지금 뭘 누르나"       편다. 그리고 2절대로 문장이 아니라 물건으로
```

**둘은 같은 것이 아니다.** 배당표는 접어도 판이 돌아가고, 첫 수는 접으면 판이 멈춘다.
2026-11-06 전까지 이 절이 그 둘을 한 문장으로 묶어 둬서 **네 화면이 같이 접혔다.**

**값 하나가 양쪽에 걸치면 「그것 없이 다음 수를 둘 수 있나」로 가른다.** 예를 들어 타워의
`choices[].fair[]`는 열 층 x 세 난이도면 서른 줄짜리 배당표지만(접는다), **고른 난이도 한 벌의
열 줄**은 오른쪽 기둥에 서서 「올라갈수록 얼마가 되는가」를 말하는 **사다리 그 자체**다(편다).
같은 배열이지만 전자는 표이고 후자는 물건이다.

> **포커는 이 규칙을 처음부터 안 지키고 있었고, 그게 옳았다.** `games/poker/panel.js`의
> `.pk-pays` 아홉 줄은 모든 단계에서 펠트 맨 위에 펼쳐져 있다. 포커에서 그 표는 배당표가
> 아니라 **어느 카드를 홀드할지 고르는 근거**이고, 빼면 다음 수를 둘 수 없다.
> 사용자가 열넷 중 포커를 못 알아본 게임으로 꼽지 않은 이유 중 하나가 이것이다.
> **예외로 적어 두는 것이 아니라, 가르는 질문이 포커에서도 같은 답을 낸다는 뜻이다.**

```html
<!-- 열 화면이 공유하는 토글. .bj-note 자리 바로 위 -->
<button type="button" class="bj-why" id="xxWhy" aria-expanded="false">How it pays</button>
<div class="bj-pays" id="xxPays" hidden>...</div>
```
```css
.bj-why{margin-top:10px;padding:0;border:0;background:transparent;color:var(--muted);
  font:700 10.5px inherit;cursor:pointer;text-decoration:underline;text-underline-offset:2px;}
.bj-why:focus-visible{outline:2px solid #e8895a;outline-offset:2px;}
.bj-pays{margin-top:6px;font-size:10.5px;color:var(--muted);font-variant-numeric:tabular-nums;}
.bj-pays[hidden]{display:none;}
```

### 5-1. 지뢰 (mines) · 판 · 최소 100

**질문.** 한 칸 더 팔까, 지금 받을까.

**최대 블록.** 5x5 격자. 그 아래 `.hl-line`에 `cash`를 `CUC.pot()`로 16px.
현금화 금액이 숫자 중 제일 크다. 이 게임의 긴장은 거기 있다.

**펠트 안.**
- 격자 5x5. 칸은 `1fr`, 간격 4, `aspect-ratio:1`. 182px에서 칸 33px, 152px에서 27px.
  **상한은 판에 건다: `max-width:216px`** (= 5x40 + 4x4). 아니면 넓은 사이드바에서 판만 거대해진다.
  칸에 `max-width:40px`를 걸면 안 된다. 칸이 멈춘 뒤에도 격자 전체는 계속 늘어나서
  **전체 폭이 칸 합보다 커지고, hairline 오프셋 식이 어긋난다.**
- 칸 상태는 `grid[25]`가 전부 준다. `null` 덮인 칸 / `safe` 보석(win 녹색 점) /
  `boom` 터진 칸(lose 빨강) / `mine` 안 밟은 지뢰(muted, 끝난 뒤에만) / `free` 안 연 칸.
- **`null`인 칸에 덮개를 그린다. 이 게임에서 제일 중요한 한 줄이다.**
  지금은 `.mn-mk`가 `background:transparent`라 덮인 칸이 아무것도 안 그리고,
  **베팅 화면도 진행 화면도 빈 녹색 사각형이다. 딜을 눌러도 판이 안 바뀐다.**
  재 보면 25칸 중 **0칸**이 무언가를 그리고 있고, 펠트 안 잉크 면적이 **5%**다
  (슬롯 183% · 휠 146% · 즉석복권 94% · 플린코 74%).

```css
/* a covered cell. Twenty-five of these ARE the board: without them the felt is empty and the
   deal changes nothing on screen. --felt-dim at .7 is 3.33:1 on the felt, 1.0 is 5.11:1 */
.mn-c::before{content:"";position:absolute;inset:3px;border-radius:5px;
  box-shadow:inset 0 0 0 1px var(--felt-dim);opacity:.7;}
/* the bet screen: the lids are there, but the board is not yours yet */
.mn-c:disabled::before{opacity:.34;}
/* a cell that has been turned over has no lid left on it */
.mn-c.safe::before,.mn-c.boom::before,.mn-c.mine::before,.mn-c.free::before{opacity:0;}
/* the hover was 1.22:1 against the felt, which is no hover at all */
.mn-c:hover:not(:disabled)::before{box-shadow:inset 0 0 0 1px #e8895a;opacity:1;}
```

> **덮개는 그린 것이지 놓인 것이 아니다.** 면을 채운 안(`background:rgba(242,246,243,.09)`)을
> 같이 그려서 버렸다. 25칸이 밝아지면 펠트가 사라지고 **타일을 올려 둔 기계**로 읽혀 3절의
> 결 구분이 깨진다. 테두리만으로 「뒤집을 것이 있다」는 충분히 읽힌다.

> **이 덮개는 100판째에도 사라지지 않는다.** 판 자체이기 때문이다.
> 「한 번 해 봤으면 감춘다」류의 `CUC.state()` 플래그를 두지 않는다. 두면 창마다 다른 판이 뜬다.
- `.hl-line` 두 번째 조각: `next`를 칩 하나로. `다음 x1.24 · 22/25`.
  `next.mult100`과 `next.chance`를 그대로 쓴다. 화면이 나누지 않는다.
- `left`는 우측 슬롯.

**버리는 것.** `ladder[]` 25행과 `fair`는 `?` 토글. `safeTotal` · `dug` · `safe`는 안 쓴다.

**조작 줄.** 베팅 화면: 지뢰 수 선택(`choices` 3/5/10)을 `.bj-stakes` 모양의 두 번째 묶음으로,
그 아래 판돈 칩 + `[Deal]`. 진행 화면: **`[Cash out 1,240]` 하나.**
파는 건 칸을 누르는 것이고, 버튼이 아니다.

### 5-2. 타워 (tower) · 판 · 최소 100

**질문.** 한 층 더 올라갈까.

**최대 블록.** 10층 사다리 전체. 다른 게임과 달리 **지나온 것이 화면에 남아 있는 게 이 게임이다.**

**펠트 안.**
- 10행을 위에서 아래로(10층이 맨 위). 각 행은 `rows[i].cells` 개수만큼 문.
- 행 높이는 `where`에 따라 둘뿐이다. `now` **28px**, `past`와 `ahead` **14px**.
  10x14 + 2개 간격 여유 ≈ 170px. 182px 폭 안에서 문 3~4개가 각 40~55px. 들어간다.
- `past` 행: 지나온 문만 ember. `ahead` 행: 전부 `--felt-dim` 30%.
- **문은 문틀로 그린다.** 지금은 `.tw-d`가 `rgba(0,0,0,.22)`, `now` 행만 `rgba(0,0,0,.3)`이라
  재 보면 **now 문이 펠트 대비 1.32:1, ahead 문이 1.07:1, 둘 사이가 1.24:1**이다.
  세 상태가 한 색으로 읽히고, 베팅 화면은 **빈 녹색 사각형**이 된다.

```css
/* a door is a door before it opens. --felt-dim 1.0 is 5.11:1 on the felt and .7 is 3.33:1, so the
   floor being climbed, the floors already taken and the floors not reached read as three things */
.tw-d{background:transparent;box-shadow:inset 0 0 0 1px var(--felt-dim);opacity:.7;}
.tw-row.tw-now .tw-d{opacity:1;}
.tw-row.tw-now .tw-d:hover:not(:disabled){background:rgba(232,137,90,.26);
  box-shadow:inset 0 0 0 1px #e8895a;}
/* the three that are filled keep their fill and drop the frame */
.tw-d.took{background:#e8895a;box-shadow:none;opacity:1;}
.tw-d.trap{background:rgba(0,0,0,.42);box-shadow:inset 0 0 0 1px var(--felt-dim);opacity:1;}
.tw-d.sprung{background:#f6836e;box-shadow:none;opacity:1;}
```

- **베팅 화면에도 사다리를 적는다.** `rows`가 비어 있을 때 `twM<f>`를 고른 난이도의
  `choices[].fair[f]`로 채운다. **화면이 계산하는 것이 아니라 엔진이 이미 보낸 수**이고,
  `pays()`가 이미 같은 배열을 쓰고 있다. 지금은 열 칸이 전부 빈 문자열이라
  **난이도 칩을 눌러도 문 개수 말고는 아무것도 안 바뀐다.** 사다리가 들어오면
  3/4를 2/3로 바꿀 때 `×1.29 … ×17`이 `×1.72 … ×57`로 움직이고, **그게 난이도가 무엇인지다.**
  (휠이 돌기 전에 28칸을 다 보여주는 것과 같은 판단이다. 사다리는 비밀이 아니다.)
- 오른쪽 **39px** 기둥에 각 행의 `mult100`을 mono **10.5px** 우측 정렬. **이게 사다리다.** 표가 아니다.
  (처음엔 12px 기둥에 10px이라고 적었는데 둘 다 틀렸다. 10px은 2절의 글자 여섯 종에 없고
  9절 체크리스트가 2절로 판정한다. 그리고 12px 기둥에는 `×1.50`도 안 들어간다.
  39px은 표의 가장 넓은 칸 `×57277`이 10.5px에서 차지하는 폭이다.)
- `.hl-line`에 `cash` 16px + `next` 칩.

**끝났을 때가 이 게임의 감정이다.** `done`이면 **모든 층의 함정을 한 번에 연다.**
못 간 층의 함정까지 전부. "거기였어"는 거기서 나온다. 연출은 6절.

**버리는 것.** `choices` 난이도표의 상세는 `?`. `floors` · `at` · `traps`는 행이 이미 말한다.

**조작 줄.** 베팅 화면: 난이도 3단 묶음 + 판돈 칩 + `[Deal]`.
진행 화면: **`[Cash out]` 하나.** 오르는 건 문을 누르는 것이다.

### 5-3. 크래시 (crash) · 판 · 최소 10

**질문.** 어디에 걸까. (그리고 재생이 끝나면) 어디서 터졌나.

**최대 블록.** **배수 숫자 하나.** 이 화면에서 유일하게 34px를 쓴다.
목표를 고를 때도 그 숫자고, 재생 중에 1.00에서 `at`까지 올라가는 것도 **같은 숫자다.**
숫자가 둘이면 어느 쪽을 보라는 건지 모른다.

**펠트 안.**
- **숫자 바로 위에 11px 한 줄로 그 숫자의 이름을 적는다.** `.cr-cap`, `--felt-dim`, 가운데.
  `arm`·`bet`에서 `Cash out at`, `done`에서 `Burst at`.
  **이 절이 "같은 숫자를 같은 자리에" 둔다고 정해 놓고 그것이 무엇인지는 어디에도 안 적었다.**
  베팅 화면을 재 보면 34px 숫자 하나와 빈 막대와 무라벨 슬라이더가 전부이고
  (`.cr-pays`는 `arm` 전에는 빈 문자열이다), **그 숫자가 목표인지 결과인지 말하는 것이 없다.**
  한 줄을 더 쓰는 것이 아니라, **한 자리를 두 뜻으로 쓰기로 한 결정의 값을 이제 치르는 것이다.**
- 가운데 `x12.4` 34px 800. `font-variant-numeric:tabular-nums` 필수. 안 그러면 숫자가 떤다.
- 그 아래 `bar100` 가로 막대 8px, ember 채움.
- 그 아래 한 줄 11px: `받는 돈 12,400 · 확률 7.9%` (`payout`, `chance`).
  **이 줄은 `arm`부터다.** 베팅 화면에는 걸 돈도 목표도 아직 호스트에게 없고,
  `idleView()`의 `chance`는 **기본 눈금 하나의 확률**이라 슬라이더를 옮기면 거짓이 된다.
  화면이 다시 계산하면 안 되므로(5절 머리말) **베팅 화면에는 이름만 있고 값은 없다.**

```css
/* what the big number IS. The same figure in the same place means the target before the launch
   and where it burst after it, and nothing else on the screen says which one is up */
.cr-cap{margin-bottom:-2px;text-align:center;font-size:11px;font-weight:700;color:var(--felt-dim);}
```

**조작 줄 위에 슬라이더 한 줄.** 1.1x~50.0x, 0.1 눈금은
`<input type="range" min="11" max="500" step="1">` 하나뿐이다.
버튼 50개를 놓을 폭이 없다. 슬라이더는 `aria-valuetext`에 `x12.4`를 넣는다.

**이 게임은 실시간이 아니다.** 화면은 재생만 한다.
**중도 회수 버튼을 만들면 안 된다.** 만들면 화면이 게임에 대해 거짓말을 한다.
`instant`(1.00x 전 파열, 3%)는 숫자가 1.00에서 한 번도 움직이지 않고 바로 빨강이 된다.

**버리는 것.** `range`는 슬라이더 양끝이 이미 말한다. `exact` · `ticks`는 안 쓴다.

> **"슬라이더 양끝이 이미 말한다"가 사실이 아니다.** 재 보면 `.cr-dial` 안에 있는 것은
> `<input>` 하나뿐이고 양끝에 아무 글자도 없다. 두 가지 중 하나를 사용자가 고른다.
> **(가) 그대로 둔다** (`.cr-cap`이 숫자의 뜻을 말하고 나면 슬라이더가 그 숫자를 움직인다는 건
> 손으로 끌어 보면 즉시 안다), **(나) 양끝에 10.5px `--felt-dim`으로 `×1.1` · `×50`을 붙인다**
> (각각 22px · 20px, 182px에서 슬라이더에 128px이 남아 들어가기는 한다).
> **권고는 (가)다.** 182px에서 한 줄에 세 덩어리를 넣는 것보다, 이름 붙은 숫자 하나가 싸다.

**조작 줄.** 판돈 칩 + **`[Launch]` 하나.**

### 5-4. 슬롯 (slots) · 기계 · 최소 10

**질문.** 세 칸이 맞았나.

**최대 블록.** 릴 3개 x 3행, 셀 **48px**. 셀 합이 `3x48 = 144`이고 남는 8px은 **양쪽 홈통 4px씩**이다.
합쳐서 152. **152는 사이드바 250에서의 펠트 안 폭과 정확히 같다.** 어느 폭에서도 들어간다.
48px은 심볼 격자(24단위)가 정확히 2픽셀/단위가 되는 유일한 값이다. 바꾸지 않는다.

**8px을 릴 사이에 쓰지 않는다.** 꺾쇠(아래)는 가운데 행의 **바깥**에 서야 하는데,
8px을 릴 사이 간격으로 쓰면 바깥에 남는 폭이 0이 된다. 8px은 두 곳에 있을 수 없다.
릴끼리의 구분은 **폭을 안 먹는 1px inset**으로 준다.

**펠트 안.**
- `.gm-plate` 슬레이트 판 위에 릴 3개.
- 각 릴은 `reels[i].above` / `.sym` / `.below` 세 칸. **엔진이 진짜 이웃을 보내므로
  진짜 링을 진짜 자리로 굴릴 수 있다.** `strips[]`와 `at`으로 굴리고, 멈추면 `above/sym/below`와 맞는다.
- 당첨 줄은 가운데 행. **박스를 치지 말고** 양쪽 홈통에 ember 꺾쇠 두 개를 둔다.
  박스는 3칸을 하나로 묶어 버려서 "세 개가 맞았다"를 지운다.
- `.hl-line`: `win.kind`에 따라 칩 하나. `three`면 `.bj-chip.bj`, `pair`면 `.bj-chip`, `none`이면 비움.

**버리는 것.** `pays[6]`은 `?` 토글. `strips`는 그리는 데만 쓰고 보이지 않는다.

**조작 줄.** 판돈 칩 + **`[Spin]` 하나.**

### 5-5. 즉석복권 (scratch) · 기계 · 최소 10

**질문.** 뭐가 나왔나, 몇 칸 남았나.

**최대 블록.** 3x3, 칸 **48px**. 총 152px. 슬롯과 같은 칸 크기다. **같은 심볼은 같은 크기로 산다.**

**펠트 안.**
- `.gm-plate` 위에 3x3.

#### 구슬은 가속한다. 등간격이 아니다

**사용자 판정: "핑코는 좋은데 너무 빨리 끝나잖아. 긴장감이 없음."**
이 화면은 정보 설계가 아니라 **시간**이 문제다. 지금은 48ms 등간격 12줄 = 576ms다.

**48ms는 한 번의 튕김이 보이기에 짧다.** 60fps에서 2.9프레임이고, 구슬이 한 프레임에
평균 1.7px(5px / 2.9) 옆으로 가므로 **튕긴 것이 아니라 흘러내린 것으로 보인다.**
한 번의 튕김이 사건으로 읽히려면 **4프레임(67ms)**, 「튕겼다가 멈췄다」까지 보이려면
**6프레임(100ms)**이 필요하다. 그래서 하한을 **70ms**로 둔다(키노의 공 간격이 이미 그 값이다).

**그리고 간격이 줄어들어야 가속으로 보인다.** 핀 줄 간격은 7px로 균일하므로, 실제 구슬이라면
아래로 갈수록 한 줄에 걸리는 시간이 짧아진다. 등간격은 그 사실에 대해 거짓말이다.

```
줄 k 의 간격 = 140 - 6(k - 1)  ms,  k = 1..12
  140 134 128 122 116 110 104 98 92 86 80 74      합 1,184
```

**첫 줄 140, 마지막 줄 74. 전부 70ms 하한 위다.** 끝이 두 배 가깝게 빨라지는 것이
떨어지는 것으로 읽히고, 마지막 세 줄에서 통이 좁혀지는 동안에도 한 번씩이 아직 보인다.

| | 지금 | 바꾼 뒤 |
|---|---|---|
| 핀밭 통과 | 576 | **1,184** |
| 통에 안착 | +130 (706) | **+180 (1,364)** |
| 결과 칩 | 806 | **1,484** (안착 +120) |

**버리는 것.** `ways[13]` · `paths` · `den`은 `?` 토글. `rows`/`bins`는 그리는 데만.

**조작 줄.** 베팅 화면에 위험도 3단(`risks`) 묶음 + 판돈 칩 + **`[Drop]`.**

```
          2줄  40x16 스파크라인  ·  손익 칩(들고 있을 때만)   .mk-spark .mk-fg
          ↓ 행을 누르면
[종목]  ← Coins · CODE · 현재가                              .mk-crumb
        (들고 있으면) 손익 26px + 한 줄 설명                  .mk-plbox
        기간 칩 4개  ·········  등락률 11 색                 .mk-spanrow
        캔들 차트 186x110 + low/high                         .mk-well
        그 아래: 판돈 칩과 [Buy], 또는 [Sell] 하나
```

#### 등락률은 목록 행에 박는다. 툴팁이 아니다

**결함이었다.** `chgBp`가 `aria-label`과 `row.title`에만 있어서 **마우스를 올려야 보였다.**
목록 행은 네 종목 중 어느 것을 열지 고르는 자리이고, 그 결정을 하는 숫자가 등락률이다.

**자리는 1줄, 현재가 바로 오른쪽이다.** 2줄(스파크라인 옆)에 둔 안을 같이 그려서 버렸다.
2줄에 두면 **등락률과 손익 칩이 6px 간격으로 나란히 서서**, 부호와 색을 가진 숫자 둘이
한 덩어리로 읽힌다. 어느 쪽이 시장이고 어느 쪽이 내 돈인지 안 갈린다.
1줄에 두면 **위 줄은 시장, 아래 줄은 그림과 내 것**으로 갈린다.

**들고 있는 종목은 둘 다 필요하다.** 등락률은 네 행이 같은 기준으로 비교되는 시장의 숫자이고,
손익 칩은 내 매수가 기준의 내 돈이다. 다른 사실이라 한쪽이 다른 쪽을 대신하지 못한다.
**다만 줄이 다르다.** 칩은 지금처럼 들고 있을 때만 2줄 오른쪽에 뜬다.

```html
<span class="mk-r1">
  <span class="mk-nm">Shellback</span>
  <span class="mk-px">692</span>
  <span class="mk-chg mk-u">+3.0%</span>
</span>
<span class="mk-r2">
  <span class="mk-spark"><!-- 40x16 svg --></span>
  <span class="mk-fg"><!-- .bj-chip.still, 들고 있을 때만 --></span>
</span>
```

**사이드바 250에서 재서 들어간다.** 고정폭은 현재가 36.41(`1,507`) + 등락률 46 + 좌우 패딩 12 +
gap 12 = 106.4px이고, 172px에서 이름에 **73.9px**이 남는다.
가장 긴 이름 `Shellback`이 12.5px bold로 **61.3px**이라 잘리지 않는다(여유 12.6px).

**등락률 칸은 `min-width:46px`로 고정한다.** 재 보면 `±X.X%`가 37.7px, `±XX.X%`가 45.2px이다.
고정하지 않으면 한 자리에서 두 자리로 넘어갈 때마다 **현재가가 7.5px 옆으로 흔들린다.**

#### 기간 칩: 4개, 기본은 1D

**주식 앱의 1D/1W/1M/1Y/ALL을 그대로 베끼지 않는다.** 이 시세는 그보다 잔잔하고,
무엇보다 **1Y는 그릴 수가 없다.** 아래가 재서 정한 네 칸이다.

| 칩 | 창 | `stepMs` | `count` | 캔들 | slot@280 | 몸통@280 | slot@250 | 몸통@250 |
|---|---|---|---|---|---|---|---|---|
| `3H` | 3시간 | 5분 | 36 | 5분봉 | 5.17 | 3.19 | 4.33 | 2.67 |
| **`1D`** | **24시간** | **60분** | **24** | **1시간봉** | **7.75** | **4.80** | **6.50** | **4.02** |
| `1W` | 7일 | 6시간 | 28 | 6시간봉 | 6.64 | 4.11 | 5.57 | 3.44 |
| `1M` | 30일 | 24시간 | 30 | 일봉 | 6.20 | 3.84 | 5.20 | 3.22 |

**캔들 개수를 36으로 고정하지 않은 이유.** 고정하면 1W가 280분봉, 1M이 20시간봉이 되어
**사람이 이름 붙일 수 없는 단위**가 된다. 위 네 줄은 전부 5분·1시간·6시간·1일이고,
그 대신 개수가 24~36으로 움직인다. 슬롯은 **250px에서도 4.33px 아래로 내려가지 않는다.**

**네 칩 모두 심지가 있다.** 엔진이 캔들 하나를 `WICK_SAMPLES`(8)번 샘플링하므로
`stepMs`가 1분보다 크기만 하면 고저가 시종가와 갈린다. 실측 심지 수는
3H 33/36 · 1D 21/24 · 1W 26/28 · 1M 25/30이다.

**기본값이 1D인 이유는 둘이다.**

1. **코인이 자기를 소개하는 단위가 하루다.** `?` 토글이 `moves about 4% a day`라고 말하고
   `grade`도 그 축이다. 거기에 `1D −2.7%`가 붙으면 한 문장으로 읽힌다.
2. **3H는 숫자가 잡음으로 읽힌다.** 표본 40회의 중앙 |등락|을 재면 이렇다.

   | | 3H | **1D** | 1W | 1M |
   |---|---|---|---|---|
   | TIDE (calm) | 0.36% | **0.81%** | 2.13% | 8.29% |
   | KELP (steady) | 0.51% | **1.71%** | 4.87% | 16.30% |
   | SHEL (choppy) | 0.64% | **2.76%** | 8.61% | 27.58% |
   | CRAB (wild) | 1.46% | **2.71%** | 10.15% | 30.21% |

   3H는 네 종목이 0.4~1.5%에 몰려 **서로 구별되지 않는다.** 1D에서 갈리기 시작한다.

**`1Y`와 `ALL`은 넣지 않는다. 취향이 아니라 거짓말이 되기 때문이다.**
가격 함수의 시작점은 `EPOCH_MS = 2026-01-01`이고 그 이전 분을 물으면 **전부 기준가 그대로**가 온다.
2026-11-06 기준으로 365일 창은 **왼쪽 15%가 엔진이 시작하기 전**이고,
실제로 그려 보면 36개 중 **5개가 고=저인 죽은 캔들**이다. 1M이 상한이다.

#### 기간 칩은 차트 바로 위에 둔다. 조작 줄에는 들어가지 않는다

`.bj-ctl`은 **버튼 두 개까지**이고(1절) 거기엔 이미 판돈 칩 3개와 `[Buy]`가 있다.
기간은 돈을 쓰는 동작이 아니라 **보는 법**이므로 보는 것 옆에 붙는다.

```
.mk-plbox            (들고 있을 때만)
.mk-spanrow          [3H][1D][1W][1M] ············ +19.1%     ← 여기
.mk-well             캔들 차트 + low/high
.hl-line             판돈 칩 또는 거래 결과 칩
.bj-why / .bj-pays
.bj-ctl              판돈 칩 + [Buy], 또는 [Sell]
```

**차트 아래가 아니라 위다.** 아래에 두면 `.hl-line`·`?`·조작 줄과 함께 세그먼트 컨트롤이
두 개 연달아 쌓여, 바로 아래 판돈 칩과 **같은 모양 두 줄**이 된다.
위에 두면 읽는 순서가 `무엇을 · 어느 창으로 · 그래서 이 모양`이 된다.

**`.bj-stakes`를 그대로 쓰지 않는다.** 재 보면 이렇다. 기준은 사이드바 250, 폭 **172px**이다.

| 컨트롤 | 칸 수 | 폭 | 등락률 45.2 + gap 6 을 올리고 남는 것 |
|---|---|---|---|
| `.bj-stakes` 그대로 (12px, 좌우 9) | 4 | 157.6 | **−36.8. 못 선다** |
| **`.mk-span` (11px, 좌우 5)** | **4** | **120.0** | **+0.8** |
| `.mk-span` | 5 | 149.5 | **−28.7. 못 선다** |

**그래서 칩은 네 개가 상한이다.** 기간 세트를 넷으로 정한 것은 취향이 아니라 이 표다.

**남는 0.8px은 세 자리 등락률이 먹는다.** `±XXX.X%`는 52.6px이라 7.4px이 모자란다.
표본 400회에서 **1M의 최대 |등락|이 64.4%**라 사실상 안 나오지만, 나올 때를 위해
`.mk-span`에 `flex:0 1 auto; min-width:0`을 준다. **칩 쪽이 눌리고 숫자는 안 잘린다.**

**세그먼트 대신 배경 없는 글자 줄로 만드는 안을 그려서 버렸다.** 더 가볍지만
선택 표시가 ember 글자가 되어, 바로 아래 판돈 칩의 선택 표시(`.on` = `--card` 바탕)와
**한 패널 안에서 "골라진 것"의 표현이 둘**이 된다. 그리고 클릭 타깃이 29x20px로 작아진다.

#### 등락률이 무엇 대비인지는 기간 칩이 말한다

지금은 `창 시작 대비`인데 **그 말이 화면 어디에도 없었다.**
이 게임에는 "전일 종가" 같은 자연스러운 기준이 아예 없으므로, **창을 정하면 기준도 정해진다.**
그래서 한 마디를 더 쓰지 않고 **자리로 푼다.**

- **종목 화면.** 등락률을 **기간 칩과 같은 줄, 오른쪽 끝**에 둔다. `1M ····· +19.1%`가
  한 줄로 읽힌다. **crumb에서는 뺀다.**
- **목록 화면.** 기간 컨트롤이 없으므로 **창 이름 한 마디**를 목록 머리 오른쪽 끝에 둔다.
  `last 3h` · `last 24h` · `last 7d` · `last 30d`. 10.5px muted, 등락률 열과 오른쪽이 맞는다.
  이것이 네 행 전부의 기준을 한 번에 말한다.
- **스크린리더.** 행과 차트의 `aria-label`은 창 이름을 풀어 쓴다.
  `Shellback, 692, up 3.0% over the last 24 hours, nothing held`.
  (창 이름이 상수표에 있으므로 패널의 `spanOf()`는 지울 수 있다. 캔들 간격을 되읽어
  "168 hours" 같은 문장을 만들던 함수다.)

> **crumb에서 등락률을 빼는 것은 결함 수정이기도 하다.** 사이드바 250에서 crumb은
> `← Coins`(61.1) + 현재가(24.2) + 등락률(37.7) + gap 18 = 141로, **종목 코드에 31px만 남는다.**
> `CRAB`은 37px이 필요해서 **`K…`로 잘리고 있었다.** 등락률을 내보내면 코드에 74.7px이 남는다.

#### 기간은 화면이 고르고 창은 호스트가 만든다

**패널이 `{stepMs, count}`를 보내지 않는다. 칩의 키만 보낸다.**

```js
CUC.post('mk', 'open', { span: '1D' })      // '3H' | '1D' | '1W' | '1M'
```

`games/market/meta.js`가 키를 `SHAPE` 표에서 찾아 `view()`에 넘기고, **모르는 키는 기본값**으로
떨어진다. 지금 그 파일에 상수 하나로 있는 `SHAPE`가 네 줄짜리 표가 되는 것뿐이다.

**이유 둘.** 하나는 지금 `SHAPE`에 적혀 있는 그대로다. **한 파일이 "무슨 창이 화면에 있나"에 답한다.**
다른 하나는 `count`가 240까지 허용된다는 것이다. 웹뷰가 보낸 수를 그대로 넘기면
한 번의 `open`이 코인 4개 x 240캔들 x 샘플 8 = 7,680번의 가격 계산이 된다.
**호스트가 고르면 그 입력은 존재하지 않는다.**

**선택한 기간은 `meta.js`가 기억한다.** `onPush`로 나가는 **아무도 묻지 않은 갱신**이
기본 창으로 되돌아가면, 1M을 보고 있던 화면이 1분마다 3H로 튄다.

**기간은 한 벌이고 두 깊이가 같이 쓴다.** `view()`는 한 번에 코인 넷을 모두 그리고
`chgBp`는 그 창의 첫 시가 대비이므로, **목록의 네 등락률도 같은 창을 따라간다.**
그것이 맞다. 목록은 네 종목을 **서로 비교**하는 자리고, 기준이 행마다 다르면 비교가 안 된다.

#### 최대 블록은 상태에 따라 바뀐다

이 화면에서만 그렇고, 그게 맞다.

- **포지션이 있으면** → 손익이 최대 블록. 26px, 부호 포함, win/lose 색. 차트는 그 아래.
  내가 안 보는 동안 움직인 것이 그 숫자다. **이게 다시 들어올 이유다.**
- **포지션이 없으면** → 차트가 최대 블록. 손익 자리는 비운다. 0을 띄우지 않는다.

**목록 행의 손익.** 포지션을 들고 있는 종목만 2줄 오른쪽에 `+1,240` 칩(`.bj-chip.still`, 49.3px).
없는 종목은 **아무것도 없다.** 4행 전부에 `0`을 깔면 숫자가 넷이 되고 그 중 하나가
움직인다는 사실이 안 보인다. 등락률은 반대로 **네 행 전부에** 있다. 그게 비교되는 숫자다.

#### 안 넣는 것 둘

**캔들 스크러빙(캔들에 마우스를 올리면 그 시점 값).** 넣지 않는다.
**슬롯이 가장 넓은 1D에서도 7.75px이고 3H에서는 4.33px이다.** 5px짜리 적중 영역은
마우스로도 겨냥이 안 되고, 키보드로는 들어갈 길이 아예 없다(차트는 `<i>` 더미다).
그리고 스크러빙이 줄 값은 **이미 `.mk-ax`의 `low` / `high`가 말하고 있다.**

**`baseBp`(기준가 대비)를 화면에 올리는 것.** `?` 토글 안에 그대로 둔다.
이 게임에는 "전일 종가"가 없는 대신 **기준가와 밴드(base/8 ~ base x8)**가 있어서
주식의 52주 범위 같은 역할을 할 수는 있다. 하지만 **그 역할은 `1M` 칩이 이미 한다.**
30일 창의 고저 폭 중앙값은 12.8%(TIDE)에서 57.2%(CRAB)로, 이 코인이 어디쯤 있는지가
**숫자 하나가 아니라 그림으로** 나온다. 둘 다 올리면 같은 질문에 답이 둘이 된다.

#### 그대로 가는 것

**차트는 라이브러리 없이 그린다.** 절대배치 `<i>` 몸통 24~36개 + 심지.
백분율 배치라 리사이즈 훅이 없다. 의존성 0이 이 저장소의 설계다.

**수수료는 한 번만 말한다.** 매수 버튼 아래 `Round trip 0.5%, taken when you sell.` 11px muted,
**매수 화면에서만.** 상시 노출하면 자기해설이 된다.
**그 숫자는 화면이 만들지 않는다.** `view()`의 `feeBp`로 온다(지금 **50 = 0.5%**).
패널에 수수료 문자열을 박으면 다음에 수수료를 바꿀 때 화면만 틀어진다.

**조작 줄.** `[Buy]` 또는 `[Sell]`. 하나씩이고 동시에 둘이 뜨지 않는다.
기간 칩은 여기에 들어가지 않으므로 **버튼 두 개 상한은 그대로다.**

**우측 슬롯.** 열린 포지션 전체의 손익 합. 포지션이 없으면 빈다.

### 5-11. 검 강화 (forge) · 작업장

재조율로 생기는 요소 넷의 자리만 정한다. 나머지는 지금 화면 그대로다.

## 6. 연출: 밀리초

**순간이 셋이다. 하나씩 기준이 다르다.** 1~2는 처음부터 있었고 3은 2026-11-06에 생겼다.

```
1. 답이 한 번에 드러나는 순간        600~960ms      카드가 뒤집힌다, 릴이 선다, 판이 열린다
2. 한 라운드 안에 여러 번 누르는 동작  250ms 아래     칸 파기, 한 칸 긁기, 문 열기
3. 답이 좁혀지며 드러나는 재생        2,000ms 아래   구슬이 떨어진다, 숫자가 오른다, 공이 나온다
```

**1의 "1초를 넘기면 느리다"는 지워지는 것이 아니라 무엇에 걸리는 규칙인지가 정해진 것이다.**
그 규칙은 **아는 데 걸리는 시간이 전부 공백인 경우**의 규칙이다. 카드가 뒤집히는 동안
플레이어는 아무것도 알아 가지 않으므로 그 시간은 짧을수록 좋다.

**3은 그 시간이 공백이 아니다.** 구슬이 한 줄을 내려갈 때마다 들어갈 수 있는 통이 줄고,
크래시의 숫자가 오를 때마다 내 목표에 가까워진다. **그 좁혀짐이 이 게임들의 내용이다.**
그래서 2026-11-06에 사용자가 **"핑코는 너무 빨리 끝나서 긴장감이 없다"**고 했다.
806ms는 1번 규칙을 정확히 지킨 값이고, **지킨 것이 틀린 것이었다.**

**3에는 두 가지가 같이 걸린다.**

| | | 왜 |
|---|---|---|
| 전체 상한 | **2,000ms** | 한 판이 끝나고 다시 누르기까지의 왕복. 넘기면 반복이 고역이 된다 |
| 한 단계 하한 | **70ms** | 60fps에서 4프레임. 그 아래는 단계가 뭉개져 한 줄기로 보인다 |

**3에 드는 것과 안 드는 것.**

```
든다    플린코 핀밭 · 크래시 상승 · 키노 추첨
안 든다 타워 전층 공개 · 지뢰 판 전체 공개
```

**타워와 지뢰의 전체 공개는 3이 아니라 1이다.** 떨어졌다는 답은 이미 나왔고 그 뒤는
「어디였나」의 설명이다. 좁혀지는 것이 없으므로 420ms 상한을 그대로 둔다.

`games/README.md` 5절대로 **한 패널의 숫자는 맨 위 `XX_T` 객체 하나에 모은다.**

### 상한을 넘기면 간격을 누른다. 꼬리를 자르지 않는다

전체 공개는 **상한 420ms** 안에 끝난다. 칸당·층당 간격을 곱해서 420을 넘으면
**간격을 `420 / 남은 개수`로 눌러** 마지막 하나가 정확히 420에 떨어지게 한다.

**뒤를 잘라서 맞추면 안 된다.** 지뢰는 숨은 칸이 최대 24개라 칸당 40ms면 960ms이고,
꼬리를 자르면 못 연 칸이 남는다. 타워에서는 더 분명하다. **못 간 층의 함정이 안 열리면
"거기였어"가 사라진다.** 그게 이 게임의 감정이고, 연출은 감정을 자르는 쪽으로 타협하지 않는다.

```
지뢰  숨은 칸 최대 24.  24 x 40 = 960 > 420  ->  간격을 눌러 420에 끝낸다
                        지뢰 뒤집기 180 + 420 = 600ms. 1초 예산 안
타워  9층 x 45 = 405 <= 420  ->  누르지 않는다. 45를 그대로 쓴다
```

**지켜야 하는 세 가지.**
1. `CUC.reduceMotion()`이면 **위 표를 전부 건너뛰고 최종 상태를 한 번에 그린다.**
2. 기다리던 응답이 아닌 것(늦게 온 것, 브로드캐스트)은 **연출 없이 있는 그대로** 그린다.
   연출하면 같은 카드를 두 번 돌리게 된다.
3. 거절된 동작은 아무것도 바꾸지 않았으므로 **아무것도 움직이지 않는다.**

## 7. 목록 화면: 4행에서 14행으로

### 지금 무슨 일이 생기나

행 하나가 `48(타일) + 8x2(padding) = 64px`다. 14행이면 **896px.**
한 화면에 안 들어간다. 그리고 지금 모든 행에 `sub` 두 번째 줄이 있는데,
14줄이 되면 그 줄은 거의 전부 `Min bet 10`이다. **14줄짜리 벽지다.**

### 결정 셋

**1. 네 묶음으로 가른다.** 묶음 머리는 `styles.js`에 이미 있는 `.sheet-sec` 레시피를 그대로 쓴다.
새 모양을 만들지 않는다.

```
Card tables     Blackjack · Red Dog · High-Low · Poker
Machines        Slots · Plinko · Wheel · Scratch Card
Boards          Mines · Tower · Keno · Crash
What you keep   Sword Forge · Market
```

`What you keep`은 남는 것을 모은 자루가 아니다. **창을 닫아도 남는 것을 가진 두 게임**이고,
그래서 이 두 행만 오른쪽에 숫자를 달 수 있다(아래 3번). 규칙이 묶음을 만든다.

```css
.gm-sec{font-size:10px;text-transform:uppercase;letter-spacing:.6px;color:var(--muted);
  font-weight:700;margin:14px 0 4px;padding:0 10px;}
.gm-sec:first-of-type{margin-top:2px;}
```

묶음 머리 4개가 더해져 총 ~960px. 줄어들지 않았지만 **14개를 훑는 일이 4개를 훑는 일이 됐다.**
타일을 줄여 높이를 줄이는 쪽은 택하지 않았다. 타일이 이 목록에서 유일하게 빨리 읽히는 것이고,
40px로 줄여 봐야 14행이 784px이라 **스크롤은 그대로 남고 그림만 작아진다.**

**2. `sub` 두 번째 줄은 기본으로 없앤다.** 다른 값을 가진 행에만 남긴다.

| 행 | `sub` |
|---|---|
| 지뢰 · 타워 | `Min bet 100` |
| 나머지 12개 | **없음** |

최소 판돈은 10 아니면 100 둘뿐이다. 12행에 `Min bet 10`을 적으면 그건 정보가 아니고,
2행에만 적으면 **"이건 비싸다"**가 된다. 타일이 높이를 64px로 잡고 있으므로
한 줄짜리 행도 두 줄짜리 행도 같은 높이다. 들쭉날쭉해지지 않는다.

환수율(96~97%)은 **행에 쓰지 않는다.** 14행이 전부 같은 값이고, 다른 데라면 몰라도
목록에서 그건 열네 번 반복되는 상수다. 필요하면 패널 제목의 `title=`에.

**3. 오른쪽 자리는 "내가 없는 동안 움직인 것"에만 준다.**

행 구조를 하나 늘린다. 셰브론 앞에 `.gm-fig`.

```html
<button class="gm-row" data-game="market">
  <span class="gm-ic">…타일…</span>
  <span class="gm-txt"><span class="gm-nm">Market</span></span>
  <span class="gm-fig gm-up">+1,240</span>        <!-- 있을 때만 -->

```
```css
.gm-fig{flex:none;font-size:11px;font-weight:700;color:var(--muted);
  font-variant-numeric:tabular-nums;white-space:nowrap;}
/* 어두운 테마: card #232326 위에서 5.70:1 / 6.26:1 */
.gm-fig.gm-up{color:#4fae74;}
.gm-fig.gm-dn{color:#f6836e;}

   흰 바탕에서 5.33:1 / 6.39:1 */
body.vscode-light .gm-fig.gm-up{color:#1f7a49;}
body.vscode-light .gm-fig.gm-dn{color:#b32a2e;}
```

> **펠트 색을 그대로 가져오면 밝은 테마에서 안 읽힌다.** 측정값:
> `#7ee6a4`는 흰 바탕에서 **1.53:1**, `#4fae74`는 **2.75:1**, `#e5484d`는 **3.91:1**로 전부 미달이다.
> 목록은 "방"이고 방은 테마를 탄다(4절). 펠트용 색을 방에 들이지 않는다.
>
> 참고로 `styles.js`의 `.xp-pop`이 이미 `#4fae74`를 `var(--card)` 위에 쓰고 있어서
> 밝은 테마에서 2.75:1이다. **이 문서의 범위 밖이지만 같은 결함이고, 따로 고칠 거리다.**

| 행 | `.gm-fig` |
|---|---|
| **시장** | 열린 포지션 손익 합. 부호 포함, 색 있음. **포지션이 없으면 아예 없다** |
| **대장간** | 보유한 검의 레벨 `+7`. 색 없음 |
| 나머지 12개 | **없다** |

**이게 "다시 들어올 이유"를 어떻게 띄우느냐에 대한 답이다.**
숫자가 두 행에만 있으면 그 둘이 움직이는 게 보인다. 14행에 다 깔면 아무것도 안 보인다.

> `.gm-fig`는 `--felt`류 고정색이 아니라 **테마를 타는 색**이다. 목록은 "방"이지 테이블이 아니다 (4절).
> 펠트용 `#7ee6a4`는 라이트 테마 바탕에서 1.6:1이다. 그대로 쓰면 안 된다.

## 8. 새 파일 둘을 어디에 꽂나

`games/tiles.js`와 `games/symbols.js`는 만들어 뒀다. 연결은 이렇게 한다.
**아래 네 군데 말고는 손댈 데가 없다.**

### 8-1. 타일 (목록 그림 10개)

**`games/<id>/meta.js`.** PNG가 있는 네 게임은 `thumb`을 그대로 두고,
새 열 개는 `thumb` 대신 `tile`을 쓴다.
```js
const tiles = require('../tiles');
module.exports = { …, tile: tiles.mines, /* thumb 없음 */ };
```

**`games/registry.js`의 `view()`.** 한 줄.
```js
icon: icon(g.icon) || '', thumb: g.thumb ? uri(g.thumb) : '', tile: g.tile || ''
```

**`html.js`의 `gameRow`.** `img`를 조건부로.
```js
<span class="gm-ic">${g.icon}${g.tile}${g.thumb ? `<img src="${g.thumb}" alt=""/>` : ''}</span>
```

**`games/casino.js`.** 두 줄. **순서가 중요하다.** `.gm-ic svg`(명시도 0,1,1)가
이미 `width:20px`을 걸고 있으므로 `.gm-ic .gm-tile`(0,2,0)로 덮어쓴다.
```css
.gm-ic .gm-tile{position:absolute;inset:0;width:48px;height:48px;display:block;}
.gm-row:hover .gm-ic img,.gm-row:hover .gm-ic .gm-tile{filter:brightness(1.1);}
```

`icon`은 타일이 있는 게임도 **계속 가지고 있어야 한다.** `CUC.frame()`이 패널 머리의 글리프로 쓴다.

### 8-2. 심볼 (슬롯·즉석복권)

둘이 합쳐 칸이 18개다. 마크업을 18번 붙이지 않는다.
**숨은 스프라이트 한 벌 + `<use>`**로 간다.

**`html.js`.** `<body>` 바로 다음에 한 줄.
```js
const symbols = require('./games/symbols');
… `<body>${symbols.sprite()}<div class="wrap">…`
```
```css
.sy-sprite{display:none;}   /* <symbol> 은 제자리에서 그려지지 않으므로 use 는 멀쩡히 된다 */
.sy-cell{display:flex;width:48px;height:48px;border-radius:6px;background:#15181c;}
.sy{width:100%;height:100%;display:block;}
```

**패널에서.** 심볼 문자열은 노드 쪽에 있고 패널은 웹뷰 쪽이라 `require`할 수 없다.
`<use>` 마크업은 문자열 조립이므로 패널에서 바로 쓴다.
```js
function cell(sym, word) {
  return '<span class="sy-cell" role="img" aria-label="' + CUC.esc(word) + '">'
    + '<svg class="sy" viewBox="0 0 24 24" aria-hidden="true"><use href="#sy-' + sym + '"/></svg></span>';
}
```

**그림은 `aria-hidden`이다. 심볼을 보여주는 쪽이 이름을 진다.**
픽셀 카드가 `CUC.cardWord`로 지키는 규칙과 같다. 심볼 이름 10개는 그대로 읽어 주면 된다.

### 8-3. 두 파일이 지키는 것

| | |
|---|---|
| 격자 | **24단위, 48픽셀로 그린다.** 단위당 2픽셀. 픽셀 카드(16x22@2px)·픽셀 동전(8x8@2px)과 같은 칸 |
| 다른 크기 | 24 / 48 / 72만. **44나 60은 모든 변이 반 픽셀에 앉는다** |
| 색 | 테마 변수를 안 쓴다 (4절). 양 테마에서 같은 그림 |
| `max-width` | **필요 없다.** 웹뷰 스타일시트가 100%로 가두는 건 `img`뿐이고 여기엔 `img`가 없다 |
| 모서리 | SVG가 둥근 모서리를 그리지 않는다. `.gm-ic`의 `overflow:hidden`이 자른다 |
| 열거 | `symbols.KEYS`로. `Object.keys(symbols)`는 **12개**다 (`KEYS`·`sprite`·`use` 포함) |

## 9. 만들기 전 확인

구현 담당자가 자기 화면에 대고 묻는 목록이다. 하나라도 "아니오"면 아직 아니다.

**정보 설계**
- [ ] 이 화면이 답하는 질문을 **한 문장**으로 쓸 수 있나. 못 쓰면 짓지 말고 물어라
- [ ] 그 답이 **화면에서 제일 큰 덩어리**인가. 흐리게 하고 봤을 때 그게 먼저 보이나
- [ ] 배당표를 `?` 뒤로 접었나. 펼쳐 둔 표가 없나
- [ ] 화면이 계산한 숫자가 하나도 없나. 배수·확률·배당·잔액 전부 `view()`가 보낸 것인가

**첫 수** (2026-11-06에 네 화면이 여기서 걸렸다)
- [ ] **처음 열었을 때 뭘 누를지가 펠트에 그려져 있나.** 문장 말고 물건으로 (2절)
- [ ] **Deal을 누르면 펠트가 바뀌나.** 베팅 화면과 진행 화면이 같은 그림이면 아직 아니다
- [ ] 누를 수 있는 것이 **펠트 대비 3:1 이상**인가. 눌렀던 것·아직 아닌 것과 세 단으로 갈리나
- [ ] hover가 실제로 보이나. 두 상태를 브라우저에서 나란히 재라 (지뢰는 1.22:1이었다)
- [ ] 화면에 쓴 문장이 있다면 **그것 없이 다음 수를 둘 수 없는 문장**인가.
      그리고 **자기가 가리키는 물건 옆**에 있나 (키노의 71px를 기억할 것)

- [ ] 가로 스크롤이 안 새나
