# 게 카지노 화면 규격

> 카지노는 게임 다섯 개다(2026-11-13). 이 문서는 **다섯이 한 가족으로 보이게 하는 규칙**이고,
> 열넷까지 늘렸다가 아홉을 폐지한 과정에서 재고 배운 값이 그대로 들어 있다.
> **없어진 게임의 화면 규격은 지웠지만, 그 게임에서 얻은 규칙과 실측값은 남겼다.**
> 규칙은 다음 화면에 걸리고, 실측값은 다시 재야 할 이유가 없다.
> 계약(파일 배치·엔진·메시지·검증)은 `games/README.md`에 있고 여기에 다시 쓰지 않는다.
> 이 문서는 **화면만** 다룬다. 충돌하면 계약이 이긴다.

구현 담당자가 읽는 순서는 이렇다.

```
1. games/README.md          무엇을 어디에 만드나
2. 이 문서 1~4절            폭·골격·바닥·테마. 다섯 화면이 공유하는 것
3. 이 문서 5절의 내 게임     무엇을 크게 보여주고 무엇을 버리나
4. 이 문서 6절              내 게임의 연출 밀리초
5. games/highlow/panel.js   가장 짧은 실제 예제. 베끼지 말고 구조만 볼 것
```

## 1. 폭: 재서 쓴 값

VS Code 탐색기 사이드바다. 가로 스크롤은 없고 사용자가 더 좁힐 수 있다.
아래는 추정이 아니라 `styles.js` + `games/casino.js`를 실제로 렌더해 잰 값이다.

| 사이드바 폭 | 펠트 바깥 폭 | **펠트 안 그릴 수 있는 폭** |
|---|---|---|
| 250 | 172 | **152** |
| 280 | 202 | **182** |
| 320 | 242 | **222** |
| 400 | 322 | **302** |

공식은 `펠트 안 = 사이드바 폭 - 98`이다.
(wrap 10x2 + card 15x2 + inner 14x2 + felt padding 10x2)

**설계 기준 폭은 182px(사이드바 280)이고, 152px(사이드바 250)에서 깨지지 않아야 한다.**

### 조작 줄에 버튼 몇 개가 들어가나 (측정값)

`.bj-btn`은 `flex:1 1 64px`, `.bj-ctl`은 `gap:6px`. 잰 결과는 이렇다.

| 버튼 수 | 한 줄로 유지되는 최소 사이드바 폭 |
|---|---|
| 2개 | 250 이하까지 |
| 3개 | **300** (280에서 두 줄로 접힌다) |
| 4개 | **360** |
| 칩 3개 + Deal | 260 |

> **High-Low는 지금 280px에서 이미 두 줄로 접힌다.** 버그는 아니지만 새 게임이 따라 할 이유도 아니다.

**규칙: 조작 줄의 버튼은 두 개까지.** 세 번째 동작이 필요하면 그것은 버튼이 아니라
펠트 위의 물건이어야 한다. 폐지된 게임들에서 실제로 그렇게 했다. 포커는 카드를 눌러 홀드했고
즉석복권은 칸을 눌러 긁었고 셧 더 박스는 타일을 눌러 닫았다. 셋 다 조작 줄에 버튼이
하나뿐이었고, 셧 더 박스는 **버튼이 0개**였다.
**이게 셋을 넘기지 않는 방법이다.** 남은 다섯은 전부 두 개 안이다.

## 2. 패널 골격

다섯 화면이 전부 쓰고 있는 뼈대다. **순서를 바꾸지 않는다.**

```
┌ .ihead.bj-head ──────────────────────────────┐  높이 ~18, margin-bottom 12
│ [←] 글리프 제목              우측 슬롯        │  CUC.frame(id) 가 만들어 준다
├ .bj-felt (또는 .fg-anvil, 또는 없음) ────────┤  padding 12/10, radius 12
│                                              │
│   이 게임이 답하는 것. 최대 블록이 여기 든다  │
│                                              │
│   .hl-line                                   │  min-height 22, margin-top 8
├──────────────────────────────────────────────┤
│ .bj-sr      (화면 밖, aria-live)              │
│ .bj-note    muted 11px                        │  margin-top 10, 보통 hidden
│ .warnbar    거절 사유                          │  보통 hidden
│ .bj-ctl     판돈 칩 + 버튼 (최대 2개)         │  margin-top 14, gap 6, 버튼 34px
└──────────────────────────────────────────────┘
```

**`.hl-line`이 펠트 안에 그려져 있는 것은 그림이 아니라 규칙이다.** 비어 있을 때 안 보이는 것은
**펠트가 뒤에 있기 때문**이고, 펠트를 걷은 화면에서는 같은 상자가 그대로 드러난다.
**그래서 바닥이 없는 화면에는 `.hl-line`을 두지 않는다.** 시장이 그랬다. 포지션을 들고 있으면
`mkLine()`이 빈 문자열을 넣어서 **빈 22px 상자(여백까지 30px)가 차트와 조작 줄 사이에 남았다.**
`.hl-line`이 지던 것은 **각자 집이 있다.** 판정 칩은 이미 있는 줄에 얹고(시장은 `.mk-conv`),
판돈 미리보기는 금액을 받는 칸이 이미 말한다.

### 각 자리에 무엇이 드나

| 자리 | 무엇 | 안 되는 것 |
|---|---|---|
| 좌측 화살표 | 한 걸음 뒤로. `CUC.frame`이 배선해 준다 | 손대지 않는다. **화면 안에 두 번째 뒤로가기를 만들지 않는다** |
| 제목 | `meta.title`, 또는 **지금 열려 있는 깊이의 이름**(`<key>Ttl`) | 규칙을 화면에 펼치지 않는다 |
| **우측 슬롯** (`.bj-side`) | **지금 이 깊이에서 가장 오래 쓰이는 숫자 하나.** 목록 깊이에서는 「내가 안 보는 동안에도 남아 있는 것」(시장 열린 손익 합), 깊이가 둘인 화면의 안쪽에서는 **그 깊이가 계속 읽는 숫자**(시장 종목의 현재가). 폐지된 화면에서는 대장간 `3 broken`, 즉석복권 `4 left` 가 여기였다 | 배당률·확률·승률. **본문의 최대 블록과 같은 숫자** |
| 펠트 | **이 화면이 답하는 질문의 답, 그리고 그 답을 얻으려고 누를 물건.** 판·릴·카드·바퀴 | 배당표, 설명문 |
| `.hl-line` | 판돈 또는 판정 칩. 한 줄, 최대 두 조각 | 세 번째 칩. **펠트가 없는 화면에는 두지 않는다**(위 단서) |
| `.bj-note` | 돈이 모자란 까닭 등. `CUC.note` | 상시 노출 안내문 |
| `.warnbar` | 호스트가 거절한 문장 그대로 | 화면이 지어낸 문장 |
| 조작 줄 | 베팅 화면은 칩+Deal, 진행 화면은 버튼 **2개까지** | 세 번째 버튼 |

### 뒤로가기는 하나다. 깊이가 둘이면 머리가 그걸 말한다

**화살표 하나가 한 걸음이다.** 화면 안에 깊이가 있으면 **머리의 화살표가 그 한 걸음을 먹고**,
안쪽에서 누르면 한 단계만 닫힌다. 배선은 패널의 `up` 한 줄이고 계약은 `games/README.md` 4절에 있다.

**두 번째 뒤로가기 버튼을 만들지 않는다.** 시장이 한동안 둘이었다. 머리의 화살표와 본문의
`← Coins` 였고, **깊이가 둘인 게임이 시장뿐이라 그건 선례가 아니라 예외였다.**
화살표가 둘이면 누르기 전에 둘을 구별해야 하고, 그 구별은 화면이 아니라 사람이 한다.
그 줄 하나가 25px이었다.

**그 대신 머리가 깊이를 말한다.** 안쪽에 있으면 **제목이 그 깊이의 이름**이어야 화살표가 무엇을
닫는지 읽힌다(시장은 종목 코드). 우측 슬롯은 그 깊이가 계속 읽는 숫자를 받는다(시장은 현재가).

```
[←] CRAB ·············· 288      종목 깊이
[←] Coin Market ······· +1,240   목록 깊이 (열린 포지션 합)
```

**같은 숫자를 머리와 본문에 같이 두지 않는다.** 시장의 머리 우측에 손익 합이 있었고,
포지션이 하나면 본문 최대 블록과 **44px 떨어진 같은 값에 같은 색**이었다. 둘 중 하나는 아무 말도 안 한다.

### 첫 수는 펠트 위의 물건이 말한다

**이 소절은 없어진 네 화면에서 얻은 규칙이다.** 2026-11-06에 사용자가 직접 해 보고
**네 게임(지뢰·타워·키노·크래시)을 "어떻게 하는지 모르겠다"**고 했고, **그래서 그 넷은
저장소에서 빠졌다.** 나머지 열은 안 걸렸다. 열넷을 같은 자로 재 보니 갈리는 선이 하나였고,
그 선이 아래다. **고칠 화면을 가리키는 것이 아니라, 새 화면을 지을 때 거르는 체다.**

**못 알아본 넷은 "안내문이 없는 넷"이 아니라 "펠트가 빈 넷"이었다.**
알아본 열은 펠트 안이 차 있었다. 딜러 게가 앉아 있거나, 릴·바퀴·은박 칸이
눌리기 전에도 거기 있었거나, 포커처럼 고르는 근거가 펠트 위에 펼쳐져 있었다.
못 알아본 넷 중 하나는 딜 전에도 딜 후에도 칸이 전부 투명이라
**Deal을 눌러도 화면이 바뀌지 않았다.** 안내문을 어디에 붙여도 그건 안 고쳐진다.

> **그래서 첫 수는 문장이 아니라 물건으로 말한다.**
> 누를 것은 **누를 수 있게 생겨야 하고**, 그러려면 눌리기 전에도 거기 있어야 한다.
> 덮인 칸은 덮개를 그리고, 닫힌 문은 문틀을 그린다. 바퀴가 돌기 전에도 바퀴인 것과 같다.

**문장은 물건으로 말할 수 없는 것에만 쓴다.** 열넷을 다 재 보니 그런 것은 둘이었다.
「몇 개를 골라야 하는가」(개수는 모양이 아니다)와 「이 숫자가 무엇인가」
(같은 자리의 같은 숫자가 목표였다가 결과가 된다). 둘 다 **한 줄 11px**이고, 그 줄은
**자기가 가리키는 물건에 붙어 있어야 한다.** 빠진 넷에서는 그 줄이 가리키는 물건에서
71px 떨어져 있어서, 줄이 있어도 둘이 이어지지 않았다.

### 누를 수 있는 것은 펠트 대비 3:1 이상이다

**하자 기준이고 취향이 아니다.** 빠진 넷에서는 지금 눌러야 할 것과 아직 아닌 것이
같은 색으로 읽혔고, 덮인 칸은 아무것도 그리지 않았으며, 마우스를 올려도 안 바뀌었다.
**세 단으로 갈리지 않으면 "지금 여기"가 없다.**

**새 색을 만들지 않고 `--felt-dim`의 불투명도로 세 단을 만든다.** 재서 쓴 값이다.

| 쓰임 | 값 | 펠트 대비 |
|---|---|---|
| 지금 누를 것 | `--felt-dim` 1.0 | **5.11:1** |
| 눌렀던 것 · 아직 안 연 것 | `--felt-dim` .7 | **3.33:1** |
| 이번 판에 내 것이 아닌 것 | `--felt-dim` .7 x 행 opacity .3 | 1.5:1 (일부러 흐리다) |
| hover · focus | `#e8895a` | 4.18:1 |

> **글자에 `font` 단축 속성을 쓰지 않는다. 세 속성을 따로 쓴다.**
> `font:700 10.5px inherit`은 **단축의 family 자리에 CSS 전역 키워드를 쓸 수 없어 선언 전체가
> 버려진다.** 한 줄이 조용히 사라지는 것이 아니라 그 줄이 정한 세 가지가 같이 사라지므로,
> 브라우저에서 재면 페이지 기본값(**13.33px · weight 400 · Arial**)이 나온다.
> 열넷 전부가 이것 때문에 2절의 「글자 여섯 종」을 깨고 있었다.
> **지금은 `games/casino.js`의 `.bj-why`를 포함해 저장소에 남은 자리가 없다**
> (`font-family` · `font-size` · `font-weight`를 따로 쓴 형태로 고쳐졌고,
> `grep -rn "font:" --include=*.js`가 내는 것은 `games/casino.js`의 경고 주석뿐이다).
> `font:inherit` 하나만 쓰는 것은 합법이라 그 자리는 그대로 둔다.
> **새 패널에서 이 단축을 다시 쓰지 마라.** 9절이 "상수 파일을 세지 말고 브라우저에서 세어라"라고
> 적어 둔 항목이 정확히 이것이다.

### 머리 글리프

`meta.icon`이 `icons.js`에서 고르는 열쇠다. **게임마다 서로 달라야 한다.**
목록에서는 48px 타일이 아이콘 자리를 덮으므로 겹침이 안 보이고, 겹치는 자리는 패널 머리 하나뿐이다.

| | |
|---|---|
| 크기 | `.ihead .it svg`가 **15x15**다. 24단위 박스가 0.625px/단위로 줄어드니 2단위 선이 1.25px이고, **2.5단위보다 가는 것은 사라진다** |
| 색 | `.ihead .it svg{color:#e8895a}`로 ember가 들어온다. 따라서 **`currentColor`만 쓴다** |
| 박힌 색 금지 | `warn` · `heart` · `coin`은 `fill`이 박혀 있어 저 규칙을 안 탄다. 머리에 쓰면 강조색이 둘이 되어 3절을 깬다 |
| 같은 물체 | `games/tiles.js`의 그 게임 타일과 **같은 물체**를 가리킨다. 타일이 탑이면 글리프도 탑이다 |

지금 쓰는 열쇠는 `icons.js` 아래쪽 블록에 게임별로 모여 있다.
새 게임이 생기면 **거기에 하나를 더하고, 기존 열쇠를 두 번째 게임에 돌려쓰지 않는다.**

### 치수는 이 값만 쓴다

```
간격      4 · 6 · 8 · 10 · 12 · 14          (.bj-ctl gap 6, felt padding 12/10)
반경      6 (작은 칸) · 8 (버튼·타일) · 12 (펠트)
버튼      높이 34, 최소 폭 64
칩 버튼   높이 28
글자      22 (영웅 수) · 16 (판돈) · 12.5 (제목) · 12 (버튼) · 11 (설명) · 10.5 (칩·우측 슬롯)
```

**글자는 이 여섯 종이 전부다.** 새 크기를 만들면 그 화면만 다른 화면이 된다.
`.mk-pl`이 그 화면의 최대 블록인 것은 그대로다. 크기를 키우는 것과 최대 블록인 것은 다른 일이다.

**예외는 둘이고, 둘 다 시장의 금액 칸이다.** 이 절은 「예외는 지금 없다」로 적혀 있었고
**그건 사실이 아니었다.** 세어 보면 시장이 렌더하는 글자 크기는 일곱 종이다.

| 예외 | 어디 | 왜 |
|---|---|---|
| 13px | `.mk-field input` | 직접 타이핑하는 칸. 12px은 입력 칸으로 작고 14px은 칩과 안 맞는다 |
| 11.5px | `.mk-seg button` | `cr`/`CRAB`/`25%`. 11px 칩보다 반 단계 위, 12px 버튼보다 반 단계 아래 |

**적어 두는 이유는 고치려는 게 아니라 세고 있으려는 것이다.** 1.31.0에서 금액 칸을 고칠 때
새 크기를 더하지 않았다(`.mk-plqty`는 12px). **일곱에서 더 늘지 않는 것이 이 표의 일이다.**

## 3. 바닥은 셋, 결은 셋

제안받은 결은 다섯이었다. **다섯이면 패널이 다섯 색으로 깜빡인다**는 지적이 맞다.
그래서 **배경이 바뀌는 횟수를 두 번으로 줄이고**, 결은 펠트 위에
**무엇이 놓이는가**로 가른다. 지금 주인이 있는 결은 셋이다.

### 바닥 (배경), 셋

| 바닥 | 토큰 | 쓰는 화면 | 왜 |
|---|---|---|---|
| 녹색 펠트 `.bj-felt` | `--felt` `--felt-lo` `--felt-ink` `--felt-dim` | 4개 (카드 2 · 기계 2) | 한 판이 올라가는 테이블 |
| **바닥 없음** | `.inner` 그대로 | 시장 1개 | 5-10절에 이유 |

> **바닥은 셋이었고 지금 둘이다.** 세 번째는 모루 갈색(`.fg-anvil`, `--forge` 계열)이었고
> 대장간 한 화면만 썼다. 2026-11-13에 대장간이 폐지되면서 `styles.js`의 `--forge` 토큰 네 개도
> 같이 걷혔다. **「작업장」 바닥이 다시 필요해지면 그때 토큰부터 다시 세운다.** 그 바닥의 규칙은
> 「테이블이 아닌 것은 펠트를 깔지 않는다」였고, 그 규칙은 시장(바닥 없음)에 그대로 살아 있다.

## 5. 게임별 정보 설계

각 항목의 형식은 같다. **질문 → 최대 블록 → 펠트 안 → 버리는 것 → 조작 줄.**

> **번호가 5-4 · 5-7 · 5-10 셋뿐이고 사이가 비어 있다.** 비어 있는 번호는 폐지된 게임의 자리고,
> 메타의 `order` 에 남겨 둔 빈 칸과 같은 이유로 안 메운다(7-2). 번호를 다시 매기면 이 문서를
> 가리키는 코드 주석이 전부 어긋난다.

> **화면은 계산하지 않는다.** 엔진이 보낸 것 중에서 고를 뿐이다.
> 배수, 확률, 배당, 잔액을 화면에서 만들지 않는다 (`games/README.md` 6절 1번).

공통으로 **버리는 것**이 하나 있다. **배당표는 어느 화면에도 상시로 깔지 않는다.**
`pays` · `ladder` · `ways` · `tables` · `fair`는 전부 `.hl-line` 아래의
`?` 토글 하나로 접어 두고, 한 줄 요약은 제목의 `title=`(`meta.hint`)에 넣는다.
상시로 펼치면 화면이 모두 표가 되고, 그러면 **무엇을 보라는 건지가 사라진다.**

### 이 금지가 첫 수까지 덮은 적이 있다. 가르는 질문은 하나다

> **빼고 나서도 플레이어가 다음에 뭘 누를지 아는가.**
> 알면 `?` 뒤로 접는다. 모르면 화면에 있어야 한다.

```
배당표      "이기면 얼마"          접는다
첫 수       "지금 뭘 누르나"       편다. 그리고 2절대로 문장이 아니라 물건으로
```

**둘은 같은 것이 아니다.** 배당표는 접어도 판이 돌아가고, 첫 수는 접으면 판이 멈춘다.
2026-11-06 전까지 이 절이 그 둘을 한 문장으로 묶어 둬서 **네 화면이 같이 접혔다.**
(그 넷은 폐지됐다. 규칙은 다음 화면에 걸린다.)

**값 하나가 양쪽에 걸치면 「그것 없이 다음 수를 둘 수 있나」로 가른다.** 예를 들어 휠의
슬라이스 목록 전체를 줄로 깔면 그건 배당표지만(접는다), **그 배수가 칸 위에 적혀 있는 것**과
범례가 말하는 **「그 배수가 판의 몇 할인가」**는 거는 판단의 근거다(편다, 5-7).
같은 배열이지만 전자는 표이고 후자는 물건이다.

> **포커(폐지)는 이 규칙을 처음부터 안 지키고 있었고, 그게 옳았다.** `.pk-pays` 아홉 줄은
> 모든 단계에서 펠트 맨 위에 펼쳐져 있었다. 포커에서 그 표는 배당표가 아니라 **어느 카드를
> 홀드할지 고르는 근거**였고, 빼면 다음 수를 둘 수 없었다.
> 사용자가 열넷 중 포커를 못 알아본 게임으로 꼽지 않은 이유 중 하나가 이것이다.
> **예외로 적어 둔 것이 아니라, 가르는 질문이 포커에서도 같은 답을 냈다는 뜻이다.**
> 남은 다섯 중에서는 휠의 범례가 같은 자리에 있다(5-7).

```html
<!-- 화면들이 공유하는 토글. .bj-note 자리 바로 위 -->
<button type="button" class="bj-why" id="xxWhy" aria-expanded="false">How it pays</button>
<div class="bj-pays" id="xxPays" hidden>...</div>
```
```css
/* 세 속성을 따로 쓴다. font 단축은 family 자리에 inherit 를 못 받아 선언 전체가 버려진다 (2절) */
.bj-why{margin-top:10px;padding:0;border:0;background:transparent;color:var(--muted);
  font-family:inherit;font-size:10.5px;font-weight:700;
  cursor:pointer;text-decoration:underline;text-underline-offset:2px;}
.bj-why:focus-visible{outline:2px solid #e8895a;outline-offset:2px;}
.bj-pays{margin-top:6px;font-size:10.5px;color:var(--muted);font-variant-numeric:tabular-nums;}
.bj-pays[hidden]{display:none;}
```

### 5-4. 슬롯 (slots) · 기계 · 최소 10

**질문.** 세 칸이 맞았나.

**최대 블록.** 릴 3개, 셀 **48px**, **창 높이 112px.** 셀 합이 `3x48 = 144`이고 남는 8px은
**양쪽 홈통 4px씩**이다. 합쳐서 152. **152는 사이드바 250에서의 펠트 안 폭과 정확히 같다.**
어느 폭에서도 들어간다. 48px은 심볼 격자(24단위)가 정확히 2픽셀/단위가 되는 유일한 값이다. 바꾸지 않는다.

**8px을 릴 사이에 쓰지 않는다.** 꺾쇠(아래)는 가운데 행의 **바깥**에 서야 하는데,
8px을 릴 사이 간격으로 쓰면 바깥에 남는 폭이 0이 된다. 8px은 두 곳에 있을 수 없다.
릴끼리의 구분은 **폭을 안 먹는 1px inset**으로 준다.

#### 창을 152에서 112로 잘랐다 (2026-11-13)

**줄인 것이 아니라 자른 것이다.** 가운데 48px은 그대로고 위아래 칸이 **각각 28px만** 보인다
(`28 + 4 + 48 + 4 + 28 = 112`). 셀은 48px이라 8-3의 「24 / 48 / 72만」 격자 규칙은 안 깨진다.

**왜.** 152px 창 안에서 당첨 줄은 48px 띠 하나였고, 그 띠가 어느 줄인지는 꺾쇠가 말했다.
112px이면 **당첨 줄이 창 그 자체**이고 위아래는 「지나가는 링」이 된다. 잉크 면적 26% 감소.
슬롯은 설계 기준 높이의 **183%로 저장소에서 제일 찬 화면**이었으니, 내줄 여유가 있는 쪽도 여기다.

**릴 사이 간격은 그대로 0이다.** 홈통 4px 두 개가 꺾쇠 자리라 거기 폭을 쓸 수 없다(위).
드럼으로 읽히게 하는 것은 위아래 **안쪽 그림자**(`.sl-reel:after`)이고, 그건 폭을 안 먹는다.

**펠트 안.**
- `.gm-plate` 슬레이트 판 위에 릴 3개.
- 각 릴은 **창(`.sl-reel`, 112px, overflow hidden) + 그 안에서 움직이는 띠(`.sl-strip`)**다.
  멈춰 있을 때 띠는 `reels[i].above` / `.sym` / `.below` 세 칸이고 가운데 칸이 창 가운데에 선다.
- **굴릴 때는 띠가 지나갈 링 전부를 들고 전환 하나로 미끄러진다.** 칸 피치 52px(48 + 간격 4).
  도착점의 가운데 칸이 **호스트가 준 `sym`**이므로 **멈출 때 다시 그릴 필요가 없다**
  (전환이 끝난 자리가 곧 정답이다). `innerHTML` 릴당 1회, 타이머 0, rAF 0.
- **70ms마다 창의 셋을 갈아 끼우지 않는다.** 그게 옛 방식이고, 5px 키프레임이 같이 떨고 있었다.
  셀이 48px·피치 52px인데 5px은 스크롤이 아니라 떨림이라 기계가 아니라 깜빡이는 격자로 보였다.
  그리고 420ms / 70ms = 6칸이라 **1/13,824짜리 게가 굴러가는 걸 한 번도 안 보여 주고 있었다.**
- 이동 칸 수는 **최고 속도를 세 릴에 똑같이 주고** 시간에서 나온다. 70심볼/초(3,640px/s,
  60fps에서 1.17셀/프레임)이고 이징의 peak/avg가 2.573이므로 **릴 1 = 14칸 · 릴 2 = 24칸(정확히
  한 링) · 릴 3 = 36칸(1.5링) · 릴 3 연장 = 45칸.**
- 당첨 줄은 가운데 행. **박스를 치지 말고** 양쪽 홈통에 ember 꺾쇠 두 개를 둔다.
  박스는 3칸을 하나로 묶어 버려서 "세 개가 맞았다"를 지운다.
- `.hl-line`: `win.kind`에 따라 칩 하나. `three`면 `.bj-chip.bj`, `pair`면 `.bj-chip`, `none`이면 비움.

#### 당첨 링은 셋이 한꺼번에 켜진다. 칩과 같은 순간이다

**릴마다 제 정지 시각에 켜면 릴 1이 520ms에 답을 말한다. 릴 3이 아직 돌고 있는데.**
세 칸이 같은 스핀에서 가장 나쁘고, 그게 이 게임이 유일하게 묻는 것이다.
`drawPlate(st, lit)`의 `lit`이 처음부터 그걸 받게 되어 있었고 **굴리는 경로만 그걸 안 타고 있었다.**
굴리는 동안은 `hit=false`, 켜는 것은 칩 시점 한 번뿐이다.
**그래서 세 번째 릴이 서는 순간이 처음으로 의미를 가진다.**

#### 두 칸이 같으면 세 번째 릴을 300ms 더 돌린다

`1,340 -> 1,640`, 칩 `1,460 -> 1,760`. 상한 2,000 안이다.

**조건은 `reels[0].sym === reels[1].sym`이다.** 그건 **이미 화면에 떠 있는 두 칸**만 읽은 것이고
(릴 2가 880에 서고, 연장이 보이기 시작하는 것은 1,340부터다), 플레이어가 보고 있는 사실을
연출이 따라가는 것이다. **세 번째 칸에 대해 아무 말도 하지 않는다.**

**`st.win`으로 읽으면 안 된다.** 그건 세 번째 칸을 읽은 것이라 선공개이고, 덤으로
**켈프 페어에서 안 걸린다**(`winOf`가 켈프 페어를 `NO_WIN`으로 돌린다).
눈에는 분명히 페어인데 연출이 모른 척하는 것이 되므로 조건으로 쓸 수 없다.

**켈프 페어 자체는 그대로 둔다.** 줄에 켈프 둘이 서면 링도 칩도 없다.
배당표의 `0x`가 그걸 설명하고 있고 의도다. 손대지 않는다.

**버리는 것.** `pays[6]`은 `?` 토글. `strips`는 그리는 데만 쓰고 보이지 않는다.

**조작 줄.** 판돈 칩 + **`[Spin]` 하나.**

### 5-7. 휠 (wheel) · 기계 · 최소 10

**질문.** 바퀴가 어디에 섰나. (돌기 전) 큰 배수가 판의 몇 할인가.

**최대 블록.** 원. 지름 **150px** 고정(152px 폭에서도 들어간다).

**바퀴는 보이는 것이다.** 어떤 칸이 어떤 배수인지는 돌기 전에도 보인다. 비밀은 어디 서느냐뿐이다.
그래서 원을 그린다. 가로 띠로 펴면 물건에 대해 거짓말이 된다.

**펠트 안.**
- `.gm-plate` 위 원. 쐐기는 **`conic-gradient` 하나**로 그린다(호스트가 준 칸 각도를 색 단계로).
  SVG 조각을 손코딩하지 않는다.
- **이 판만 좌우 패딩이 1px이다.** 공유 8px이면 `150 + 16 = 166 > 152`로 가로 스크롤이 샌다(3절).
- 12시에 ember 포인터 하나. **큰 배수 쐐기를 12시에 두지 말 것.**
  포인터와 겹쳐 하나의 화살표로 읽힌다 (`games/tiles.js`의 휠 타일에서 실제로 났던 일).
- **숫자는 판 안에 적는다.** `.wh-num`, 10.5px/700, 자기 칸의 중심 각도에 반지름 56px.
  꽝 칸도 `×0`을 적는다. 라벨이 없는 칸은 덜 그려진 판으로 읽힌다.
- **퍼센트를 쓰지 않는다.** 엔진이 `chance:{num,den}`으로만 보내고 **화면은 나누지 않는다**(5절 머리말).
  범례의 `4 of 30`이 그 두 수를 그대로 읽은 것이다.
- **범례는 없어지지 않고 역할이 바뀌었다.** 원 아래 `.wh-key`는 이제 「이 배수가 얼마를 주는가」가
  아니라 **「어떤 배수가 판의 몇 할인가」**를 말한다. 배수는 칸이 말하고 비율은 범례가 말하므로
  한 사실을 두 군데 쓰는 것이 아니다. 행은 **배수 한 종에 하나**이고 꽝 행은 `nothing`으로 맨 아래다.
  그래서 행 수는 바퀴마다 다르다(**mild 5 · medium 6 · wild 4**).
- `done`이면 `stop` 칸을 ember로 밝히고 포인터가 그 위에 선다. 그 칸의 숫자는 글자색을 어둡게
  뒤집는다(`.wh-num.on`). 솔리드 ember 위에서는 밝은 글자가 사라진다.
  **단 그건 바퀴가 도착한 뒤다. 아래 두 소절이 그 시점을 정한다.**

#### 켜진 쐐기·뒤집힌 숫자·`aria-label`은 1,800에 같이 온다

**셋 다 회전 시작 프레임에 와 있었다.** `drawFace()`가 회전을 시작하면서 `faceCss(w, stop)`을
넣어서, 멈출 칸이 회전 내내 솔리드 `#e8895a`로 칠해진 채 같이 돌았다. 죽은 쐐기 대비 **6.06:1**로
판에서 가장 밝다. **어디 설지 보는 게임인데 어디 설지가 첫 프레임부터 보였다.**
30단위 중 24가 꽝인 wild에서 가장 심했다.

```
회전 중    faceCss(w, null) · drawNums(w, null) · "Medium wheel, 11 slices, spinning"
1,800      faceCss(w, stop) · drawNums(w, stop) · "Stopped on slice N of M, ×3"
1,900      범례 행 점등 + 결과 칩
```

범례는 처음부터 제대로 막혀 있었다(`drawKey(wh.st, fresh ? null : stop)`). **그 패턴이 정본이고,**
쐐기·숫자·`aria-label`이 그걸 안 따르고 있었다.

#### 회전량을 정규화한다. 안 하면 ms가 스핀마다 다른 속도를 뜻한다

바퀴를 `-(spins x 3 x 360 + mid)`로 돌리면 **이동량이 새 칸 `mid`의 크기에 딸려 간다.**
세 바퀴에서 재면 **744~1,416도로 1.9배 흔들린다.** 한 지속 시간에 최고 속도가 1.9배 달라지므로
위 표의 ms가 스핀마다 다른 것을 뜻하게 된다.

**항상 앞으로 돈다.** `travel = 3 x 360 + ((mid_new - mid_prev + 360) % 360)`.
범위가 **1,080~1,428도(1.33배)**로 좁아지고, 덤으로 모든 스핀이 전진이 된다.
바퀴는 뒤로 안 돈다.

#### 라벨은 빠른 구간에서 비켜 있는다

반지름 56, 라벨 폭 17.98px에서 재서 정한 값이다.

| | |
|---|---|
| **1,100 deg/s 위** | 프레임당 29px로 토막 나서 끊겨 보인다. 1,800ms 곡선에서 **0~532ms** |
| **370 deg/s 아래** | 읽힌다. 곡선에서 **1,130~1,800ms** (670ms) |

`.wh-nums`에 `@keyframes whLabels` 하나. `0% opacity:1 -> 10% 0 -> 30% 0 -> 63% 1 -> 100% 1`이고
퍼센트가 1.8s 기준의 실제 시각이다(10%=180 가속 끝, 30%=540 1,100 통과, 63%=1,134 370 통과).
그래서 애니메이션 자체는 `linear`다.
**라벨이 돌아오는 순간이 「이제 읽어라」가 된다.**

**`filter: blur`를 쓰지 않는다.** CSS 블러는 등방이라 속도가 아니라 안개로 보이고,
쐐기까지 같이 흐려진다.

#### 마지막 한 바퀴를 별도 단계로 넣지 않는다

**감속 꼬리가 이미 그 일을 한다.** 1,800ms 곡선에서 남은 24도(최소 칸 하나)에 **330ms**,
12도에 237ms가 걸린다. 최소 칸에 들어가는 순간이 끝나기 237ms 전이고, 그 뒤 칸 하나를 기어서
통과한다. **「거의 멈출 듯하다가 한 칸 더 가는」 것이 이 구간이고 꾸며낸 것이 아니다.**

**멈췄다가 다시 한 칸 가는 연출은 넣지 않는다.** 끊긴 프레임과 구별이 안 되고,
멈춘 한 박자 동안 앞 칸이 답처럼 보인다.

#### 숫자가 판 안으로 들어간 경위 (2026-11-06)

**이 절은 오래 "숫자는 원이 아니라 범례가 진다"고 적어 두었다. 지금은 반대다.**
사용자가 **"돌림판 안에 ×2, 나누기2 이런 식으로 적혀 있는 게 좋지"**라고 해서,
**28칸 등분**을 **30단위 x 12도의 가변 폭 칸**으로 바꾸고 배수를 칸 위에 올렸다.
옛 근거("한 칸이 호 18px이라 글자가 안 들어간다")는 **등분에 대한 주장이었고, 등분이
사라지면서 같이 사라졌다.** 아래는 `wheel.js`와 `games/wheel/meta.js` 머리말의 실측이다.

| | |
|---|---|
| 칸의 하한 | **24도**(2단위). 라벨이 실제로 요구하는 것은 20.4도이고, 24도는 여유를 둔 값이다 |
| 호와 글자 | 가장 좁은 칸이 이 크기에서 호 **31px**, 가장 넓은 라벨 `×12`가 10.5px/700에서 **17.98px** |
| 배수의 천장 | 칸이 2단위보다 얇아질 수 없으므로 **×14.5가 상한이다. 옛 `×20`은 이제 만들 수 없다** |
| 환수율 | `Σ(폭 x 반배수) / 60` = **58/60 = 96.6667%.** 96~97% 밴드 안의 정수 분자는 **58 하나뿐** |
| 세 바퀴 | 칸 수 mild 13 · medium 11 · wild 9. 꽝이 30단위 중 **4 · 16 · 24** |
| 홀수 판돈 | `÷2` 칸이 있어 배수를 반 단위 정수로 들고 있고, 그래서 **엔진이 홀수 판돈을 거절한다** (`bet % 2`). 칩이 10 · 100 · 1000이라 지금 막히는 조작은 없다 |

**큰 배수는 "희귀한 한 칸"이 아니라 "얇은 한 칸"이다.** 폭이 곧 확률이라
배수를 키우는 방법이 칸을 얇게 하는 것뿐이고, 그 얇기의 바닥이 라벨 한 줄이다.
**화면이 라벨 문자열을 만들지 않는다.** 엔진의 `labelOf`가 정한 것을 그대로 찍는다.

**버리는 것.** 칸 목록 원본은 색과 각도로만 쓴다. `top`은 범례 첫 행이 이미 말한다.

**조작 줄.** **`[Deal]` 다음에 `[Spin]`, 두 단계다.** 엔진이 바퀴 종류를
`act(st,{op:'spin',risk})`에서 받으므로 베팅 화면에서 바퀴를 고르고 `[Spin]` 하나로 끝낼 수 없다.
블랙잭이 `[Deal]` 다음에 `[Hit]`·`[Stand]`를 받는 것과 같은 두 단계이고,
한 줄에 버튼은 여전히 두 개까지다.

### 5-10. 코인 시장 (market) · 바닥 없음

**질문.** 지금 내 포지션이 얼마인가. 그리고 들어갈까, 나올까.

**이 화면만 다른 이유가 둘 있고, 둘 다 취향이 아니다.**

1. **한 판이 없다.** deal도 settle도 없고 라운드가 없다. 펠트는 "이 테이블에 한 판이 올라가 있다"는
   뜻이고, 시장에는 올릴 판이 없다.
2. **캔들은 위가 녹색, 아래가 빨강인 것이 전부다.** 녹색 펠트 위에서는 빨강만 사건으로 읽히고
   녹색은 바닥의 일부가 된다. (대비는 7.03:1로 충분하다. 문제는 대비가 아니라 **색의 정체성**이다.)

그래서 펠트를 걷고 `.inner` 위에 **차트 우물** 하나를 판다.

```css
.mk-well{padding:8px;border-radius:10px;background:var(--inner);
  box-shadow:inset 0 0 0 1px var(--iborder);}
```

#### 이 화면이 쓸 수 있는 폭은 다른 화면보다 넓다

**펠트가 없으므로 1절의 `−98`이 아니라 `−78`이다.** 펠트 좌우 패딩 10x2가 빠진다.
아래는 `.inner.mk`를 실제로 렌더해 잰 값이다.

| 사이드바 | `.inner.mk` 안 | `.mk-well` | **`.mk-chart`** |
|---|---|---|---|
| 250 | 172 | 172 | **156** |
| 280 (설계 기준) | 202 | 202 | **186** |
| 320 | 242 | 242 | **226** |

> 이 절은 오래 **차트를 182x110이라고 적어 두었다.** 그 182는 펠트 안 폭이고 시장에는 펠트가 없다.
> 실측은 **186x110**이다. 슬롯·몸통 수치도 182로 계산돼 있었으므로 아래 표가 정본이다.

**깊이를 말하는 것은 머리다.** `.mk-crumb`(`← Coins · CODE · 현재가`)은 없다. 2절
「뒤로가기는 하나다」가 그 근거이고, crumb이 지던 셋은 전부 머리에 자리가 있다.
코드는 제목, 현재가는 우측 슬롯, 되돌아가기는 그 화살표다.

**`.hl-line`도 없다.** 2절의 단서가 그 근거다. 이 화면은 펠트를 걷었으므로 빈 줄이 그대로 보인다.
거래 판정 칩은 `.mk-conv` 줄이 받고, 판돈 미리보기는 금액 칸이 이미 말한다.

#### 등락률은 목록 행에 박는다. 툴팁이 아니다

**결함이었다.** `chgBp`가 `aria-label`과 `row.title`에만 있어서 **마우스를 올려야 보였다.**
목록 행은 네 종목 중 어느 것을 열지 고르는 자리이고, 그 결정을 하는 숫자가 등락률이다.

**자리는 1줄, 현재가 바로 오른쪽이다.** 2줄(스파크라인 옆)에 둔 안을 같이 그려서 버렸다.
2줄에 두면 **등락률과 손익 칩이 6px 간격으로 나란히 서서**, 부호와 색을 가진 숫자 둘이
한 덩어리로 읽힌다. 어느 쪽이 시장이고 어느 쪽이 내 돈인지 안 갈린다.
1줄에 두면 **위 줄은 시장, 아래 줄은 그림과 내 것**으로 갈린다.

**들고 있는 종목은 둘 다 필요하다.** 등락률은 네 행이 같은 기준으로 비교되는 시장의 숫자이고,
손익 칩은 내 매수가 기준의 내 돈이다. 다른 사실이라 한쪽이 다른 쪽을 대신하지 못한다.
**다만 줄이 다르다.** 칩은 지금처럼 들고 있을 때만 2줄 오른쪽에 뜬다.

```html
<span class="mk-r1">
  <span class="mk-nm">Shelliba</span>
  <span class="mk-px">692</span>
  <span class="mk-chg mk-u">+3.0%</span>
</span>
<span class="mk-r2">
  <span class="mk-spark"><!-- 40x16 svg --></span>
  <span class="mk-fg"><!-- .bj-chip.still, 들고 있을 때만 --></span>
</span>
```

**사이드바 250에서 재서 들어간다.** 고정폭은 현재가 36.41(`1,507`) + 등락률 46 + 좌우 패딩 12 +
gap 12 = 106.4px이고, 172px에서 이름에 **73.9px**이 남는다.
가장 긴 이름이 12.5px bold로 **61.3px**(옛 `Shellback`)이라 잘리지 않는다(여유 12.6px).
1.31.0의 네 이름(`Tidether` `Kelpereum` `Shelliba` `Crabidia`)도 모두 그 한계 안이다.
**현재가는 이 폭 때문에 목록에서만 정수다.** `1,434.13`은 56.69px이라 이름을 먹는다(5-10절).

**등락률 칸은 `min-width:46px`로 고정한다.** 재 보면 `±X.X%`가 37.7px, `±XX.X%`가 45.2px이다.
고정하지 않으면 한 자리에서 두 자리로 넘어갈 때마다 **현재가가 7.5px 옆으로 흔들린다.**

#### 기간 칩: 4개, 기본은 1D

**주식 앱의 1D/1W/1M/1Y/ALL을 그대로 베끼지 않는다.** 이 시세는 그보다 잔잔하고,
무엇보다 **1Y는 그릴 수가 없다.** 아래가 재서 정한 네 칸이다.

| 칩 | 창 | `stepMs` | `count` | 캔들 | slot@280 | 몸통@280 | slot@250 | 몸통@250 |
|---|---|---|---|---|---|---|---|---|
| `3H` | 3시간 | 5분 | 36 | 5분봉 | 5.17 | 3.19 | 4.33 | 2.67 |
| **`1D`** | **24시간** | **60분** | **24** | **1시간봉** | **7.75** | **4.80** | **6.50** | **4.02** |
| `1W` | 7일 | 6시간 | 28 | 6시간봉 | 6.64 | 4.11 | 5.57 | 3.44 |
| `1M` | 30일 | 24시간 | 30 | 일봉 | 6.20 | 3.84 | 5.20 | 3.22 |

**캔들 개수를 36으로 고정하지 않은 이유.** 고정하면 1W가 280분봉, 1M이 20시간봉이 되어
**사람이 이름 붙일 수 없는 단위**가 된다. 위 네 줄은 전부 5분·1시간·6시간·1일이고,
그 대신 개수가 24~36으로 움직인다. 슬롯은 **250px에서도 4.33px 아래로 내려가지 않는다.**

**캔들은 자기 보폭의 격자에 박혀 있고, 가장 새 칸만 진행 중이다**(1.31.0).
`count` 중 `count-1`개는 **완성된 칸**이고 마지막 하나는 `[격자, 지금)` 구간의 **부분 칸**이다.

> **옛날에는 끝에 매달려 있었다.** 캔들 i 의 끝이 `끝분 - i*보폭`이라
> **끝이 1분 움직이면 24칸이 전부 한 칸씩 밀렸다.** 1D(1시간봉)에서는
> **90초 동안 24칸 전부가 다시 그려지는데 가장 새 종가는 1시간에 한 번** 움직였다.
> 그림은 계속 밀리고 숫자는 멈춰 있는 것이 이 화면이 죽어 보이던 기계적 원인이다.
>
> 격자에 박으면 격자 사이에 변하는 것은 **마지막 칸 하나**이고,
> 등락률의 기준(`rows[0].o`)도 **격자마다**만 움직인다.
> 가격이 안 움직여도 등락률이 흔들리던 것이 같이 고쳐진다.
>
> **부분 칸을 채우지 않는다.** 폭이 0인 칸(격자가 막 넘어간 순간)도 그대로 그린다.
> 그 칸의 종가가 **지금 거래되는 가격**이고, 그게 이 화면의 유일한 뉴스다.

**네 칩 모두 심지가 있다.** 엔진이 캔들 하나를 `WICK_SAMPLES`(8)번 샘플링하므로
고저가 시종가와 갈린다. **1.31.0 에서 격자가 1/64분이 되면서 다시 쟀다**(종목 4개 x 창 50개 평균).

| | 3H | 1D | 1W | 1M |
|---|---|---|---|---|
| 1분 격자 | 28.3/36 | 20.9/24 | 25.8/28 | 26.1/30 |
| **1/64분 격자** | **32.4/36** | **20.4/24** | **24.8/28** | **25.6/30** |

**3H 만 크게 올랐고, 그게 맞다.** 5분봉에서 옛 샘플 위치는 `round(j*5/8)` 분이라
7개 중 3쌍이 같은 분에 겹쳐 **서로 다른 분이 넷**뿐이었다. 노드 격자에서는 여덟 개가
전부 다른 시점이다. 1M(일봉)은 `1440*64/8`이 정확히 180분이라 **옛 위치와 같아서 안 변한다.**

**1분봉도 이제 심지가 있다.** 1분이 64노드이므로 다른 봉과 같이 8번 샘플링된다.
옛 격자에서는 1분봉의 고저가 **시종가 그 자체**였다(`market.js`의 `VIEW_STEP_MS` 주석).

**기본값이 1D인 이유는 둘이다.**

1. **코인이 자기를 소개하는 단위가 하루다.** `?` 토글이 `moves about 4% a day`라고 말하고
   `grade`도 그 축이다. 거기에 `1D −2.7%`가 붙으면 한 문장으로 읽힌다.
2. **3H는 숫자가 잡음으로 읽힌다.** 표본 40회의 중앙 |등락|을 재면 이렇다.

   | | 3H | **1D** | 1W | 1M |
   |---|---|---|---|---|
   | TIDE (calm) | 0.36% | **0.81%** | 2.13% | 8.29% |
   | KELP (steady) | 0.51% | **1.71%** | 4.87% | 16.30% |
   | SHEL (choppy) | 0.64% | **2.76%** | 8.61% | 27.58% |
   | CRAB (wild) | 1.46% | **2.71%** | 10.15% | 30.21% |

   3H는 네 종목이 0.4~1.5%에 몰려 **서로 구별되지 않는다.** 1D에서 갈리기 시작한다.

**`1Y`와 `ALL`은 넣지 않는다. 취향이 아니라 거짓말이 되기 때문이다.**
가격 함수의 시작점은 `EPOCH_MS = 2026-01-01`이고 그 이전 분을 물으면 **전부 기준가 그대로**가 온다.
2026-11-06 기준으로 365일 창은 **왼쪽 15%가 엔진이 시작하기 전**이고,
실제로 그려 보면 36개 중 **5개가 고=저인 죽은 캔들**이다. 1M이 상한이다.

#### 기간 칩은 차트 바로 위에 둔다. 조작 줄에는 들어가지 않는다

`.bj-ctl`은 **버튼 두 개까지**이고(1절) 거기엔 이미 판돈 칩 3개와 `[Buy]`가 있다.
기간은 돈을 쓰는 동작이 아니라 **보는 법**이므로 보는 것 옆에 붙는다.

```
.mk-plbox            (들고 있을 때만) 손익 · 수량 · 설명
.mk-spanrow          [3H][1D][1W][1M] ············ +19.1%     ← 여기
.mk-well             캔들 차트 + low/high
.mk-amt              [ 41000   cr|CRAB ]  /  [25%][50%][Max]  두 줄 70px
.mk-conv             환산 한 줄, 또는 거래 판정 칩
.bj-ctl              [Buy] / [Sell]
.bj-why / .bj-pays
```

**차트 아래가 아니라 위다.** 아래에 두면 금액 칸과 조작 줄 사이에 세그먼트 컨트롤이
두 개 연달아 쌓여, 바로 아래 세그먼트와 **같은 모양 두 줄**이 된다.
위에 두면 읽는 순서가 `무엇을 · 어느 창으로 · 그래서 이 모양`이 된다.

**`.bj-stakes`를 그대로 쓰지 않는다.** 재 보면 이렇다. 기준은 사이드바 250, 폭 **172px**이다.

| 컨트롤 | 칸 수 | 폭 | 등락률 45.2 + gap 6 을 올리고 남는 것 |
|---|---|---|---|
| `.bj-stakes` 그대로 (12px, 좌우 9) | 4 | 157.6 | **−36.8. 못 선다** |
| **`.mk-span` (11px, 좌우 5)** | **4** | **120.0** | **+0.8** |
| `.mk-span` | 5 | 149.5 | **−28.7. 못 선다** |

**그래서 칩은 네 개가 상한이다.** 기간 세트를 넷으로 정한 것은 취향이 아니라 이 표다.

**남는 0.8px은 세 자리 등락률이 먹는다.** `±XXX.X%`는 52.6px이라 7.4px이 모자란다.
표본 400회에서 **1M의 최대 |등락|이 64.4%**라 사실상 안 나오지만, 나올 때를 위해
`.mk-span`에 `flex:0 1 auto; min-width:0`을 준다. **칩 쪽이 눌리고 숫자는 안 잘린다.**

**세그먼트 대신 배경 없는 글자 줄로 만드는 안을 그려서 버렸다.** 더 가볍지만
선택 표시가 ember 글자가 되어, 바로 아래 판돈 칩의 선택 표시(`.on` = `--card` 바탕)와
**한 패널 안에서 "골라진 것"의 표현이 둘**이 된다. 그리고 클릭 타깃이 29x20px로 작아진다.

#### 등락률이 무엇 대비인지는 기간 칩이 말한다

지금은 `창 시작 대비`인데 **그 말이 화면 어디에도 없었다.**
이 게임에는 "전일 종가" 같은 자연스러운 기준이 아예 없으므로, **창을 정하면 기준도 정해진다.**
그래서 한 마디를 더 쓰지 않고 **자리로 푼다.**

- **종목 화면.** 등락률을 **기간 칩과 같은 줄, 오른쪽 끝**에 둔다. `1M ····· +19.1%`가
  한 줄로 읽힌다. **머리에는 넣지 않는다.**
- **목록 화면.** 기간 컨트롤이 없으므로 **창 이름 한 마디**를 목록 머리 오른쪽 끝에 둔다.
  `last 3h` · `last 24h` · `last 7d` · `last 30d`. 10.5px muted, 등락률 열과 오른쪽이 맞는다.
  이것이 네 행 전부의 기준을 한 번에 말한다.
- **스크린리더.** 행과 차트의 `aria-label`은 창 이름을 풀어 쓴다.
  `Shelliba, 692, up 3.0% over the last 24 hours, nothing held`.
  (창 이름이 상수표에 있으므로 패널의 `spanOf()`는 지울 수 있다. 캔들 간격을 되읽어
  "168 hours" 같은 문장을 만들던 함수다.)

> **crumb에서 등락률을 뺀 것은 결함 수정이었고, 지금은 crumb 자체가 없다.** 당시의 계산은
> 이렇다. 사이드바 250에서 crumb은 `← Coins`(61.1) + 현재가(24.2) + 등락률(37.7) + gap 18 = 141로
> **종목 코드에 31px만 남았고**, `CRAB`은 37px이 필요해서 **`K…`로 잘렸다.**
> **그 줄이 머리로 올라가면서 이 계산은 끝났다.** 머리에는 `← Coins` 가 없고(화살표가 그 일을
> 한다) 등락률도 없으므로, 코드가 쓰는 폭은 화살표와 현재가를 뺀 나머지 전부다.

#### 기간은 화면이 고르고 창은 호스트가 만든다

**패널이 `{stepMs, count}`를 보내지 않는다. 칩의 키만 보낸다.**

```js
CUC.post('mk', 'open', { span: '1D' })      // '3H' | '1D' | '1W' | '1M'
```

`games/market/meta.js`가 키를 `SHAPE` 표에서 찾아 `view()`에 넘기고, **모르는 키는 기본값**으로
떨어진다. 지금 그 파일에 상수 하나로 있는 `SHAPE`가 네 줄짜리 표가 되는 것뿐이다.

**이유 둘.** 하나는 지금 `SHAPE`에 적혀 있는 그대로다. **한 파일이 "무슨 창이 화면에 있나"에 답한다.**
다른 하나는 `count`가 240까지 허용된다는 것이다. 웹뷰가 보낸 수를 그대로 넘기면
한 번의 `open`이 코인 4개 x 240캔들 x 샘플 8 = 7,680번의 가격 계산이 된다.
**호스트가 고르면 그 입력은 존재하지 않는다.**

**선택한 기간은 `meta.js`가 기억한다.** `onPush`로 나가는 **아무도 묻지 않은 갱신**이
기본 창으로 되돌아가면, 1M을 보고 있던 화면이 1분마다 3H로 튄다.

**기간은 한 벌이고 두 깊이가 같이 쓴다.** `view()`는 한 번에 코인 넷을 모두 그리고
`chgBp`는 그 창의 첫 시가 대비이므로, **목록의 네 등락률도 같은 창을 따라간다.**
그것이 맞다. 목록은 네 종목을 **서로 비교**하는 자리고, 기준이 행마다 다르면 비교가 안 된다.

#### 최대 블록은 상태에 따라 바뀐다

이 화면에서만 그렇고, 그게 맞다.

- **포지션이 있으면** → 손익이 최대 블록. **22px**, 부호 포함, win/lose 색. 차트는 그 아래.
  내가 안 보는 동안 움직인 것이 그 숫자다. **이게 다시 들어올 이유다.**
- **포지션이 없으면** → 차트가 최대 블록. 손익 자리는 비운다. 0을 띄우지 않는다.

**그 자리에 손익을 두는 결정은 그대로다. 크기만 22px로 내렸다**(2절). 26px은 저장소에서
그 한 곳만 쓰는 크기였고, 그 크기를 쓰던 화면이 **제일 긴 화면**이기도 했다.

**수량은 자기 줄을 가진다**(1.31.0). `347.9 CRAB`, 12px/700 `--text`.
들고 있는 사람이 묻는 것이 그건데, 네 가지를 밀어 넣은 11px muted 줄의 **첫 어절**이었다.
`.mk-plbox`는 이 줄로 4.00px 늘고, 아래 줄이 두 줄에서 한 줄로 줄어 **실질 +4px**이다.
12px은 2절의 여섯 종 안이다. 여러 번 산 경우의 `· 3 buys`가 이 줄 뒤에 붙는다.

**아래 한 줄에 퍼센트를 적지 않는다.** `1,000 in · 299.49 avg · 15s` 까지다.
**`at avg 287 (3 buys)` 꼴로 길게 쓰지 않는다.** 사이드바 250에서 208.22px이 되어 두 줄이 된다.
손익률(`plBp`)을 여기에 적으면 **29px 아래 기간 줄의 시장 등락률과 부호·색이 같아서**
둘이 한 덩어리로 읽히고, 어느 쪽이 내 돈이고 어느 쪽이 시장인지 안 갈린다.
**이것은 목록 행에서 이미 지키던 규칙이고**(위 「등락률은 목록 행에 박는다」),
종목 화면에서만 안 지켜지고 있었다. `held`는 남긴다. 분마다 움직이는 숫자가 그것이다.

**목록 행의 손익.** 포지션을 들고 있는 종목만 2줄 오른쪽에 `+1,240` 칩(`.bj-chip.still`, 49.3px).
없는 종목은 **아무것도 없다.** 4행 전부에 `0`을 깔면 숫자가 넷이 되고 그 중 하나가
움직인다는 사실이 안 보인다. 등락률은 반대로 **네 행 전부에** 있다. 그게 비교되는 숫자다.

#### 안 넣는 것 둘

**캔들 스크러빙(캔들에 마우스를 올리면 그 시점 값).** 넣지 않는다.
**슬롯이 가장 넓은 1D에서도 7.75px이고 3H에서는 4.33px이다.** 5px짜리 적중 영역은
마우스로도 겨냥이 안 되고, 키보드로는 들어갈 길이 아예 없다(차트는 `<i>` 더미다).
그리고 스크러빙이 줄 값은 **이미 `.mk-ax`의 `low` / `high`가 말하고 있다.**

**`baseBp`(기준가 대비)를 화면에 올리는 것.** `?` 토글 안에 그대로 둔다.
이 게임에는 "전일 종가"가 없는 대신 **기준가와 밴드(base/8 ~ base x8)**가 있어서
주식의 52주 범위 같은 역할을 할 수는 있다. 하지만 **그 역할은 `1M` 칩이 이미 한다.**
30일 창의 고저 폭 중앙값은 12.8%(TIDE)에서 57.2%(CRAB)로, 이 코인이 어디쯤 있는지가
**숫자 하나가 아니라 그림으로** 나온다. 둘 다 올리면 같은 질문에 답이 둘이 된다.

#### 그대로 가는 것

**차트는 라이브러리 없이 그린다.** 절대배치 `<i>` 몸통 24~36개 + 심지.
백분율 배치라 리사이즈 훅이 없다. 의존성 0이 이 저장소의 설계다.

**수수료는 한 번만 말하고, 그 한 번은 `?` 접힘 안이다.**
`Round trip 0.5%, taken when you sell · stake 10 to 2,500,000`.
**상시 노출하지 않는다.** 매수 버튼 아래 11px muted로 깔려 있었고, 그건 어느 깊이에서도
어느 상태에서도 같은 한 문장이라 **화면이 자기를 해설하는 줄**이었다. 쟀더니 설계 기준
폭에서 19px, 사이드바 250에서는 두 줄이 되어 **32px**이었다.
**그 숫자는 화면이 만들지 않는다.** `view()`의 `feeBp`로 온다(지금 **50 = 0.5%**).
패널에 수수료 문자열을 박으면 다음에 수수료를 바꿀 때 화면만 틀어진다.

**`?` 접힘은 조작 줄 아래다.** 이 화면만 그렇고, 그게 맞다. 위에 두면 **차트와 그 차트에
대고 누르는 버튼 사이**에 설명문이 끼어 흐름을 끊는다. 다른 넷은 펠트 바로 아래가
`.hl-line`·`?`·조작 줄 순서고, 거기선 `?`가 판과 버튼 사이가 아니라 **판이 끝난 자리**에 있다.
여백은 `.mk .bj-why{margin-top:12px}`. 34px 버튼 아래는 10px이 좁다.

**조작 줄.** `[Buy]`, 또는 들고 있으면 `[Add]`와 `[Sell]` **둘 다.**
**1.23.0에서 「들고 있는 코인을 또 사기」가 들어오면서 동시에 둘이 된다.** 이 절은 그때까지
「하나씩이고 동시에 둘이 뜨지 않는다」로 적혀 있었고, **규격이 코드보다 낡은 상태였다.**
둘은 1절의 상한(버튼 두 개)에 그대로 들어가고, 기간 칩은 이 줄에 없으므로 상한은 안 깨진다.

> **라벨이 `Buy more`가 아니라 `Add`인 것은 재서 정한 것이다.** 사이드바 250에서 버튼 하나가
> 83px이고 글자가 쓸 수 있는 폭은 **71px**이다. `Buy more 100`은 12px/700으로 그 폭에
> 안 들어가서 **34px 버튼 안에서 두 줄로 접혔다**(1절 위반). `Add 100`이 44.8px,
> `Add 100,000`이 70.1px으로 **`Buy 100,000`(69.0px)과 같은 범위**다.
> 즉 두 번째 버튼이 첫 번째 버튼에 없던 폭 문제를 만들지 않는다.

**우측 슬롯.** 목록 깊이에서는 열린 포지션 전체의 손익 합(없으면 빈다),
종목 깊이에서는 **그 종목의 현재가, 틱 2자리**(`299.49`)다. 2절 「뒤로가기는 하나다」가 그 근거다.

> **왜 소수 둘인가.** 1틱은 1/100 크레딧이고 1.31.0부터 가격이 1/64분마다 움직인다.
> 정수 크레딧으로 반올림하면 **1초마다 숫자가 바뀔 확률이 5.3~8.4%**이고
> 틱으로 찍으면 **94.3~96.2%**다(종목별 2만초 실측. 옛 1분 격자에서는 둘 다 1.7%).
> 격자를 쪼개 놓고 화면이 반올림하면 **쪼갠 것이 안 보인다.**
> 같은 이유로 `.mk-ax`의 low/high, `.mk-plsub`의 진입가, 판정 칩의 진입가가 모두 틱 2자리다.
> **항상 두 자리**다. `271.20`은 `299.49` 옆에서 열이 되고 `271.2`는 한 자리 밀린 숫자가 된다.
>
> **목록(`.mk-px`)은 정수 그대로다.** 사이드바 250에서 `.mk-px` 한계가 38.62px인데

#### 판돈 기본값은 지갑의 1/10 (1.31.0)

**`100` 고정이었다.** 다른 게임의 최소 베팅이고, 1.24.0에서 크레딧 가치가 10배가 된 뒤에도
안 따라갔다. 잔액 410,862에서 **0.024%**다. 판돈이 아니라 Buy 버튼이 달린 반올림 오차다.

```
mk.typed  =  max(minBuy, sig2(room() / 10))      sig2 = 유효숫자 둘로 내림
잔액 41만 -> 41,000        잔액을 모르면 -> minBuy * 10 = 100
```

**1/10 이고 1/2 이 아니다.** 아직 고르지 않은 판돈이므로 **잃어도 게임이 끝나지 않는 액수**여야
하고, 반대쪽 답은 `25% / 50% / Max` 칩이 바로 옆에서 이미 하고 있다.
**한 번만 심고**(지갑을 알게 된 첫 순간) 그 뒤로는 화면이 타이핑을 덮지 않는다.
`TICKS_PER_CREDIT`를 쪼개는 안은 반려됐다. 소수점만 옮길 뿐 유효숫자 개수가 같아 목록 폭을
안 풀고, 보유가 `34,794.7`, 진입가가 `0.0299`가 되어 「장난감 숫자」로 읽힌다.

**새 색도 새 글자 크기도 없다.** 등락률 색은 이 패널이 이미 가진 `--mk-up` / `--mk-dn`
(`.mk-u` / `.mk-d`)이고, 양 테마 값이 `games/casino.js`의 `.gm-fig`와 같은 쌍이다.
선택된 칩은 ember가 아니라 `--card` 바탕이다. **ember는 포커스 링과 진입선(`.mk-mark`)에만 남는다.**

## 6. 연출: 밀리초

**순간이 셋이다. 하나씩 기준이 다르다.** 1~2는 처음부터 있었고 3은 2026-11-06에 생겼다.

```
1. 답이 한 번에 드러나는 순간        600~960ms      카드가 뒤집힌다, 판이 열린다
2. 한 라운드 안에 여러 번 누르는 동작  250ms 아래     칸 파기, 한 칸 긁기, 문 열기
3. 답이 좁혀지며 드러나는 재생        2,000ms 아래   바퀴가 느려진다, 릴이 하나씩 선다
```

> **3의 예시가 바뀌었다(2026-11-13).** 전에 적혀 있던 「구슬이 떨어진다, 숫자가 오른다,
> 공이 나온다」는 **전부 폐지된 화면**(플린코·크래시·키노)이라 다음 구현자가 가리킬 대상이 없었다.
> 지금 분류 3에 드는 둘이 그 자리를 받는다. 「릴이 선다」가 1번 예시에서 빠진 것도 같은 이유다.
> 릴 셋이 하나씩 서는 것은 한 번에 드러나는 것이 아니라 좁혀지는 것이다(아래 5-4·5-7).

**1의 "1초를 넘기면 느리다"는 지워지는 것이 아니라 무엇에 걸리는 규칙인지가 정해진 것이다.**
그 규칙은 **아는 데 걸리는 시간이 전부 공백인 경우**의 규칙이다. 카드가 뒤집히는 동안
플레이어는 아무것도 알아 가지 않으므로 그 시간은 짧을수록 좋다.

**3은 그 시간이 공백이 아니다.** 구슬이 한 줄을 내려갈 때마다 들어갈 수 있는 통이 줄어든다.
**그 좁혀짐이 그 게임의 내용이다.**
그래서 2026-11-06에 사용자가 **"핑코는 너무 빨리 끝나서 긴장감이 없다"**고 했다.
806ms는 1번 규칙을 정확히 지킨 값이고, **지킨 것이 틀린 것이었다.**

**3에는 두 가지가 같이 걸린다.**

| | | 왜 |
|---|---|---|
| 전체 상한 | **2,000ms** | 한 판이 끝나고 다시 누르기까지의 왕복. 넘기면 반복이 고역이 된다 |
| 한 단계 하한 | **70ms** | 60fps에서 4프레임. 그 아래는 단계가 뭉개져 한 줄기로 보인다 |

**하한 70ms는 「좁혀지는 단계」에만 걸린다. 움직임에는 안 걸린다.**
이 단서가 없으면 다음 구현자가 굴러가는 릴의 심볼 교체를 70ms 틱에 묶는다. **실제로 그랬다.**
슬롯은 70ms마다 창의 심볼 셋을 갈아 끼우고 있었고, 그건 단계가 아니라 **격자가 깜빡이는 것**이었다.
가르는 질문은 하나다.

```
좁혀지는 단계   그것이 지나가면 가능한 답이 줄어든다            하한 70ms
움직임          물건이 움직인 것이고 가능한 답은 그대로다        하한 없음. 뭉개지는 것이 목적이다
```

릴 하나가 서는 것은 단계다(남은 답이 줄어든다). 그 릴이 **한 칸 지나가는 것**은 움직임이다.
굴러가는 릴은 **초당 70심볼**이고 한 칸이 14ms인데, 그게 맞다. 빠른 드럼은 뭉개져야 드럼이다.
휠도 같다. 포인터 아래를 칸이 지나가는 것은 움직임이고, **멈춘 칸이 켜지는 것**이 단계다.

**지금 3에 드는 화면은 둘이다. 휠과 슬롯.**
이 절은 오래 「드는 화면이 없다」고 적어 두었고 **그 문장은 2026-11-13에 틀려졌다.**
그때까지 둘은 1번으로 판정돼 있었는데(휠 860 · 슬롯 940), 둘 다 **좁혀지는 것**이다.
바퀴는 느려지면서 들어갈 수 있는 칸이 줄고, 릴은 하나씩 서면서 남은 족보가 줄어든다.
1번 규칙(1초 미만)을 지킨 것이 그 좁혀짐을 지운 것이었고, 플린코에서 얻은 교훈과 같은 모양이다.
상한 2,000과 하한 70은 플린코에서 재서 얻은 것이라 그대로 쓴다. 다시 재지 않는다.

> **분류 3은 시간을 늘리는 허가가 아니라 좁혀지는 것에만 주는 시간이다.**
> 2026-11-06에 빠진 네 게임 중 둘은 전체 공개를 하면서도 3이 아니라 1로 판정했다.
> 답이 이미 나온 뒤의 「어디였나」는 설명이고, 설명은 좁혀지지 않는다.
> **좁혀지지 않는 것을 길게 하면 그냥 느린 것이 된다.**
> 내 연출이 3이라고 말하려면 **그 시간 동안 플레이어가 실제로 알아 가는 것**을 댈 수 있어야 한다.

`games/README.md` 5절대로 **한 패널의 숫자는 맨 위 `XX_T` 객체 하나에 모은다.**
CSS 애니메이션 길이와 같은 사실을 두 번 쓰는 곳에는 주석으로 짝을 적는다
(`games/wheel/meta.js`의 `.wh-face.turning` · `@keyframes whLabels` 와 `WH_T.stop` 이 그 예이고,
`test/webview/games/wheel.js` 가 두 사본이 같은 수인지 실제로 읽어서 대조한다).

**길이가 요소마다 다른 전환은 CSS에 두지 말고 패널이 인라인으로 준다.** 슬롯 릴 셋이 그렇다.
세 릴의 전환 길이가 각각 다르므로 CSS에 두면 클래스가 세 개 생기고 같은 수가 두 군데에 적힌다.
이징만 공유하는 상수(`SL_EASE`)로 패널에 두고, 사본은 하나다.

### 답이 언제 화면에 오는가는 ms보다 먼저 정할 것

**휠과 슬롯은 둘 다 답을 연출이 끝나기 전에 화면에 올려 두고 있었다.** 밀리초를 늘리는 것만으로는
안 고쳐지고, 늘리면 오히려 더 나빠진다. 답이 일찍 보이는 시간이 길어지기 때문이다.

```
호스트가 안 보내는 것    진행 중 라운드의 seed, 휠의 stop (계약. games/README.md 6절 2번)
화면이 안 그리는 것      받았지만 연출이 아직 도착하지 않은 답
```

**둘은 다른 규칙이다.** 전자는 호스트가 지키고 후자는 패널이 지킨다.
휠은 `stop`을 돌기 전엔 못 받지만, **받은 뒤에는 첫 프레임부터 그 칸을 솔리드 ember로 칠하고
있었다.** 슬롯은 릴마다 자기 `hit`을 들고 가서 릴 1이 420ms에 링을 켰다.
**둘 다 「호스트는 숨겼는데 화면이 보여 준」 경우다.**

**판정법.** 연출 중간 프레임을 하나 골라서, **그 프레임만 보고 답을 알 수 있나**를 묻는다.
알 수 있으면 그 연출은 시간을 쓰고 있을 뿐 아무것도 안 하고 있다.

### 상한을 넘기면 간격을 누른다. 꼬리를 자르지 않는다

**2026-11-06에 빠진 두 게임에서 얻은 규칙이고, 여러 칸을 한꺼번에 여는 연출 전부에 적용된다.**
간격 x 개수가 상한을 넘으면 **간격을 `상한 / 남은 개수`로 눌러** 마지막 하나가 상한에 떨어지게 한다.

**뒤를 잘라서 맞추면 안 된다.** 숨은 칸이 많을 때 꼬리를 자르면 못 연 칸이 남고,
**못 간 자리가 안 열리면 "거기였어"가 사라진다.** 그게 그 게임들의 감정이었고,
연출은 감정을 자르는 쪽으로 타협하지 않는다. **덜 보여 주는 것보다 빠르게 보여 주는 것이 낫다.**

> **지금 이 규칙을 타는 화면은 없다.** 마지막 후보였던 즉석복권(남은 칸당 55ms, 최대 8칸 =
> 440ms)도 폐지됐다. 빠진 게임들에 걸려 있던 **전체 공개 상한 420ms** 가 일반 규칙인지 그 화면
> 들에만 걸려 있던 값인지는 **이 문서가 한 번도 적지 않았다.** 다음에 여러 칸을 한꺼번에 여는
> 화면을 지을 때 정한다.

**지켜야 하는 세 가지.**
1. `CUC.reduceMotion()`이면 **위 표를 전부 건너뛰고 최종 상태를 한 번에 그린다.**
2. 기다리던 응답이 아닌 것(늦게 온 것, 브로드캐스트)은 **연출 없이 있는 그대로** 그린다.
   연출하면 같은 카드를 두 번 돌리게 된다.
3. 거절된 동작은 아무것도 바꾸지 않았으므로 **아무것도 움직이지 않는다.**

## 7. 목록 화면: 다섯을 어떻게 늘어놓나

이 화면이 답하는 질문은 하나다. **"지금 뭘 할까, 그리고 내가 없는 동안 뭐가 움직였나."**
즐겨찾기도 오른쪽 숫자도 전부 그 한 문장에서 나온다.

> **이 절은 열넷을 재서 썼고, 지금 목록은 다섯이다.** 그래서 두 가지가 섞여 있다.
> **재서 쓴 값(7-0)은 그대로 두고 산술만 다시 했다.** 다시 재지 않는다.
> **열넷이어서 성립했던 근거는 성립한다고 적어 두지 않았다.** 7-1의 근거 2가 그 경우이고,
> 거기에 그렇게 적혀 있다.
>
> **목록은 2026-11-13에 평평해졌다.** 이 절은 그때까지 「묶음 셋을 그대로 둔 것은 판단이다,
> 평평하게 펼지는 시각 설계 판단이라 여기서 혼자 정하지 않는다」로 적혀 있었다. **정해졌다.**
> 7-2가 그 결정과 근거이고, 머리 셋(67px)과 접힘은 코드에서도 걷혔다.

시안 두 장이 옆에 있다. `docs/games-list-options.png`(지금 · 안 1 · 안 2 · 거절한 4열, 라이트 포함)과
`docs/games-list-tiles-at-size.png`(타일을 24 · 40 · 48 로 나란히 깐 것).
**숫자가 아니라 이 두 장이 7-1의 근거다.** 두 장 다 열넷짜리 목록이다.

### 7-0. 재서 쓴 값. 다시 재지 마라

`.inner` 안쪽에 그릴 수 있는 폭 = **사이드바 - 78** (wrap 10x2 + card 15x2 + inner 14x2).

| 사이드바 | `.inner` 안 | 4열 gap4 | 4열 gap2 | 3열 gap4 | 2열 gap4 | 타일 48 auto-fill gap2 |
|---|---|---|---|---|---|---|
| 250 | 172 | 40.0 | 41.5 | 54.7 | 84.0 | **3열** (칸 56.0) |
| 280 | 202 | 47.5 | 49.0 | 64.7 | 99.0 | **4열** (칸 49.0) |
| 320 | 242 | 57.5 | 59.0 | 78.0 | 119.0 | 4열 (칸 59.0) |
| 400 | 322 | 77.5 | 79.0 | 104.7 | 159.0 | 6열 (칸 52.0) |

게임 이름 **열넷**의 실제 렌더 폭(VS Code 기본 글꼴, `font-weight:700`). 제일 긴 것은
`Scratch Card`였다. **이 표는 2026-11-13 폐지 전에 잰 것이고, 넷 다 폐지된 게임이다.**

| 크기 | 제일 긴 이름 | `Sword Forge` | `Shut the Box` | `Draw Poker` |
|---|---|---|---|---|
| 12.5px | **81.7** | 78.8 | 79.2 | 71.3 |
| 10.5px | 70.1 | 67.6 | 68.0 | 61.2 |
| 9.5px | 64.1 | 61.8 | 62.3 | 55.9 |

**그래도 지우지 않는다. 지금 레이아웃이 버티기로 한 상한이 그 81.7이다.**
남은 다섯(`Blackjack` · `High-Low` · `Slots` · `Wheel` · `Market`)은 **글자 수가 전부
`Scratch Card`보다 적다.** 따라서 81.7은 아무 행도 닿지 않는 **상한**이고, 상한 아래에서는
7-3의 폭 계산이 여유만 늘어난다. **다섯의 실제 렌더 폭은 안 쟀다.** 상한으로 충분한 자리에
새 측정값을 지어 넣지 않는다.

행 하나 = `24(타일) + 8x2 = 40px`. 묶음 머리 = 25px(첫 번째만 17px).
**사이드바 250, 다크, 즐겨찾기 없을 때의 전체 높이 실측(열넷 기준):**

| 모양 | 높이 | 이름 | `.gm-fig` |
|---|---|---|---|
| 열넷 (1열 행 + 묶음 넷) | **680** | 있음 | 있음 |
| 1열 행 + 즐겨찾기 블록 넷 (안 1) | **705** | 있음 | 있음 |
| 1열 행 + 즐겨찾기 타일 격자 (안 2) | **643** | 있음 | 있음 |
| 4열 그림만 | 308 | **없음** | **없음** |
| 2열 (24 타일 위, 이름 9.5px 아래) | 496 | 작아짐 | **없음** |

**다섯일 때의 높이는 위 680에서 산술로 내린다. 다시 재지 않는다.**

```
행 아홉이 빠진다          9 x 40 = 360
묶음 머리 하나가 빠진다   Dice 머리 25        (넷 -> 셋)
680 - 360 - 25 = 295px
묶음 머리 셋이 빠진다     17 + 25 + 25 = 67   (2026-11-13, 7-2)
295 - 67 = 228px
```

**목록이 228px이다.** 열넷에서 680이었고 사이드바를 거의 다 채웠으므로 7-3이 길이를 문제로
삼았는데, **295px도 228px도 길이가 문제인 높이가 아니다.** 즐겨찾기는 그래서 길이를
줄이는 장치가 아니고, **지금 그것이 하는 일은 「내가 쓰는 것이 맨 위에 있다」 하나다**
(7-3이 처음부터 그렇게 적어 둔 것이기도 하다).
**67px은 평평하게 편 근거가 아니다.** 근거는 7-2에 있고, px은 그 결과다.

### 7-1. 왜 전체 격자가 아닌가

사용자 요청은 4x4 격자였다. 그려 보고 재 본 결과 **목록 전체는 1열 행으로 간다.** 근거 셋이다.

**1. 48px 타일이 4열에 안 들어간다.** 사이드바 250에서 4열 칸은 40.0~41.5px다.
칸에 맞춰 타일을 줄이면 칠해진 PNG 4장이 깨진다. 원본이 96px이라 **정수 배율은 24(4.00배)와 48(2.00배)뿐**이고,
40은 2.40배, 47.5는 2.02배, 56은 1.71배다. `image-rendering:pixelated`에서 이 배율은
어떤 소스 픽셀은 2px, 어떤 것은 3px이 되어 **같은 카드의 테두리 굵기가 줄마다 달라진다.**
사이드바 280에서 4열 칸은 47.5px이라 48px 타일이 **0.5px 넘친다.** 타일 48이 4열에 들어가려면
사이드바가 276 이상이어야 하고, 250은 규격이 지키기로 한 하한이다.

**2. 그림만으로는 열넷이 안 갈린다. 이 근거는 다섯에서 성립하지 않는다.**
원래 근거는 이것이었다. 24px에서 `Blackjack`과 `Draw Poker`는 둘 다 "녹색 명판 위의 흰 카드와
칩"이고 구별이 안 되며, 열넷에는 같은 물건을 쓰는 가족이 둘(카드 넷 · 주사위 넷) 있었다.
**둘 중 하나는 통째로 폐지됐고 카드 가족은 둘로 줄었다.** 남은 다섯은 카드 둘(블랙잭 ·
하이로우), 기계 둘(슬롯 · 휠), 차트 하나(시장)이고, 물건이 겹치는 것은 카드 둘뿐이다.
**그러니 이 근거를 다섯에 그대로 들이대지 마라.** 결론은 바뀌지 않지만 그것은 근거 1과 3이
받치고 있어서이고, **이 근거 2는 지금 아무 무게도 지지 않는다.**

**3. 세로 칸에는 `.gm-fig` 자리가 없다.** 그림 위 · 이름 아래로 쌓는 칸은 오른쪽 자리를 못 만든다.
숫자를 타일에 구워 넣거나 버려야 하는데 둘 다 7-4를 깬다.
**오른쪽 자리는 가로 행에만 있다. 그래서 행이 남는다.**

> 격자가 허용되는 자리는 **즐겨찾기 블록 하나뿐**이다(7-3, 안 2).
> 거기서는 내가 고른 서넛이라 이름이 없어도 되고, 숫자는 타일 바닥의 캡션으로 붙는다.

### 7-2. 묶음은 없다. 목록은 평평하다 (2026-11-13)

머리 셋을 걷었다. 전에는 이랬다.

```
Card tables     Blackjack · High-Low        order 10 · 30
Machines        Slots · Wheel               order 50 · 70
What you keep   Market                      order 140
```

**근거는 67px이 아니다.** 7-3이 이미 「295px은 길이가 문제인 높이가 아니다」라고 적어 뒀으므로
짧아지는 것은 근거가 못 된다. 근거는 셋이다.

1. **다섯 행은 이름도 타일도 전부 다르다.** `Slots`가 기계라는 것을 `Machines` 머리가
   알려 주지 않는다. 열넷일 때는 같은 물건을 쓰는 가족이 둘 있어서 머리가 일을 했고,
   다섯에서는 겹치는 것이 카드 둘뿐이다(7-1의 근거 2가 같은 사정을 적고 있다).
2. **`What you keep`은 한 행짜리 묶음이다.** 한 행 위의 머리는 묶음이 아니라 **꼬리표**이고,
   그 꼬리표가 하는 일은 **화면에 쓰는 자기해설**이다. 시장 행만 숫자를 다는 이유를 설명하려는
   것이었는데, 설명이 있을 곳은 이 문서 7-4이고 **거기 이미 있다.**
3. **머리를 걷으면 7-4가 더 잘 작동한다.** 7-4의 요지는 「숫자가 한 행에만 있으면 그게 보인다」인데,
   머리 셋이 있으면 눈이 읽을 글자 덩어리가 **여덟**이다. 걷으면 **같은 모양 다섯 + 다른 것 하나**가
   되고, 그 하나가 시장 행의 숫자다.

**접기가 사라지는 것은 잃는 것이 아니다.** 다섯 행이 한 화면에 들어오므로 접는 조작은 할 일이
없고, **저장 상태 하나(`gamesFold`)가 같이 줄었다.** 접힘이 묶음 이름 문자열로 기억되던 것도
같이 없어졌다.

**안 하는 것 둘.**

- **시장 행 앞에 구분선을 긋지 않는다.** 머리를 얇은 선으로 다시 그리는 것일 뿐이고,
  눈을 숫자가 아니라 경계로 보낸다.
- **`Favourites` 머리를 만들지 않는다.** 머리를 걷는 판에 머리를 새로 세우는 것이다.
  즐겨찾기는 `order` 순으로 맨 위에 모이고, **켜진 별(상시 ember)이 표시다**(7-3).

**상자는 둘이고 머리는 0이다.** 별을 누른 행이 위 상자로 올라가야 하므로 상자는 둘 필요하고
(`gmFavRows` · `gmRows`), 비면 `hidden`이다.

```css
.gm-rows{margin-top:10px;}
.gm-rows[hidden]{display:none;}
.gm-rows.gm-top{margin-top:2px;}   /* 보이는 첫 상자. :first-of-type 이 말할 수 없는 것 */
```

> **`order` 의 빈 칸(20 · 40 · 60 · 80~130)은 폐지된 아홉의 자리고, 안 메운다.**
> 번호를 10~50으로 다시 매기면 보기에만 깔끔하고 얻는 것이 없다. 비워 두면 **빠진 자리에 게임을
> 되넣을 때 그 번호를 그대로 쓴다.** **이 규칙은 평평해진 것과 무관하게 그대로다.**
> 없어진 것은 그 옆에 있던 다른 규칙이다: 「묶음은 `order` 순서에서 끊기지 않아야 한다」는
> 머리가 두 번 찍히는 것을 막는 규칙이었고, 머리가 없으면 그 실수도 없다.
> `test/registry.test.js` 에서 그걸 잡던 시험도 같이 지웠다. **대신 「목록에 머리가 0개다」를
> 화면 쪽에서 단언한다**(`test/webview/games/blackjack.js`).

### 7-3. 즐겨찾기

**별을 누르면 그 게임이 목록 맨 위 상자로 올라간다. 아래 목록에서는 빠진다.**
같은 게임이 두 군데 있으면 둘이 다른 것인지 보는 사람이 판단해야 한다. 하나만 있는다.

> **그 상자에 머리는 없다(7-2).** 「올라가 있다」와 「켜진 별」이 같은 사실을 두 번 말하는 것이
> 되고, 머리를 걷은 목록에 남는 유일한 머리가 된다. **표시는 상시 ember로 켜진 별 하나다.**

#### 두 안. 하나를 고를 것

**안 1로 갔다.** 아래 표는 그 결정의 근거이고 그대로 둔다. 다만 **안 1의 머리는 2026-11-13에
걷혔다**(7-2): 상자는 있고 그 위의 `Favourites` 글자가 없다.

| | 안 1 (채택) | 안 2 |
|---|---|---|
| 맨 위 상자 | 행 넷. 아래 목록과 같은 모양 | 48px 타일 격자. 250에서 3열, 280에서 4열 |
| 이름 | 있음 | 없음 (`title=`로만) |
| 전체 높이(250, 즐겨찾기 4개) | 705 | 643 |
| `.gm-fig` | 행 오른쪽 그대로 | 타일 바닥 캡션 |
| 무엇을 얻나 | 블록 전체가 한 모양이라 배울 것이 없다 | 사용자가 말한 격자. 62px 짧다 |
| 무엇을 잃나 | 지금보다 25px 길어진다 | 즐겨찾기만 다른 모양이 된다. 250에서 3+1로 접힌다 |

**안 1을 권한다.** 안 2가 아끼는 62px은 한 화면에 들어가느냐를 바꾸지 못하고,
한 목록 안에 모양이 둘이 되는 값을 치를 만큼 크지 않다.
**둘 다 "목록이 길다"를 해결하지는 않는다.** 길이를 진짜로 줄이는 것은 이름을 버리는 것뿐이고(7-1),
즐겨찾기가 푸는 문제는 길이가 아니라 **내가 쓰는 것이 맨 위에 있다**는 것이다.

#### 켜고 끄기: 행 오른쪽의 별

**셰브론을 뺀다.** 열네 행에 똑같이 붙는 상수이고, 행 hover와 `cursor:pointer`가 이미 같은 말을 한다.
그 자리가 비어야 별이 들어간다. **폭이 그만큼밖에 없다**(아래 계산).

우클릭 메뉴는 쓰지 않는다. 웹뷰에서 VS Code 자체 메뉴를 막고 메뉴를 직접 그려야 하고,
그건 별 하나가 할 일에 비해 부품이 너무 크다. 길게 누르기도 아니다. **여기는 마우스 면이다.**

행이 버튼 하나에서 **감싸개 하나 + 버튼 둘**이 된다. 버튼 안에 버튼을 넣을 수 없다.

```html
<div class="gm-row" data-game="${g.id}">
  <button type="button" class="gm-open" data-game="${g.id}"${title}>
    <span class="gm-ic">…타일…</span>
    <span class="gm-txt"><span class="gm-nm">${g.name}</span>${sub}</span>
    <span class="gm-fig" id="fig-${g.id}"></span>
  </button>
  <button type="button" class="gm-fav" data-fav="${g.id}"
          aria-pressed="false" title="Favourite">${IC.star}</button>
</div>
```

```css
.gm-row{display:flex;align-items:center;border-radius:10px;padding-right:6px;}
.gm-row:hover{background:var(--track);}
.gm-open{flex:1 1 auto;min-width:0;display:flex;align-items:center;gap:6px;
  padding:8px 4px 8px 10px;border:0;border-radius:10px 0 0 10px;background:transparent;
  font-family:inherit;text-align:left;cursor:pointer;}
.gm-open:focus-visible{outline:2px solid #e8895a;outline-offset:-2px;}
/* .ws-fold 와 같은 치수: 20x20 상자 안에 14~16px 글리프. 사이드바는 마우스 면이라 44px 규칙을 안 탄다 */
```

위가 아래의 발췌로 읽힌다.

#### 어디에 저장하나: 호스트 `globalState`

**`CUC.state()`(= `vscode.getState()`)에 두지 않는다.** 그건 웹뷰 하나짜리 기억이라
창을 두 개 띄우면 창마다 다른 즐겨찾기가 뜬다. 즐겨찾기는 "내가 뭘 하는 사람인가"지
"이 창이 뭘 보고 있나"가 아니다. 탭·현재 게임이 `getState()`에 있는 것과 반대다.

`extension.js`에 이미 같은 성질의 것이 셋 있다(`agentNicknamesV1` · `agentRolesV1` · `agentAppearanceV1`).
**그 옆에 `gameFavoritesV1`을 붙인다.** 작업공간별인 `agentHiddenV1`(`workspaceState`)이 아니다.
게임은 프로젝트를 안 탄다.

```
webview  ->  { type:'favGame', id:'market', on:true }
host     ->  globalState.update('gameFavoritesV1', …)  ->  push()
```

`push()`가 모든 창을 다시 그리므로 두 창이 어긋나지 않는다. **웹뷰가 자기 DOM 을 먼저 고치고
호스트에 알리는 낙관적 갱신을 하지 않는다.** 호스트가 돌려준 것만 그린다. 5절 내내 지킨 규칙과 같다.

`.gm-row`가 `button`에서 `div`로 바뀌므로 지금 코드 두 곳이 조용히 깨진다.

### 7-5. `sub` 두 번째 줄과 최소 판돈

**남은 다섯은 전부 최소 10이라 `sub`를 다는 게임이 하나도 없다.** 최소 판돈이 다른 게임은

- `sub`는 **카지노 바닥값(10)과 다른 게임에만** 붙는다. 같으면 아무것도 안 쓴다
- **셋 이상이 `sub`를 달게 되면 그 줄이 틀린 것이다.** 그때는 목록에서 빼고
  최소 판돈은 패널의 베팅 조작에만 둔다. 세 줄부터는 정보가 아니라 벽지다
  (목록 길이가 아니라 **같은 줄의 반복**이 기준이다. 그래서 행 수와 무관하게 셋이다)
- 환수율(96~97%)은 **행에 쓰지 않는다.** 전부 같은 값이다. 필요하면 패널 제목의 `title=`에

## 8. 새 파일 둘을 어디에 꽂나

`games/tiles.js`와 `games/symbols.js`는 만들어 뒀다. 연결은 이렇게 한다.
**아래 네 군데 말고는 손댈 데가 없다.**

### 8-1. 타일 (목록 그림)

**`games/<id>/meta.js`.** PNG가 있는 두 게임(블랙잭 · 하이로우)은 `thumb`을 그대로 두고,
나머지는 `thumb` 대신 `tile`을 쓴다. 지금 `tile`을 쓰는 것은 셋(슬롯 · 휠 · 시장)이다.
PNG가 있던 나머지 둘(포커 · 대장간)은 폐지됐고 `game-poker.png` · `game-forge.png` 도 같이 지웠다.
```js
const tiles = require('../tiles');
module.exports = { …, tile: tiles.slots, /* thumb 없음 */ };
```

**`games/registry.js`의 `view()`.** 한 줄.
```js
icon: icon(g.icon) || '', thumb: g.thumb ? uri(g.thumb) : '', tile: g.tile || ''
```

**`html.js`의 `gameRow`.** `img`를 조건부로.
```js
<span class="gm-ic">${g.icon}${g.tile}${g.thumb ? `<img src="${g.thumb}" alt=""/>` : ''}</span>
```

**`games/casino.js`.** 두 줄. **순서가 중요하다.** `.gm-ic svg`(명시도 0,1,1)가
이미 `width:20px`을 걸고 있으므로 `.gm-ic .gm-tile`(0,2,0)로 덮어쓴다.
```css
.gm-ic .gm-tile{position:absolute;inset:0;width:24px;height:24px;display:block;}
.gm-row:hover .gm-ic img,.gm-row:hover .gm-ic .gm-tile{filter:brightness(1.1);}
```

**타일은 24px이다.** 이 절은 오래 48px로 적어 두었는데, 목록이 1열 행으로 가면서
행 높이가 `24 + 8x2 = 40px`로 정해졌다(7-0). 코드가 정본이고 지금 값은 24px이다.
48px 타일이 서는 자리는 7-3의 즐겨찾기 격자(안 2)뿐이다.

`icon`은 타일이 있는 게임도 **계속 가지고 있어야 한다.** `CUC.frame()`이 패널 머리의 글리프로 쓴다.

### 8-2. 심볼 (슬롯)

슬롯이 한 번에 칸 아홉을 그린다(릴 셋 x 행 셋). 마크업을 아홉 번 붙이지 않는다.
**숨은 스프라이트 한 벌 + `<use>`**로 간다.
(즉석복권이 같은 심볼로 3x3 을 깔아서 합 18이었다. 그쪽이 폐지돼도 배선은 그대로다.)

**`html.js`.** `<body>` 바로 다음에 한 줄.
```js
const symbols = require('./games/symbols');
… `<body>${symbols.sprite()}<div class="wrap">…`
```
```css
.sy-sprite{display:none;}   /* <symbol> 은 제자리에서 그려지지 않으므로 use 는 멀쩡히 된다 */
.sy-cell{display:flex;width:48px;height:48px;border-radius:6px;background:#15181c;}
.sy{width:100%;height:100%;display:block;}
```

**패널에서.** 심볼 문자열은 노드 쪽에 있고 패널은 웹뷰 쪽이라 `require`할 수 없다.
`<use>` 마크업은 문자열 조립이므로 패널에서 바로 쓴다.
```js
function cell(sym, word) {
  return '<span class="sy-cell" role="img" aria-label="' + CUC.esc(word) + '">'
    + '<svg class="sy" viewBox="0 0 24 24" aria-hidden="true"><use href="#sy-' + sym + '"/></svg></span>';
}
```

**그림은 `aria-hidden`이다. 심볼을 보여주는 쪽이 이름을 진다.**
픽셀 카드가 `CUC.cardWord`로 지키는 규칙과 같다. 심볼 이름 10개는 그대로 읽어 주면 된다.

### 8-3. 두 파일이 지키는 것

| | |
|---|---|
| 격자 | **24단위, 48픽셀로 그린다.** 단위당 2픽셀. 픽셀 카드(16x22@2px)·픽셀 동전(8x8@2px)과 같은 칸 |
| 다른 크기 | 24 / 48 / 72만. **44나 60은 모든 변이 반 픽셀에 앉는다** |
| 색 | 테마 변수를 안 쓴다 (4절). 양 테마에서 같은 그림 |
| `max-width` | **필요 없다.** 웹뷰 스타일시트가 100%로 가두는 건 `img`뿐이고 여기엔 `img`가 없다 |
| 모서리 | SVG가 둥근 모서리를 그리지 않는다. `.gm-ic`의 `overflow:hidden`이 자른다 |
| 열거 | `symbols.KEYS`로. `Object.keys(symbols)`는 **12개**다 (`KEYS`·`sprite`·`use` 포함) |

- [ ] 누를 수 있는 것이 **펠트 대비 3:1 이상**인가. 눌렀던 것·아직 아닌 것과 세 단으로 갈리나

**연출**
- [ ] 타이밍이 `XX_T` 하나에 모여 있나. CSS 길이와 짝이 주석에 적혀 있나
- [ ] 내 연출이 6절의 **셋 중 어느 분류**인지 말할 수 있나
- [ ] 분류 1(한 번에 드러남)이면 **1초 미만**인가
- [ ] 분류 2(여러 번 누름)이면 **250ms 미만**인가
- [ ] 분류 3(좁혀지며 드러남)이면 **2초 미만이고 한 단계가 70ms 이상**인가.
      그리고 **그 시간 동안 플레이어가 실제로 알아 가는 것이 있나** (없으면 분류 3이 아니다)
- [ ] 그 **「한 단계」가 무엇인지 말할 수 있나.** 지나가면 가능한 답이 줄어드는 것만 단계다.
      물건이 움직이는 것은 단계가 아니고 하한 70ms를 안 탄다 (6절).
      휠에서 한 단계는 **포인터 아래를 지나는 칸 하나**이고, 70ms를 각속도로 옮기면
      **343 deg/s 아래**다. 위에서 「370 아래면 라벨이 읽힌다」고 적은 선과 같은 선이다
- [ ] **연출 중간 프레임 하나만 보고 답을 알 수 있나.** 알 수 있으면 아직 아니다 (6절).
      호스트가 안 보내는 것과 **화면이 아직 안 그리는 것은 다른 규칙**이다
- [ ] `reduceMotion()`에서 한 번에 그리나
- [ ] 늦게 온 응답과 브로드캐스트를 연출 없이 그리나
